## Deterministic unit identity, matching, and serialization

All unitization, matching, ordering, and hashing are frozen before real labels. Human reviewers may assign only the finite coded values; they may not invent unit IDs, merge units, vote a route, or edit source text.

1. **Canonical source identity.** A raw observation is identified by length-prefixed UTF-8 serialization of `(subject_id,hadm_id,note_id,note_seq,charttime,storetime,field_ordinal,span_start,span_end,parser_version)`. `span_start` and `span_end` are half-open character offsets in normalized source text. Missing values use the literal sentinel ` `; integers are base-10 ASCII; timestamps use the parent's exact parsed representation and a fixed UTC-offset policy; no locale or floating-point formatting is allowed.
2. **Canonical text normalization.** For matching and hashing only, apply Unicode NFC, replace CRLF/CR by LF, and preserve all other code points and whitespace. Source text is never overwritten. The normalized-text hash and original source hash are both stored. No semantic stemming, synonym expansion, or unvalidated diagnosis extraction is allowed.
3. **Unit identity.** `unit_id = SHA256( protocol_hash || LP(canonical_source_identity) || LP(target_cluster) || LP(action_modality) || LP(due_interval) || LP(polarity) || LP(recipient) || LP(responsibility) || LP(replacement) || LP(conflict) )`, where `LP(x)` is an unambiguous decimal-byte-length prefix followed by UTF-8 bytes. Before a semantic field has been labeled, the corresponding component is serialized as `UNLABELED`; after labels, the derived assertion key is separately hashed and may not replace the source identity. Distinct source spans or distinct note IDs are distinct units even when their text is identical. A reciprocal restatement is deduplicated only when its locked source-link identity and all route-defining coded fields match; otherwise both units remain.
4. **Canonical field matching.** Compare the exact ordered tuple `(target_cluster, action_modality, due_interval, polarity, recipient, responsibility, replacement, conflict)`. Values are members of the locked finite domains or `ABSENT` or `UNKNOWN`; there are no free-text comparisons. Equality requires exact code equality. If either side is `UNKNOWN`, emit both `MATCH_POSSIBLE` and `NONMATCH_POSSIBLE` states when allowed by the inherited matcher; never choose a favorable match. `ABSENT` is equal only to `ABSENT`, not to `UNKNOWN`. A missing/nonresponsive panel field is `UNKNOWN`, while a structurally unavailable source is `ADVERSE_SOURCE_MISSING`.
5. **Deterministic order and manifest.** Sort units by `(subject_id,hadm_id,source_note_id,span_start,span_end,field_ordinal,unit_id)` and panel assertions by `(panel_id,unit_id,field_name)`. Sort finite-state cross-products in fixed lexical order. Every serialized packet, unit inventory, matching decision, route-table row, bridge record, and compatible-set member stores protocol hash, schema hashes, source snapshot, code version, and SHA-256. Duplicate IDs, noncanonical ordering, hash collision handling other than fail-closed, or any mismatch between the reference serializer and executable serializer invalidates selection.

This contract makes reproducibility checkable independently of whether H1/H2/H3 agree. Agreement remains measurement evidence only; correlated shared error remains admissible in the parent's `Omega_i`.

## Actionability bridge and target-linked documentation states

The bridge is evaluated only after the parent packet and unit inventory have been sealed, using the same route-concealed H1/H2/H3 observations and the parent's compatible-set machinery. No bridge field is allowed to alter `Y,V,H,Z`, the parent route, the atom, sampling, or weights.

For each structurally eligible inherited unit, code the canonical DS payload against the radiology assertion using the exact eight-field tuple above. The bridge's target-linked outcome is one of the mutually exclusive states below.

| state | deterministic meaning | endpoint treatment |
|---|---|---|
| `EXACT_TARGET_LINK` | Every applicable target, action/modality, due interval, polarity, recipient/responsibility, replacement, and conflict field is exactly preserved in DS, with no unresolved field and no contradictory plan | positive target-linked numerator; non-adverse |
| `PARTIAL_TARGET_LINK` | Target cluster and action/modality are preserved, but at least one applicable timing, recipient/responsibility, polarity, replacement, or conflict field is absent or not fully preserved | adverse-compatible; secondary descriptive category, never exact positive |
| `CONTRADICTORY_TARGET_LINK` | DS contains an explicit incompatible value for any applicable field, or an explicit superseding plan conflicts with the index unit | adverse-compatible and route-informative only under the inherited route table |
| `NOT_PRESENT_IN_DS` | DS text is available and readable but no target-linked payload is found under the locked parser/reader codebook | adverse-compatible; not evidence that care or communication failed |
| `UNREADABLE_OR_NONRESPONSE` | Panel cannot inspect/code the supplied artifact, or returns no response | adverse-compatible, missingness numerator |

| `NA_NO_UNIT` | Parent frame contains no inherited pulmonary recommendation unit | excluded from bridge denominator and separately reported NA |
| `NA_NO_ROUTE_TARGET` | Locked route table says `NOACTION` and no target-linked handoff is defined | excluded from bridge denominator and separately reported NA; parent route remains unchanged |

`NOT_PRESENT_IN_DS` is not `NA`: an available canonical artifact was searched and did not contain the target-linked payload. Conversely, `NA` is not a favorable success and cannot lower an adverse endpoint. If a panel labels a structurally missing case `NOT_PRESENT_IN_DS`, compatibility retains the structural adverse state and the discrepancy is a falsification of packet/state handling.

A bridge admission is `EXACT` only if every inherited unit with `B_i,u=1` is `EXACT_TARGET_LINK` and no attempted unit is `PARTIAL`, `CONTRADICTORY`, `UNREADABLE`, `NONRESPONSE`, or `ADVERSE_SOURCE_MISSING`. All-unit adverse precedence therefore applies to the bridge as it does to routing. An admission with no bridge-applicable unit is `NA`, not exact. This prevents a clean unit from hiding a conflicting unit and prevents an empty packet from appearing actionable.

The primary secondary estimands, all computed over the frozen finite population with the inherited design weights, are:

* `Q_exact(g,r)`: weighted ratio of admissions in parent atom-route cell `(g,r)` that are bridge-eligible and all-unit `EXACT_TARGET_LINK`, with the denominator explicitly restricted to `B_i=1` and not `NA`; report the structural eligibility and NA fractions alongside it.
* `Q_adverse(g,r)`: the jointly optimized weighted ratio of bridge-eligible admissions whose compatible state is `PARTIAL`, `CONTRADICTORY`, `NOT_PRESENT_IN_DS`, `UNREADABLE_OR_NONRESPONSE`, or `ADVERSE_SOURCE_MISSING`.
* `Q_target_falsification(g,r)`: weighted rate of target-linked failures in bridge-eligible admissions, with structural missingness and unresolved states adverse-compatible and with numerator/denominator optimized jointly over `Omega_i`; no favorable numerator may be paired with an incompatible denominator.

The parent's exact route/atom estimands remain primary. These secondary ratios do not redefine the parent denominator and are not presented as care completion, clinical correctness, or benefit.

## Pre-label target-linked controls

Controls are constructed from the already sampled challenge packets before labels, using a sealed transformation manifest and separate transformed-text storage. They do not change parent labels, routes, atoms, source rows, or estimands, and their processing is charged only to the inherited controls/packet-integrity ledger rows.

* A `TARGET_SCRAMBLE` control replaces the target-linked span with a provenance-matched non-target span while preserving section position, formatting, and all non-target text. The expected exact target link is `NOT_PRESENT_IN_DS` or `NONMATCH_POSSIBLE`, as fixed by the manifest; a claimed exact match is a specificity falsification.
* A `ROUTE_IRRELEVANT` control changes only a formatting/author-like nuisance token or unrelated sentence. The parent route, unit inventory, and bridge state must not change.
* A `ROUTE_DECISIVE` control changes exactly one locked field, such as replacement or due interval, while preserving all other fields. The expected route/bridge transition is the corresponding truth-table row and no other field may change.
* A `TARGET_PRESERVATION` positive control duplicates an exact target/action/timing payload in a provenance-matched DS location without changing unrelated text. It tests sensitivity of the coded bridge, not clinical truth.

Transformations are feasible only when source spans, offsets, and expected state are unambiguous under the pre-label parser. Otherwise code `CONTROL_INFEASIBLE` and retain it adversely; never hand-edit or delete an inconvenient control. H1/H2/H3 do not see control type or expected result. Any invariant control flip or decisive control violation is a falsification signal, not a rescue for real-case performance.
