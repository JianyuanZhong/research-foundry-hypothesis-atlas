# Episode 10 landmark branch — process signal and a post-360-minute deterioration boundary

Status: proposed substantive child of `[prior hypothesis]`. No cohort count, fitted coefficient, prediction, metric, or scientific result is claimed. The parent remains the scientific ancestry and its P12/S720/S6 mortality experiment is preserved unchanged.

## Scientific opening and the decision this branch can resolve

The parent asks whether laboratory-result and vital-recording process features transport across eICU hospitals beyond recorded state, using ICU-discharge mortality. Its fixed-bin trajectory augmentation addresses the strongest remaining state explanation: a latest value can miss a transient fall, recovery, or instability that also increases observation density. A separate ambiguity remains: even a process increment that survives the trajectory test may be a property of how the ICU stay ends. eICU gives `unitdischargeoffset` and `unitdischargestatus`, but not a reliable time of death, and it does not tell us whether a row is an order, specimen result, bedside measurement, device output, interface transmission, or clinician action.

The closest inspected evidence bounds, but does not answer, this question. Rajkomar et al. [K1] show that temporally rich EHR representations can predict mortality across centers, not that recording density represents physiology. Gao et al. [K2] (abstract-only) show that missingness/presence can be predictive in a dynamic competing-risk model and warn that shifting EHR patterns can damage transportability. Hadler et al. [K3] show that external discrimination can persist while local data patterns improve calibration, with missingness and harmonization limiting implementation. None supplies a validated eICU deterioration timestamp or separates observation from physiology in this database.

The falsifiable branch hypothesis is:

> Among adult first ICU stays present at the six-hour landmark, a [0,360] lab/vital process vector P predicts a subsequently recorded, persistent severe vital-sign excursion in (360,720] before ICU exit, with a non-negligible held-out-hospital increment after the fixed-bin value state T and a future-observability audit. If the increment is present only when a later measurement exists, disappears under the measurement-censoring sensitivity or trajectory-state null, or is concentrated among discharge-time strata, the process signal is not transport evidence for deterioration; it is documentation or ICU-exit selection. If the endpoint cannot pass a source/clinical validity gate, this branch deliberately narrows the claim to an operational observed-excursion boundary and defers any clinical deterioration interpretation.

This is a descriptive prognostic/transportability test. It is not a causal test of monitoring, treatment, clinician action, EOL decisions, or mortality.

### Why this is a substantive advance

The parent can establish whether P adds information for eventual ICU-discharge mortality after measured trajectories. This child changes the estimand to a temporally separated event while retaining the parent experiment as an unchanged secondary module. The new event is defined from vital measurements after the feature window, and ICU discharge is a censoring/competing exit rather than the event. Thus a positive result would be evidence that the process increment travels with a later observed physiologic boundary, not merely with the final discharge label. A negative or selection-sensitive result would prevent over-interpreting the parent mortality increment as a clinically actionable deterioration signal.

The advance is only valid if the observed-excursion endpoint passes its measurement and threshold audit. Without source validation or critical-care adjudication, the result remains “prediction of a recorded severe vital excursion,” not “prediction of clinical deterioration.”

### Candidate non-discharge-selected endpoint

Define `D_obs` as the first *confirmed recorded severe vital excursion* in (360,720] while the patient is still in the ICU:

- use only finite values from the fixed fields `temperature`, `sao2`, `heartrate`, `respiration`, `systemicmean`, and `noninvasivemean`;
- a channel is abnormal at a post-window offset if `sao2 <88`, `heartrate <40 or >140`, `respiration >35`, `systemicmean or noninvasivemean <55`, or `temperature <35 or >39.5`;
- require two abnormal values from the same channel at distinct offsets no more than 120 minutes apart, with the first abnormal offset in (360,720] and before recorded ICU exit. The first qualifying pair defines event time. No carry-forward, interpolation, or discharge field creates an event;
- retain a one-abnormal-reading version as an exploratory sensitivity, never as the primary clinical claim;
- values at offsets outside the follow-up interval are not used. The primary endpoint is a recorded physiologic excursion, not a diagnosis, treatment escalation, death, or discharge outcome.

Threshold units and channel semantics must be verified from the source dictionary and, before any clinical interpretation, reviewed by a critical-care expert. If the source audit finds unit ambiguity, implausible value encoding, fewer than two readings cannot be distinguished from a single reading, or the persistence rule is not clinically acceptable, `D_obs` is not a valid clinical endpoint. The solver must then report the audit and stop at a descriptive feasibility result; it must not substitute ICU discharge mortality or call the endpoint deterioration.

ICU exit before a qualifying excursion is a competing/censoring event, not a negative physiologic observation. Report separate cause-specific exit categories for `unitdischargestatus == "Alive"` and `"Expired"`, but never interpret an expired discharge as a death time. Patients still in the ICU at 720 without `D_obs` are administratively event-free for the six-hour horizon only when they have an eligible observation process; missing future measurements are separately audited, not silently treated as physiologic stability.

The primary D estimand is the six-hour cumulative incidence of `D_obs` before ICU exit or offset 720 in the S6 population, evaluated on held-out hospitals. A pooled discrete-time cause-specific hazard model over (360,480], (480,600], and (600,720] estimates the D event and ICU-exit competing risk. This remains conditional on being in the ICU at six hours; it is not a population mortality estimand.

## Predictors and process/state contrasts

Retain the parent X, T, and P definitions exactly. X is age, gender, ethnicity, admissionweight, up to 30 training-fold-selected lab analytes and up to 20 training-fold-selected vital channels; each channel is its latest valid [0,360] value with training-fold median imputation and no carry-forward. T concatenates X with medians in [0,120), [120,240), and [240,360] for the same selected channels, standardized/imputed fold-wise, with no missingness indicators or process fields. ## Nulls and rival explanations

1. The inherited X-state and trajectory-state nulls cyclically reassign complete P vectors within hospital and trajectory-state cells based on training-fold risk, age bin, admissionweight bin, gender, and ethnicity. No outcome or P value is used for assignment.
2. The inherited unrestricted within-hospital process permutation and +180-minute displacement remain secondary controls.
3. For the new boundary, fit an M/M2 observation model and compare unweighted D_obs to the pre-specified observation-weighted result. A process increment for M/M2 with no increment after weighting is documentation/availability evidence, not deterioration evidence.
4. Add a discharge-time sensitivity permutation: within hospital, T-risk cells, and coarse recorded exit-time bands (360–480, 480–720, >720), permute complete P vectors without changing D, T, or exit. This is explicitly a selection diagnostic, not a causal match. A collapse toward this null means P is linked to recorded ICU-exit timing.
5. Do not use `actualicumortality`, `unitdischargestatus`, `carePlanEOL`, or any post-window value as a predictor of D_obs. Use Apache and EOL only for audit and boundary-stratified reporting.

Expected patterns distinguish only descriptive rivals:

- D_obs process increment attenuates after T, is not present for M/M2 alone, survives observation weighting, and is stable across hospitals: supports that measured temporal state carries information about a later recorded severe excursion; it does not establish physiology beyond the operational threshold or a monitoring effect.
- P predicts M/M2 and unweighted D_obs but not the weighted result or the discharge-time null: supports recording/exit selection.
- D_obs persists after T and weighting but not in the trajectory-state null, with adequate source validation: residual patient-linked information is plausible, but unmeasured severity and measurement bias remain.
- D_obs persists in state/discharge nulls or is concentrated in one hospital: workflow/feed behavior is more plausible than a portable clinical signal.
- Parent mortality P persists while D_obs is absent or invalid: the process signal is inseparable from discharge/outcome timing in the available data, or the operational event is not a sufficiently sensitive proxy; do not claim transport-sensitive deterioration.

## Falsification, decision boundary, and interpretation

Support for the branch’s specific transport-sensitive observed-deterioration claim requires:

1. Source/threshold audit passes, at least five viable hospitals remain, and the D_obs event, M2 coverage, and per-hospital event support are adequate; otherwise the result is inconclusive/deferral.
2. The external D_obs process increment has a paired interval excluding the inherited 0.01 AUC negligible margin (and a coherent calibration or 10% net-benefit contrast) for both learners, with directionally coherent internal estimates.
3. The increment remains above the margin after T and after the pre-specified M2 observation-weighting sensitivity, is not explained by the trajectory-state or discharge-time null, and is not confined to one hospital.
4. The same conclusion is compatible with, but does not replace, the unchanged P12/S720/S6 mortality boundary results.

The branch is falsified as a claim of transport-sensitive deterioration if D_obs has adequate support but Q_P^T(external) is at or below the negligible margin, or if the apparent increment disappears with T/observation weighting or is reproduced by the discharge-time null. This does not refute a recording-process association with ICU-discharge mortality; it narrows the parent interpretation.

Supportive results mean only “early recording process is associated with a later recorded severe vital excursion under the defined eICU risk set.” Adverse results mean no clinically useful portable increment was demonstrated for this endpoint. Inconclusive results include intervals spanning the margin, fewer than five hospitals or fewer than 100 parent P12 events, low D/M2 coverage, poor positivity or effective sample size, unstable threshold/units, Apache-label discordance that prevents audit, missing discharge offsets, or source/join/leakage failures. An imprecise null is not refutation.

The actionable decision boundary is: do not recommend a monitoring, treatment, discharge, or EOL change from this study. Continue to a clinical validation/measurement study only if the D_obs endpoint passes adjudication and the external weighted process increment survives both state and discharge nulls. If the result is selection-sensitive, prioritize order/specimen/device/interface timestamps and a reliable death time. If the endpoint fails validation or is under-supported, abandon this temporal clinical interpretation and retain only the parent’s bounded descriptive mortality/recording-process result.

## Missing evidence and verifier boundary

eICU cannot establish whether a lab/vital row is an order, specimen, bedside measurement, device aggregation, or interface transmission; it lacks a reliable death timestamp, treatment assignment, staffing/workflow data, and adjudicated deterioration. `carePlanEOL` is a recorded field, not a goals-of-care adjudication; missing rows do not prove no decision. `actualicumortality` is an Apache audit field, not an independent gold standard for D_obs or the parent label. Threshold validation, unit interpretation, endpoint adjudication, and any clinical action require expert review and another study.

A verifier can check source hashes, exact table/column bindings, joins, offsets, no post-window predictors, endpoint interval logic, competing-exit coding, training-only preprocessing/weights, hospital folds, null assignments, saved predictions, metrics, bootstrap intervals, and that conclusions cite computed output rows. It cannot establish that D_obs is true deterioration, that a process feature is clinician behavior, or that a result changes care.

## Method alternatives and compute decision

The parent’s matched elastic-net versus capacity-matched histogram GBM comparison is retained at the same inputs, [0,360] feature window, hospital-held-out folds, nulls, uncertainty, and decision metrics. The discrete-time hazard formulation is needed because the new event occurs after 360 and ICU exit is a competing boundary; a static logistic model would either discard early exits or misclassify them as no deterioration.

A raw-event neural sequence model is deferred: the available tables do not encode order/specimen/device/interface semantics, and a complex model would not resolve whether D_obs is observed physiology or future recording. Revisit only if endpoint adjudication and a bounded diagnostic demonstrate clinically relevant ordering information lost by three fixed state bins, while preserving all parent contrasts and nulls. A hospital random-effects model is also deferred because the held-out-hospital estimand is the scientific test; it may be added later only as descriptive heterogeneity after a stable residual is established. CPU is selected for the future solver: selected-column gzip extraction, fixed-bin aggregation, pooled hazards, two tabular learners, nulls, and 2,000 cluster bootstrap; an A100 would not answer the endpoint-validity ambiguity. Planned solver envelope remains 16 CPUs, up to 262,144 MiB RAM, and 28,800 seconds; this is an estimate, not a measured full-study runtime. A bounded readiness job should first time post-window vital extraction, threshold auditing, one hazard fold, and the observation-weight calculation.
