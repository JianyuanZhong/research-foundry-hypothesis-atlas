## What is known and what remains untested

The strongest source-supported claim is that MIMIC-IV 3.1 contains timestamped ICU loop input records and separate hospital eMAR records, with exact eMAR-to-pharmacy/prescription keys. The eMAR contains `charttime`, `event_txt`, `medication`, and `pharmacy_id`; detail is keyed by `(subject_id, emar_id, emar_seq)); pharmacy and prescriptions can be joined by `(subject_id, hadm_id, pharmacy_id)). ICU inputevents contain `starttime`, `endtime`, `storetime`, loop item IDs and status, but no `emar_id` or `pharmacy_id`. The source therefore permits a reproducible documentation concordance audit, not a deterministic administration join.

The unresolved measurement claim is: among the frozen A12/B12 labels, how often does an accepted ICU loop onset have a temporally compatible, drug-identified, positive-dose eMAR administration record, and how often does B12 contain such a record? The unresolved clinical claim remains the parent claim about a recorded furosemide/bumetanide initiation strategy and bounded recorded airway outcomes; this audit cannot establish actual delivery, intent, perfusion response, renal safety, or benefit.

## Corrected eMAR event construction

1. Normalize text only for matching: lowercase, trim, replace non-alphanumeric runs by spaces, collapse whitespace, and use token boundaries. A loop identity token is exactly `furosemide` or `bumetanide`; do not infer a loop from “Lasix” alone unless the dictionary or a linked order explicitly supplies the generic identity.

2. Deduplicate eMAR only on the full event key `(subject_id, emar_id, emar_seq)`. Exact duplicate rows are retained once. If rows with the same key disagree in charttime, medication, event_txt, pharmacy_id, or storetime, mark the event duplicate-conflict and do not qualify it.

3. Join detail only on `(subject_id, emar_id, emar_seq)`. Do not sum parent and product rows. Treat rows with null `parent_field_ordinal` as parent/overall fields and non-null `parent_field_ordinal` as product/detail fields.

   - If one or more product rows exist, a positive product-level `dose_given` or `product_amount_given`, finite and with a nonmissing unit, can establish positive administered quantity; values from different product rows may be reported separately but are never combined with parent dose values.
   - If no product row has a positive given amount, a positive finite parent-level `dose_given` with a nonmissing unit can establish positive administered quantity.
   - `dose_due` alone never establishes administration.
   - If same-role detail rows have incompatible positive/zero values, incompatible units, or irreconcilable affirmative/negative completion fields, mark dose-detail-conflict. A parent dose-due value versus a product amount is not by itself a conflict; it is the expected parent/product structure.
   - Any affirmative `complete_dose_not_given` (`yes`, `true`, `1`, case-insensitive) disqualifies strict administration. Missing, unrecognized, or contradictory completion values are ambiguous. `Not Given`, `Held`, and every non-Administered event status are not negative exposure; they are status-specific unknown/ambiguous states.

4. The only strict administration status is exact `event_txt='Administered'`. Enumerate every source `event_txt` value. Do not silently equate `Applied`, `Confirmed`, `Started`, or any other status with administration.

5. Drug identity has three noninterchangeable fields:

   - eMAR-text identity: exact generic token in `emar.medication`, or, when that is absent/ambiguous, exact generic token in detail `product_description` or `product_description_other`.
   - linked-order identity: exact generic token in linked `pharmacy.medication` or any linked `prescriptions.drug`.
   - identity agreement: both sources positive for the same generic; identity disagreement: both present but different; identity-unresolved: neither or only a non-specific text.

   Exact joins to pharmacy/prescriptions are `(subject_id,hadm_id,pharmacy_id)), retaining admission agreement. A missing pharmacy/prescription link does not erase a specific eMAR-text identity, but it is reported as uncorroborated. A pharmacy or prescription match is order/dispensing documentation, not receipt.

6. Route is descriptive only. Report eMAR-detail, pharmacy, and prescription route and normalized route classes. ICU inputevents has no route field, so route equality is not a concordance condition and route disagreement cannot be resolved automatically. Dose-unit equality is also descriptive; no mg/mL/tablet conversion is invented.

7. Timing comes only from eMAR `charttime` and ICU inputevents `starttime`. eMAR detail has no time field. Require nonmissing parseable charttime/starttime and compare within the same `subject_id,hadm_id) and frozen `stay_id) for inputevents. The eMAR itself is admission-linked, not stay-linked; if an admission has overlapping or multiple ICU stays, only input rows from the frozen stay may match. The primary diagnostic tolerance is absolute difference <=2 hours, with 1-hour and 4-hour counts reported. `storetime` is a recording-lag diagnostic only and never substitutes for charttime.

## Falsification and interpretation

The medication audit is falsified as a valid computational gate if any exact source header, archive member, key, status list, parent/product rule, dose rule, timing boundary, or duplicate behavior cannot be reproduced; if the primary A concordance is <0.80; if B conflict is >0.05; if arm minima fail; or if the result changes materially under exact duplicate removal, 1-hour versus 4-hour timing, or eMAR-text versus linked-order identity strata. These are measurement-validity failures, not treatment harm.

- **Supportive recorded-strategy result:** all inherited validity and uncertainty requirements pass, the operational medication screen passes, the airway lower bound is >+0.05, no Holm-rejected adverse family occurs, renal/RRT/terminal/disposition margins pass, and no inherited material reversal occurs. This supports only a reproducible recorded-strategy association with an operationally concordant documentation audit, suitable for external validation or randomization.
- **Adverse-FWER result:** an adjusted adverse E_R family passes every validity axis, including the medication audit. This is an observational recorded-proxy concern, not toxicity, renal safety, causality, or a recommendation.
- **Margin-falsified result:** validity passes, no adjusted adverse family occurs, and airway upper bound <=+0.05. This rejects only the prespecified recorded five-point improvement.
- **Medication-ascertainment-inconclusive:** any audit minimum, reproducibility, availability-proxy, or threshold requirement fails, or source disagreement prevents a stable classification. Directional outcome estimates may be printed descriptively, but no treatment-direction claim follows.
- **Operationally passing but clinically unvalidated:** all computational checks pass but no eMAR availability log or bedside adjudication validates completeness or delivery. The result may support reproducible documentation concordance only; it cannot establish receipt, awareness, intent, safety, benefit, actionability, or recommendation.
- **Statistically inconclusive/primary-infeasible:** retain the parent meanings.

Necessary stronger conclusions require medication-safety/critical-care adjudication, a validated eMAR availability log, richer administration-system data, note review for intent and bedside events, external replication, and preferably randomization. Automation can check the source bindings, row transformations, strata, thresholds, estimates, intervals, and prose-to-output linkage; it cannot establish delivery, exchangeability, causal effect, perfusion, congestion, urine accuracy, extubation readiness, KDIGO safety, transportability, or clinical actionability.
