Repeated observations, a post-window median, physiology, airway-record corroboration, explicit observation/missingness states, and competing exits prevent a single copied setting or premature discharge from being interpreted as improvement.

A supportive result would mean only incremental information in this eICU structured-chart construct. It would not establish that a daily extubation evaluation, SBT, extubation, readiness, appropriate care, benefit, harm, or a treatment effect occurred. No result is claimed in this proposal.

## Evidence boundary and falsifiable hypothesis

The strongest evidence inherited from the parents is limited to exported documentation: the exact labels are sparse and hospital-dependent; earlier chart-setting mappings were dominated by peak pressure and did not establish a common phenotype; and independent durable liberation markers are not sufficiently observable for bedside validation. Those findings do not determine whether the labels predict a later patient-state trajectory.

The unresolved hypothesis is: among the locked eligible labelled person-landmarks, conditional on the pre-`D` state and opportunity to observe it, the `evaluation` label has a positive evaluation-minus-no-trial risk difference for a persistent safety-preserving non-peak support reduction, and adds held-out predictive information beyond an identical pre-`D` state-plus-opportunity model without the label. The hypothesis is falsified if the contrast is absent or reverses with adequate support, is already present in a pre-`D` placebo, is no better than a documentation-opportunity-only model, disappears after component/source ablation, lies within the valid label-permutation null, or reverses across held-out hospitals. If support or observability is inadequate, the correct result is inconclusive rather than adverse clinical evidence.

The estimand is descriptive conditional association/predictive information, not a causal effect. No exchangeability, positivity, consistency, or bedside semantic assumption is made.

## Deterministic source rebuild and lineage verification

All source files are read-only. The exact eICU 2.0 snapshot is `[source checksum]`, catalog [source checksum]. Every source is a gzip CSV with an ordinary-file archive member. The executable writes `source_manifest.json` containing absolute source paths, byte sizes, SHA-256 values, schema paths and hashes, headers, snapshot/catalog IDs, and a read-only check.

The lineage check is performed in the following fixed order.

1. Hash each required parent artifact before parsing it. Canonicalize neither the original artifact nor its byte stream for the hash; retain the original bytes and hash.
2. Validate headers, required columns, UTF-8/CSV parsing, null representation, and unique row identifiers. For parent rows, require the identity columns `sid`/`patientunitstayid`, `uniquepid`, `hospitalid`, `landmark`, `L`, `D`/`decision_offset`, and `label` as applicable.
3. Create a canonical identity tuple for each row: `(sid, uniquepid, hospitalid, landmark, L, D, label)`. Sort by typed values with explicit null ordering, serialize with UTF-8 length-prefixed fields, and hash each tuple. Verify one row per `(sid,landmark)`, one `D` per action row, exact label membership, `D ∈ [L,L+360]`, and `D == decision_offset`.
4. Reconstruct identity and exposure independently from `patient.csv.gz` and `carePlanGeneral.csv.gz` using chunked scans. The patient table is joined only by `patientunitstayid`; no repeated clinical source table is joined directly to a patient row. For each candidate stay and landmark, select the minimum target `cplitemoffset` in the closed interval. Ties at the same offset are sorted by numeric `cplgeneralid`; if different target values remain tied, apply the parent contradiction exclusion rather than selecting arbitrarily. The tie rule and all tied rows are written to `lineage_ties.csv`.
5. Apply the parent filter manifest in its declared order, writing a count and a cryptographic digest after every filter. Each intermediate digest is a sorted Merkle-style digest of canonical identity tuples, not merely a row count. Compare every stage count, digest, and final row tuple to the supplied frozen artifact. Any divergence is a hard stop before outcome-source reads.
6. Run a second implementation of the reconstruction using an independent sort/group-by path rather than sharing the first implementation's selection function. Compare final canonical row hashes, stage counts, and selected `D` values. A disagreement is `rebuild_implementation_mismatch`, not a reason to choose one output.
7. Freeze an `exposure_verified.csv` byte-identical copy only after all checks pass. The artifact records source row IDs used for each exposure and whether the raw selected row is unique.

This process distinguishes three states that must not be conflated: `verified` (byte-identical parent plus independent raw rebuild), `artifact_verified_rebuild_unavailable` (parent bytes valid but raw reconstruction inputs/manifest unavailable), and `lineage_unverified` (hash, schema, identity, or reconstruction mismatch). Only `verified` permits the primary outcome analysis. The current workspace has the eICU sources and schemas but does not contain the two named parent row artifacts, so this proposal intentionally reports no cohort or association estimate.

## Outcome-blind parser freeze

Before reading any arm-specific outcome summaries, scan all rows of `respiratoryCharting.csv.gz` and write the complete distinct `respchartvaluelabel` vocabulary with normalized form, frequency, and first-seen source row ID. Normalization is Unicode-safe trim, case-folding, collapse of internal whitespace, and removal of only a terminal colon; it does not rewrite clinical words. The parser specification is committed as a standalone JSON with version, date, normalization function, exact matched strings, field-specific numeric bounds, and unmatched labels.

The primary component families are frozen as exact normalized labels or explicitly frozen regular expressions that are tested against the complete vocabulary: FiO2, PEEP/PEEP-CPAP, pressure support, and set respiratory rate. Peak inspiratory pressure is enumerated and retained only for ablation. A family is not inferred from an arm-specific frequency, a post-hoc synonym, or a value distribution. If a claimed family maps ambiguously to multiple respiratory concepts, the parser fails closed for that family and the endpoint is marked unavailable rather than using outcome-guided relabeling.

Parse only finite numeric `respchartvalue` values after trimming the eICU representation. Values outside the predeclared family bounds, empty values, nonnumeric values, and ambiguous text are missing, with a reason code. No unit conversion is inferred beyond the eICU convention. For every component-window retain valid count, distinct-time count, first/last clinical offsets, median, minimum/maximum, median gap, invalid count, and missing reason. `respchartoffset`, not `respchartentryoffset`, is clinical time; entry-minus-clinical lag is an opportunity diagnostic only.

## Persistent respiratory-state endpoint

For each frozen person-landmark with decision time `D`, define:

* pre-trajectory window `P = (D-1440,D-720]`;
* baseline window `B = (D-720,D]`;
* post-label window `O = (D+360,D+1800]`; and
* prespecified 12-hour sensitivity `O12 = (D+360,D+1080]`.

The six-hour washout excludes the classification-time chart from the response. Require `patient.unitdischargeoffset > D+1800` for a complete primary window. Discharge or death before completion is retained as a competing exit; a stay ending in truncation or unavailable discharge timing is also separately coded and never silently recoded as a respiratory event.

A component-window is observed only if it has at least two valid observations at distinct clinical offsets separated by at least 30 minutes. The window summary is the median of all valid observations. The implementation tests the separation on sorted distinct offsets, not row count; duplicate rows at one time cannot satisfy it. The primary support domain is positive when at least one non-peak component decreases from B median to O median by a fixed threshold:

* FiO2: at least 0.05;
* PEEP or PEEP-CPAP: at least 2 cm H2O;
* pressure support: at least 2 cm H2O; or
* set respiratory rate: at least 2 breaths/min.

The primary safety domain requires `vitalPeriodic.sao2` and `vitalPeriodic.respiration` to each have the same two-observation/separation eligibility in B and O. Among available signals, safety passes when O median `sao2` is not more than 2 percentage points below B median and O median `respiration` is not more than 4 breaths/min above B median. A violation fails safety. If either required safety signal lacks a complete pair of windows, the primary endpoint is missing, not safe by default.

The primary persistent safety-preserving state is `improved` if support and safety pass and O contains respiratory-care corroboration. Corroboration is a nonmissing `airwaytype` or at least one nonmissing ventilator interval field in `respiratoryCare`; it is an observation requirement, not proof of bedside device delivery. A complete row failing support or safety is `observed_non_improvement`. Rows with sufficient B but inadequate O observations are `endpoint_missing`, unless the ICU exits before O completion, in which case they are `competing_exit` with exit subtype `discharge`, `death` if represented by `unitdischargestatus`, or `truncation/unknown`. A row with `unitdischargeoffset <= D+360` is additionally flagged `no_post_washout_opportunity`.

The primary risk contrast is the evaluation-minus-no-trial risk difference for `improved` among complete non-competing observations. It must always be accompanied by the four-state distribution over all 540 frozen rows, arm-specific observation opportunity, and competing-exit rates. A multinomial all-row sensitivity models `improved`, `observed_non_improvement`, `endpoint_missing`, and competing exit as distinct states; it is not allowed to turn missingness into a negative event. An inverse-observation-weighted binary sensitivity estimates complete-observation probability using only pre-D state/opportunity, hospital, and landmark, with weights fit within training folds and truncated at the predeclared 1st/99th percentiles. Failed positivity or extreme arm-specific competing exits makes the weighted result inconclusive.

Prespecified secondary endpoints are support-only (removes safety), safety-preserving FiO2/PEEP reduction, and strict airway-transition validation. The airway sensitivity uses only an outcome-blind literal rule frozen before arm counts: a time-ordered `respiratoryCare.airwaytype` transition to exact normalized `No Artificial Airway`, or an exact normalized treatment-string ETT-removal candidate followed by no invasive-airway respiratory-care record for 48 hours. It is not called extubation or liberation. If fewer than 10% of rows in both arms have the sensitivity observable, it is unavailable and no association is estimated.

## Pre-D predictors and documentation opportunity

The baseline state-plus-opportunity model contains only measurements in `(D-1440,D]`, with B medians/latest values, P-to-B changes, pre-D counts, unique clinical timestamps, median gaps, source presence, component minimum-observation flags, and entry-lag summaries. It includes hospital and landmark only as non-target-derived fold covariates/strata. No respiratory value, care-plan field, source count, or treatment string after D is allowed in baseline.

The opportunity-only model uses pre-D row counts, distinct timestamps, distinct respiratory labels/airway values, source presence, and entry-lag summaries, but no respiratory numeric values or care-plan semantics. The state-plus-label model adds only the binary exact label to the identical pre-D state/opportunity feature set. A separate post-D documentation negative control predicts source density, unique times, and entry lag; it is not an adjustment for the primary estimand. Any complete-window analysis is accompanied by all-row missingness and competing-exit tables, and by an inverse-observation-weighted sensitivity using only pre-D variables.

## Held-out analysis and uncertainty

The primary predictive comparison is leave-one-hospital-out: state-plus-label versus identical state-plus-opportunity. For every fold, imputation, scaling, regularization, and observation weights are fitted on training hospitals only. Held-out outcomes cannot determine a calibration intercept, label rate, target rate, parser, threshold, or feature selection. Report row-weighted micro and equal-hospital macro log loss and Brier score, calibration slope/intercept, AUROC only when both classes occur, and arm-specific predicted/observed risk differences. Report all fold support, endpoint state, missingness, and competing-exit counts.

The primary within-hospital risk contrast requires at least five hospitals with at least 10 complete non-competing endpoint rows in each arm and at least 50% of all complete endpoint-observed rows in those hospitals; no hospital may supply more than 40% of either arm. This is a support gate, not a significance threshold. Folds with only one arm contribute no within-fold arm contrast, though they may contribute appropriately defined overall prediction metrics. If no valid fold has both arms, no label-added transport claim is made.

Uncertainty uses a stay-cluster bootstrap with fixed seed `61061`, resampling complete `sid` clusters within hospital strata and retaining all landmarks in a sampled stay. Refit the complete preprocessing/model pipeline in each replicate; target 1,000 replicates and report any shortfall before inspecting results. The label permutation sensitivity permutes labels within hospital-by-landmark strata that contain both arms, preserving all source-derived rows, endpoint states, and arm counts. Run 1,000 valid permutations when at least 20 valid strata exist; otherwise report the exact count and mark this gate inconclusive. No row-level bootstrap is permitted.

## Falsification criteria

1. **Pre-D placebo:** apply the identical repeated-observation, median, support, safety, and corroboration rules to `P` versus `B`. A contrast comparable to the post-D contrast is adverse to a newly emerging post-label trajectory.
2. **Lead-time placebo:** move exposure time to `D-720` while retaining the outcome window defined relative to D. Similar held-out label gain indicates pre-existing trajectory or leakage.
3. **Component/source ablation:** remove each support component, each safety signal, and airway corroboration in turn. Dependence on peak pressure, one field, one source family, or one hospital is not supportive.
4. **Documentation-only negative control:** predict post-window row density, unique times, and entry lag. Label-associated opportunity without a corresponding value-based trajectory gain supports documentation propensity, not state information.
5. **Permutation:** the observed held-out increment must exceed the 97.5th percentile of valid within-stratum permutations. An invalid or tiny permutation set cannot support a positive conclusion.
6. **Persistence stress test:** repeat with 60-minute separation and first/last summaries. A large change from the 30-minute median result signals copied-value or chart-interface sensitivity.
7. **Competing-exit/missingness sensitivity:** compare complete-window, multinomial four-state, and pre-D-only weighted results. Strong arm-specific exits, nonpositive weight support, or materially discordant estimands is inconclusive, not a reason to select the favorable analysis.
8. **Boundary/leakage audit:** machine-check every open/closed interval, `D+360` washout, `unitdischargeoffset`, and source-field provenance; reject any post-D baseline feature or `respchartentryoffset` substitution.

## Machine-checkable gates and interpretation

Call the computational result **supportive** only if lineage is `verified`; the primary parser is frozen before arm summaries; at least five hospitals meet the complete endpoint support gate; the evaluation-minus-no-trial risk difference is positive with at least 4/5 estimable hospital directions positive; state-plus-label improves both micro and macro held-out log loss over state-plus-opportunity by at least 0.01 with a stay-cluster 95% interval excluding zero; the gain survives the pre-D and lead-time placebos, component/source ablations, and valid permutation; missingness/competing exits do not explain the value-based gain; and independent airway corroboration is available in at least 10% of rows in both arms. Passing remains only support for incremental information in this chart construct.

Call the computational result **adverse** only when verified endpoint support is adequate and at least one failure is reproduced in a bounded sensitivity: no label increment over the identical baseline, reversal across hospitals/held-out folds, placebo or permutation explanation, ablation dependence, or opportunity-only explanation. This does not prove absence of bedside evaluation or that labels are mere documentation conventions.

Call it **inconclusive** for any lineage stop; fewer than five supporting hospitals; no valid held-out arm contrast; sparse corroboration; insufficient repeated measurements; failed positivity; materially discordant competing-exit/missingness analyses; bounded-definition disagreement; intervals spanning meaningful gain and no gain; or inability to execute the parser, hash, tie, join, or boundary audits. No relaxed threshold, post-hoc label expansion, outcome-guided parser, pooled row bootstrap, or recreated denominator is permitted.
