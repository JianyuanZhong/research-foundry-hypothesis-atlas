This child neither creates a new route nor changes a primary outcome, baseline, atom, temporal boundary, sample, weight, or causal estimand.

The bridge is a route-blinded secondary diagnostic inside the already selected admissions and existing holistic challenge rows. It asks a clinically sharper but bounded question: **can an independent reader reproduce the same stored radiology recommendation units and, separately, can the canonical stored discharge text explicitly encode the target, action, timing, recipient/responsibility, replacement, and conflict information needed to describe a next text-defined action?** A positive answer is evidence about reproducibility and explicit text content only. It is not evidence that anybody viewed, signed, communicated, accepted, executed, scheduled, followed, or benefited from the recommendation.

The untested claim is therefore not “the route is safe” or “the text is actionable in practice.” It is that a documentation-reproducible, explicit text-actionability gap can be measured without making unavailable workflow facts, ambiguous note linkage, or reader nonresponse disappear. Supportive, adverse, and inconclusive results are defined below and cannot alter the inherited routing result.

## Deterministic source-unit identity and canonical serialization

The canonical source-unit reference is

```text
U = (subject_id, hadm_id, source_note_id, reciprocal_chain_id, unit_ordinal)
source_note_id = (subject_id, note_id)
```

`unit_ordinal` is zero-based and generated once by the locked extractor over the canonical reciprocal chain. A source-note row is never merged because text is identical. If the parser cannot generate one unique chain or ordinal, emit the unit with `U_BOUNDARY` and deterministic reason code rather than deleting it.

The canonical structural envelope for a unit is

```text
E(U) = (target_span_id, action_span_id, due_span_id,
        target_cluster, action_modality, due_interval, polarity,
        recipient, responsibility, replacement, conflict)
```

Each field is exactly one locked code, `ABSENT`, or `UNKNOWN`; this is an extraction state, not clinical truth. Span offsets are byte offsets into an NFC-normalized copy, while the original source text bytes are retained. The envelope and unit identity are generated before reviewers see routes, atoms, weights, outcomes, or other panel outputs.

All source-derived and panel-derived records use UTF-8, Unicode NFC, ASCII LF, sorted JSON object keys, declared array order, explicit JSON `null`, no NaN/infinity, and identifiers serialized as decimal strings without floating-point conversion. Timestamps are stored as UTC-naive ISO-8601 with exactly six fractional digits when non-null; deidentified within-subject intervals are retained and no cross-subject date arithmetic is performed. The canonical JSON line is serialized with a fixed JSON implementation and no whitespace. Records are sorted by the bytewise tuple

```text
(subject_id, hadm_id, source_note_id.subject_id, source_note_id.note_id,
 reciprocal_chain_id, unit_ordinal, target_cluster, action_modality,
 due_interval, polarity, recipient, responsibility, replacement, conflict,
 reader_id)
```

with null before non-null and UTF-8 byte order. The manifest records protocol hash, source and schema hashes, extractor/code version, input and output counts, canonicalization rules, every record SHA-256, and the final file SHA-256. `unit_manifest.jsonl`, `panel_match_manifest.jsonl`, `h3_repro_manifest.jsonl`, `bridge_eligibility.jsonl`, and `serialization_manifest.json` are ordinary derived outputs in the workspace, never source edits. Reordered CSV rows, filesystem order, locale, hash-map iteration, or repeated execution must not change bytes. Duplicate keys, missing null/unknown distinctions, invalid timestamps, count discrepancies, or hash mismatch fail closed.

## H1/H2 unit matching and fixed panel outputs

H1 and H2 receive the same source artifacts but independent pseudonyms, packet ordering, rosters, and codebooks. They do not see route, atom, stratum, inclusion probability, parent labels, or compatible-set summaries. Neither may create a new source unit. Each output is append-only JSONL and must contain `packet_id`, `unit_ref` (`U` or `NO_UNIT_CLAIM`), the full assertion tuple, `reader_state`, eight availability codes, packet hash, codebook hash, and output hash. Allowed `reader_state` values are `SUPPORT`, `CONTRADICT`, `INDETERMINATE`, `UNREADABLE`, and `NONRESPONSE`. Malformed JSON, duplicate `(packet_id,unit_ref)`, missing required key, or out-of-domain code is `NONRESPONSE` with its raw-record hash retained.

The pure matching algorithm is identical for H1 and H2 and is run on sealed records.

1. Validate exact admission key `(subject_id,hadm_id)` and exact `U` syntax. A different admission is `CROSS_ADMISSION_NONMATCH`; a malformed identity is `MALFORMED_MATCH`.
2. If the panel supplies a canonical `U`, compare only to that source unit. If it supplies `NO_UNIT_CLAIM`, compare to all source units in that packet and retain every candidate; one-to-many or zero-to-one uncertainty is `AMBIGUOUS_MATCH` or `SOURCE_UNIT_MISSING`, not a selected best match.
3. Compare in locked field order `target_cluster, action_modality, due_interval, polarity, recipient, responsibility`. Equal codes are `EXACT_MATCH`; `ABSENT` versus any non-`ABSENT` is `FIELD_NONMATCH`; distinct known codes are `FIELD_NONMATCH`; `UNKNOWN` against a code or `ABSENT` branches into both admissible `UNKNOWN_WILDCARD` states under the inherited compatible-set rule. `replacement` and `conflict` are compared separately and never erased.
4. A complete assertion tuple with the same canonical `U`, including replacement and conflict, is `DUPLICATE_RESTATEMENT` only when byte-identical. Equal wording with another source note, chain, or ordinal is `DISTINCT_UNIT`.
5. Emit the ordered set of `(match_state,candidate_U,field_trace,reason_code)` sorted by canonical `U`, then the fixed field order. No vote, fuzzy similarity, database row order, or favorable tie-break may collapse it. Allowed match states are `EXACT_MATCH`, `DUPLICATE_RESTATEMENT`, `DISTINCT_UNIT`, `FIELD_NONMATCH`, `AMBIGUOUS_MATCH`, `CROSS_ADMISSION_NONMATCH`, `UNKNOWN_WILDCARD`, `MALFORMED_MATCH`, and `SOURCE_UNIT_MISSING`.

`D_REPRO` is computed from the sealed atomic inventories, not parent route agreement. It is `1` only when H1 and H2 each have valid packets; their canonical source-unit inventories have identical ordered `U` keys and complete assertion envelopes; every non-unknown unit is matched one-to-one with identical non-unknown values in all required fields; no duplicate/restatement or unresolved boundary remains; and no required output is `NONRESPONSE`, `UNREADABLE`, or malformed. It is `0` for an observed nonmatching inventory. It is `UNKNOWN` for missing/corrupt/nonresponse, unresolved reciprocal boundary, or a remaining unknown that makes the identity undecidable. H3 is not silently folded into this label; H3 is a separate independent reproducibility gate reported jointly and included in the compatible set.

For the text-actionability lane, H2 separately assesses whether the canonical DS artifact explicitly contains every required field in every retained source unit without inference: target cluster, action/modality, due interval, polarity where applicable, recipient/responsibility where applicable, and replacement/conflict resolution. `A_TEXT_COMPLETE=1` is this explicit text property only. `A_TEXT_COMPLETE=0` is explicit absence, contradiction, unresolved required field, or adverse-compatible incomplete content; `A_TEXT_COMPLETE=UNKNOWN` is unreadable, nonresponse, unresolved unit mapping, or corrupted packet. `A_TEXT_GAP=1` only when `D_REPRO=1` and `A_TEXT_COMPLETE=0`; an unknown denominator is not converted to a gap or no-gap.

## Independent H3 reproduction

H3 is a separately rostered and independently implemented reproduction of source-unit inventory, assertion envelope, matching manifest, and canonical serialization. H3 receives raw permitted packet artifacts, the source manifest specification, and sealed codebook/version hashes, but not H1/H2 outputs, routes, atoms, strata, weights, challenge status, parent labels, or bridge summaries. H3 may emit `NO_UNIT_CLAIM`, but may not invent a unit identity.

The H3 output has one canonical row per `U`, full normalized assertion tuple, state, source references, `source_manifest_hash`, `packet_hash`, `extraction_version`, and output hash. Run it at least twice from independent process state, once with original physical row order and once with a deterministic reverse/pseudorandom permutation generated from a predeclared seed. The verifier also reruns fixed chunks in reverse concatenation order. After canonical sorting, all runs must be byte-identical in unit keys, assertion tuples, match states, counts, and SHA-256 manifests. Any difference is `H3_REPRODUCIBILITY_FAILURE`; do not choose the favorable run. It widens the compatible set, is adverse/inconclusive for the H3 gate, and cannot change the population, route, atom, sample, or workload. H3 agreement with H1/H2 is agreement, not a truth certificate.

Synthetic fixtures are sealed before labels and include: exact duplicate restatement versus distinct note/ordinal; every `UNKNOWN` wildcard field; `ABSENT` versus coded mismatch; unresolved reciprocal boundary; cross-admission claim; malformed JSON/duplicate key; identical explicit plan; missing recipient; contradictory replacement; route-invariant formatting perturbation; one decisive one-field perturbation; and a shared-wrong panel pair. The expected canonical bytes and state transitions are fixed in advance. A fixture failure is a control failure, not repaired by relabeling.

## Pre-label source availability and the eight facts

Each of the following eight facts receives one availability code, retained in every packet, panel output, compatible state, and summary:

* `VIEWED_BEFORE_DEPARTURE`
* `FINALIZED_SIGNED`
* `COMMUNICATED`
* `ORDER_OR_REFERRAL_EXECUTED`
* `RESPONSIBLE_TEAM_ACCEPTED`
* `SCHEDULED_OR_HANDOFF_CONFIRMED`
* `PATIENT_OR_CAREGIVER_CAPACITY_PREFERENCE`
* `POST-DISCHARGE_FOLLOWUP_OR_OUTCOME`

## Eligibility and complete actionability state machine

Eligibility is label-independent. For a source unit/admission, write every predicate and failure reason before opening H1/H2/H3 outputs. `BRIDGE_ELIGIBLE=1` requires: unique admission key; valid canonical source `U`; valid reciprocal pre-`D` boundary; non-null `R_store<D`; nonempty source text and structurally parseable envelope; exactly one selected canonical DS with nonempty text, non-null `note_id`, and non-null `DS_store`; exact `(subject_id,hadm_id)` join; and a complete eight-fact source-availability audit. Detail ambiguity is retained as a flag and does not delete an otherwise eligible pair. A failed predicate is counted as `NOT_ELIGIBLE` with all reasons.

Every record has exactly one `eligibility_code` and one `bridge_state`; neither is null. The state table and precedence are:

| precedence | eligibility/state | deterministic condition | interpretation |
|---:|---|---|---|
| 1 | `NOT_ELIGIBLE / NA_NOT_ELIGIBLE` | any structural predicate fails: absent/nonunique DS, invalid or unresolved source boundary, missing required clock, malformed envelope, wrong join, or incomplete source audit | structural NA; counted separately; never a success or clinical failure |
| 2 | `ELIGIBLE / NA_NO_TARGET` | eligible packet has an explicitly empty target-unit inventory under the locked parser | descriptive NA; not a missed action; not a favorable no-action |
| 3 | `ELIGIBLE / NA_NO_ACTION` | a retained target/unit is explicitly classified by the locked action vocabulary as `NOACTION` with no requested action field | descriptive NA; distinct from missing reader output |
| 4 | `ELIGIBLE / NA_ROUTE_DEFER` | inherited route is `DEFER` and the preregistered bridge target rule excludes the unit from the actionability construct | structural NA only; unresolved route fields are not complete |
| 5 | `ELIGIBLE / ACTIVE_EXACT` | all required target/action/due fields are explicit and one-to-one linked to DS, with no contradiction, replacement, unresolved conflict, or required-clock failure; all required reader outputs valid | favorable text-defined state only |
| 6 | `ELIGIBLE / ACTIVE_PARTIAL` | target is linked but at least one required action/due/recipient/responsibility field is absent or unknown, without an explicit contradiction | adverse-compatible partial text state |
| 7 | `ELIGIBLE / SUPERSEDED_EXPLICIT` | DS explicitly supplies a replacement or superseding plan | adverse for the original unit; retain replacement |
| 8 | `ELIGIBLE / TARGET_CONTRADICTED` | DS explicitly negates or conflicts with a required target/action/polarity field | adverse text mismatch |
| 9 | `ELIGIBLE / TIMING_UNRESOLVED` | required timing/chronology cannot be resolved, is malformed, stale, post-`D`, or is otherwise outside the locked clock rule | adverse-compatible; no favorable timing imputation |
| 10 | `ELIGIBLE / DS_UNREADABLE` | DS exists but decoding, packet integrity, or reader access prevents a valid assessment | adverse-compatible missingness |
| 11 | `ELIGIBLE / NONRESPONSE` | required H1/H2/H3/bridge output is absent, malformed, duplicated, or out of domain | adverse-compatible; not complete-case deletion |
| 12 | `ELIGIBLE / DETAIL_AMBIGUOUS` | retained detail rows have unresolved duplicate/conflicting interpretation affecting a required field | adverse-compatible ambiguity |
| 13 | `ELIGIBLE / BRIDGE_INCONCLUSIVE` | eligible pair exists but deterministic matching, H3, controls, or compatible states cannot distinguish the preceding possibilities | inconclusive, never favorable |

The first applicable state is selected, while a complete raw condition vector is retained. `NA` can arise only from the structural or explicitly declared no-target/no-action/DEFER rules. Missing text, unknown fields, reader disagreement, corruption, contradiction, timing uncertainty, or H3 failure can never be relabeled as NA. Conversely, `NOT_PRESENT_IN_AVAILABLE_SOURCES` is carried as an evidence-availability limitation and cannot create `NA_NO_ACTION` or a patient-level workflow failure.

For no-unit `NOACTION`, `D_REPRO=1` only if both independent inventories are valid and independently empty; `A_TEXT_COMPLETE=NA`, never a favorable match. For `NA_NO_TARGET`, actionability is `NA`; do not treat zero target units as a zero success rate. For inherited `DEFER`, unresolved fields remain `D_UNKNOWN` and/or `A_TEXT_UNKNOWN` and the route is not rescued by a complete-looking text. For an eligible unit, `NONRESPONSE` and all adverse states stay in the denominator under the inherited compatible-set rule. If a denominator is zero, the estimand is `UNDEFINED/NA`, never zero.

## H3, compatibility, and fail-closed analysis

For each admission, retain the Cartesian product of admissible H1/H2/H3 atomic states, raw match states, all eight availability codes, reader failures, structural flags, and shared-error flags. `UNKNOWN_WILDCARD`, `AMBIGUOUS_MATCH`, `U_BOUNDARY`, `NONRESPONSE`, and H3 failure remain explicit compatible states wherever the inherited rules permit. `NOT_PRESENT_IN_AVAILABLE_SOURCES` is preserved as a category and cannot be relabeled as observed.

The inherited route is evaluated separately for each compatible atomic tuple with the frozen precedence and all-unit adverse rule. The bridge does not change `route(U)`, `Omega_i`, atom, sample, inclusion probability, denominator, or primary estimand. If any admission has no admissible compatible state, emit `OMEGA_EMPTY` and `NO_SELECTION`; never replace it with a consensus or favorable state.

For bridge quantities, optimize joint numerator/denominator contributions over the Cartesian product of admission compatible sets using exact rational arithmetic or an equivalently deterministic interval implementation. In particular, calculate the joint compatible bounds for `(D_REPRO, A_TEXT_COMPLETE, A_TEXT_GAP, workflow-gap vector)` and the inherited route together; never combine separately optimized marginal extrema. Unanimous panel agreement does not remove a shared-wrong compatible state. A compatible-set endpoint is `INCONCLUSIVE` if its denominator is zero, interval is wide under the inherited gate, any required field is unresolved, or a seal/control/workload gate fails.

Report, by frozen atom and inherited route, the weighted joint matrix of `(D_REPRO, A_TEXT_COMPLETE, A_TEXT_GAP, eight availability codes, bridge_state)`, challenge-only conditioning for challenge labels, and the documentation-to-text-actionability gap

```text
G_text = P_w(A_TEXT_GAP=1 | D_REPRO=1, atom, inherited route)
```

with numerator and denominator retained jointly in every compatible state. Also report the weighted frequency and exact reason vector for each `NOT_PRESENT_IN_AVAILABLE_SOURCES` fact, separately from patient-level `UNKNOWN` records. No complete-case, favorable-consensus, unweighted, model-imputed, or pooled atom result is permitted. The primary route estimands remain exactly those of the inherited experiment and cannot be rescued by a favorable bridge result.

The compiler copies the parent ledger version and its exact unit convention rather than silently converting or inventing a new cap. It reports planned worst-case parent charge, planned worst-case bridge charge within existing rows, actual parent charge, actual bridge charge, overlap, unioned distinct admissions/challenges, unspent reserve, and any overflow. If any planned or actual charge exceeds the sealed cap, fail closed as `LEDGER_OVERFLOW`/`INCONCLUSIVE`; do not downsample, truncate, extend a row, or remove difficult records. A computational H3 rerun cannot be used to claim an unbudgeted human review pass.

## Audit sequence and falsification controls

1. Verify every source path, hash, archive member, schema artifact, column list, identity key, temporal field, and read-only status.
2. Freeze the complete population, chronology, reciprocal-boundary audit, canonical DS, source units, atom, strata, sample, inclusion probabilities, challenge roster, packet hashes, source-availability audit, codebooks, serializer, and ledger before opening labels.
3. Run H3 and independent reference serialization on synthetic fixtures and reordered inputs; require byte-identical manifests and expected state transitions.
4. Label H1/H2/H3 route-blinded packets, append-only seal outputs, and only then compute bridge states and inherited routes by code. No reviewer may view route, atom, weight, bridge summary, or compatible-set bounds before sealing.
5. Recompute with an independent interpreter and verify exact joins, chronology, unit matching, source-level availability, state precedence, joint ratio bounds, sample/weight invariance, ledger sums, and output hashes.

Falsification occurs if any reviewer receives route/atom/weight information early; if source rows or unavailable facts are silently imputed; if row order, locale, or input permutation changes canonical bytes; if H3 repeated runs differ; if a route-invariant formatting perturbation changes unit identity, eligibility, or actionability; if a decisive one-field fixture fails the prescribed state transition; if H1/H2 matching uses fuzzy or vote-based correspondence; if `NOT_PRESENT_IN_AVAILABLE_SOURCES` becomes a patient-level negative or observed fact; if NA masks an eligible adverse unit; if compatible-set numerator and denominator extrema are combined incompatibly; if `OMEGA_EMPTY` is replaced by consensus; if a bridge result changes the inherited route/sample/atom/weight; or if workload ceilings are exceeded or difficult cases are dropped.

## Interpretation and required next study

Supportive results require deterministic serializer/matcher certificates, independent H3 reproduction, valid seals and controls, nonempty compatible sets, finite weighted support, a bounded `G_text`, and passage of the inherited route and workload gates. They support only the claim that a stored radiology-to-DS documentation/text functional is reproducible enough to specify a separately governed prospective silent validation and identify the exact workflow fields that must be collected. They do not support clinical actionability in practice, appropriateness, safety, communication, completion, benefit, or transport.

Adverse results include a supported documentation-to-text gap, explicit replacement/contradiction/timing burden, unresolved unit matching, adverse-compatible `AUTO` routing, H3 or serializer failure, route-invariance failure, source audit failure, or missingness/ledger/control failure. A high workflow-gap value caused solely by `NOT_PRESENT_IN_AVAILABLE_SOURCES` is reported as an evidence limitation, not as a clinical failure; it cannot change the inherited route. An affected atom or bridge claim is not nominated for silent validation unless its missing prospective field is added.

Inconclusive results include zero eligible units, zero denominator, sparse atom, unresolved reciprocal boundary, packet corruption, nonresponse, H3 non-reproduction, broken seal, wide compatible-set interval, `OMEGA_EMPTY`, or a source-level availability audit that cannot distinguish `NOT_PRESENT_IN_AVAILABLE_SOURCES` from record-level `UNKNOWN`. Inconclusive is not evidence of safety, non-actionability, or clinical failure.

The required next study is a prospectively governed, silent, within-site validation preserving the frozen atom and routing definition while recording actual event provenance and timestamps for viewing/availability, finalization/signature, communication, responsibility acceptance, order/referral execution, scheduling/handoff, patient/caregiver capacity or preference, outside-plan visibility, and follow-up/outcome. Expert adjudication is required for radiologic truth, appropriateness, and safety; a later outcome study is required for harm, utility, benefit, or causal effects. No retrospective MIMIC bridge conclusion may claim successful care delivery, clinical safety, causal benefit, or external validity.
