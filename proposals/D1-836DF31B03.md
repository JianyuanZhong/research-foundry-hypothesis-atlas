# Prospective-silent packet readiness as a source-computable endpoint

## Successor scope and substantive repair

This is an independent targeted successor of assessed-valid `[prior hypothesis]` and `[prior hypothesis]`. It retains the Lead's frozen pulmonary discharge-handoff question and repairs one remaining bridge gap: the prior placement layer can show that a human reader judged an exact atom to be present in a discharge summary, but it does not define a completely source-only, pre-label test of whether the same atom can be serialized into the bounded packet that a prospective silent system would log. This child adds that endpoint without treating serialization as delivery, viewing, assignment, action, appropriateness, safety, benefit, or causality.

The new endpoint is `R` (prospective-silent packet readiness). It is a deterministic property of the frozen source text, source provenance, canonical discharge-summary artifact, and pre-registered atom/dictionary; it is computed before any phase-1 or phase-2 label and before exposing any reader packet. It is reported in addition to, and never substitutes for, the inherited exact atom/route, H-layer, holistic challenge, paired target/control handoff contrast, support atlas, and all adverse precedence. The inherited estimand, population, chronology, route table, sampling, inclusion probabilities, maximum 900-admission master, phase-2 allocation, packet workload, and silent-validation-only conclusion ceiling are unchanged.

The unresolved, falsifiable question is:

> For the already selected exact atom-route and its frozen paired-control domain, can each eligible source-linked opportunity be deterministically converted into a provenance-complete, atom-preserving, action-and-due-interval shadow packet using only MIMIC fields available before a prospective silent observation, and is this readiness at least 10 percentage points more frequent for the target than for the matched non-target control?

This tests instrumentability of a retrospective text construct. It does not test whether a report was sent, seen, assigned, ordered, scheduled, completed, clinically appropriate, safe, or beneficial.

## Evidence boundary

The available evidence supports only that MIMIC contains admission, service, ICU-proxy, radiology-note/detail, discharge-note/detail rows from which the inherited stored-text frame and a deterministic packet-construction audit can be attempted. It does not support a claim that a stored note was visible at physical departure, that a service was accountable, that a plan was delivered or acted upon, or that any recommendation was clinically correct. Subject-specific shifted timestamps permit only within-subject/admission ordering; they cannot establish a prospective calendar date or cross-subject time relation.

A positive `R` is therefore “the source extract contains enough unambiguous material for the registered silent packet serializer,” not “the workflow received the packet.” A failed `R` is an adverse result for this narrow instrumentability construct when support is adequate; missing or ambiguous source material is retained as `R_U` and is adverse-compatible for the readiness lower bound, not silently deleted.

## Inherited frame and chronology (immutable)

Construct exactly the parent frame: first eligible adult admission per subject ordered by `(admittime,hadm_id)`, one admission per subject, an opportunity in `[admittime-12 hours,D)`, reciprocal report/addendum chain within the same subject/admission, exactly one canonical pre-discharge DS, and every inherited exclusion. Retain the exact inherited target atom `g*=(E*,M*,W*)`, terminal `curr_service`, workflow class, all-unit target routing and `AUTO/RECON/TIMING/DEFER` precedence. The target is selected once in the inherited fixed order, or `NO_SELECTION`; do not search for another target after reading any label or readiness outcome.

Use strict timezone-naive parsing. Require non-null `admittime`, `D`, radiology `charttime`, and `storetime`; require radiology `charttime<D` and `storetime<D`; retain `D`, charttime, storetime and original strings. No readiness field may use post-`D` text, `deathtime`, `dod`, `hospital_expire_flag`, discharge location, transfer completion, ICU stay completion, services as responsibility, or any cross-subject date arithmetic. These fields remain inherited eligibility/proxy/diagnostic fields only.

## Pre-label, deterministic readiness serializer

### Frozen serializer inputs

Before `FRAME_SUPPORT_SEALED`, freeze and hash a finite `bridge_serializer_dictionary`. It contains the inherited atom dictionary IDs and exact cluster/modality/due-interval lexicons; affirmative action verbs `{obtain,schedule,arrange,follow up,repeat,return,see,contact}`; exact heading patterns for `follow-up`, `discharge instructions`, `recommendations`, `plan`, and `pending studies`; negation, uncertainty, historical, hypothetical, optional/conditional, screening, surveillance, staging, and no-follow-up exclusions; Unicode NFKC/lowercase/whitespace/punctuation rules; section-level and field-level boundary rules; maximum packet schema and serializer version. It is authored without labels, reader outputs, DS outcomes, or observed times. No embedding, language model, spelling correction, synonym invention, clinical inference, or post-label edit is permitted.

Use longest exact phrase match, dictionary row order for ties, and preserve original character offsets. Canonical equality is dictionary-ID equality: clinically similar modalities are unequal, and `3 months` is unequal to `12 weeks`; no interval conversion or inferred calendar date is allowed. If a source span has incompatible atom parses, it is unresolved rather than arbitrarily resolved.

### Unit and DS extraction

For each already frozen target unit and each already frozen first non-target control unit, use only the reciprocal pre-`D` radiology source span and the canonical DS. Reconstruct detail text in ascending `field_ordinal`; never concatenate fields with an undeclared separator. A detail row with null `field_value`, duplicate `(subject_id,note_id,field_ordinal)` values, a missing referenced note, or an unresolved field order is a provenance failure. Preserve every contributing `(subject_id,hadm_id,note_id,field_name,field_ordinal,charttime,storetime,D)` and source character offset.

A deterministic parser must identify, in the source unit, one exact positive atom `(E,M,W)` equal to the frozen packet atom, an affirmative recommendation scope, and an unambiguous source span. The same atom must be locatable in the canonical DS text or ordered detail fields. A match cannot cross a heading boundary, an unresolved field boundary, or an unrelated instruction. An explicit negation, uncertainty, history, hypothetical, conditional/optional language, screening/surveillance/staging context, or no-follow-up scope over any atom component makes readiness unresolved or negative according to the rule below, never positive.

A forwardable scope exists only when a frozen heading pattern is found at a declared heading level and its end is the next heading at that level or end of the same note/detail field. Unmatched headings yield `section_unknown`; an unsectioned narrative is not forwardable. The exact match must contain all three atom components, an explicit action verb from the frozen list, and due interval/date in the same affirmative instruction span or in two adjacent fields linked by the fixed field-ordinal adjacency rule. Generic `follow up`, generic `imaging`, a related modality, a different interval, an action verb elsewhere in the DS, or a plan inferred from the radiology report is insufficient.

### Machine-checkable packet schema

The serializer emits a fixed JSON object with no free clinical interpretation:

`schema_version, atom_E_id, atom_M_id, atom_W_id, polarity, action_id, source_report=(subject_id,hadm_id,note_id,field_ordinal,charttime,storetime,D,source_span_start,source_span_end), ds=(subject_id,hadm_id,note_id,field_name,field_ordinal,charttime,storetime,D,ds_span_start,ds_span_end), forwardable_section_id, source_hash, ds_hash, dictionary_hash, reason_codes`.

`R=1` only if every required key is non-null and type-valid; the source and DS keys point to the same admission; all required atom components and positive polarity are exactly represented; the source report is reciprocal and pre-`D`; the DS is the canonical pre-`D` artifact; the action-and-due-interval span is affirmative and within a known forwardable section; the packet serializes deterministically twice to byte-identical canonical JSON (UTF-8, sorted keys, fixed separators, no NaN); and no forbidden source or post-label field entered construction. `R=0` means all required source objects are readable and linked but at least one registered positive condition is absent (for example an exact atom is outside a forwardable section or lacks an explicit action verb). `R_U` means unresolved provenance, null/truncated text, duplicate identity, unknown section level, incompatible parse, ambiguous boundary, missing DS/detail linkage, parser exception, or any required field that cannot be adjudicated by the deterministic rules. `R_U` is never coerced to `R=0` for the primary uncertainty report, but is counted as non-ready in the adverse-compatible lower readiness bound.

This endpoint is source-only and is sealed at `FRAME_SUPPORT_SEALED`/`TARGET_SEALED`, before phase-1 labels. It does not require a reader, a new packet, a new panel, or a new admission. The inherited H and holistic readers may later inspect their unchanged packets, but their judgments cannot alter `R`, its provenance, its denominator, or its reason codes. Serializer fixtures use synthetic text only and include exact action/interval matches, section-boundary crossings, conditional language, duplicate detail ordinals, missing DS links, and byte-serialization perturbations.

## Endpoint, support, positivity, and fixed estimand

The primary readiness domain is the inherited paired support domain `S_TC`: full-frame admissions with at least one target unit in `g*` and the deterministic first control `c_i`, defined before labels. Report `R_Ti` and `R_Ci` for target and control on exactly this same admission domain, plus `R_U` counts and reason-code frequencies. The readiness contrast is

`Delta_R = |S_TC|^{-1} sum_i (R_Ti - R_Ci)`.

Use the inherited sequential inclusion probability `p_i=pi1_i*q_i`, retaining first-stage and conditional factors separately. Estimate target, control, and paired readiness totals with the same admission-level HT/Hájek machinery and the same nested design uncertainty as the parents. Do not complete-case delete `R_U`; conservative readiness sets it non-ready for the lower-bound/gate while separately reporting its unknown count. If `S_TC` is empty, a requested probability is zero/undefined by design and the result is `DEFER`, not a favorable no-control claim.

Before labels, require the same inherited target/control support certificate and, for this endpoint, at least 60 paired-support admissions with a non-null canonical DS payload, positive `pi1_i` and positive conditional `q_i` in every occupied inherited path, and at least two inherited phase-1 strata represented. The readiness denominator is never redefined by `R`, H+, reader response, or successful serialization. A path with zero/undefined inclusion probability, zero second-order support for a requested variance, or undefined denominator fails closed. Structural missingness is reported, not repaired by a control-only admission or replacement.

The readiness endpoint has no incremental reader minutes and no incremental sampled admissions. Its source-only computation is performed once for the already sealed target/control units and serialized as provenance. The inherited workload ledger remains exactly unchanged, including fixed controls, duplicate/holistic charges, distinct-admission accounting, 15% charged reserve, `120<=T<=300`, and `charged_minutes<=84,000`; if implementation adds a human task or a new packet, it is not this endpoint and the protocol fails closed. The inherited 20,000 deterministic nested Rao-Wu replicates replay the frozen endpoint fields without rebuilding membership from labels.

## Prespecified margins and interpretation

The endpoint's design margin is fixed before labels: supportive readiness requires the lower one-sided simultaneous 95% bound for `Delta_R` to be at least `0.10`, the upper simultaneous bound for target non-readiness (with every `R_U` adverse-compatible) to be at most `0.10`, and the upper simultaneous bound for readiness on a pre-label atom-scrambled packet to be at most `0.05`. The finite family (target/control readiness, `Delta_R`, unknown/non-ready rate, and scrambled readiness) is frozen before labels and added to the inherited max-statistic multiplicity family. These are documentation/instrumentability margins, not clinical safety thresholds or effect estimates.

The scrambled readiness control is generated before labels by a cryptographic seed and a derangement of atom IDs that never equals the original atom. It retains source and DS provenance but is marked non-clinical. The serializer must not inspect DS text or H outcomes to choose the replacement atom. Any `R=1` on a scrambled atom is a falsification signal for atom-specificity; it cannot be interpreted as a patient event or used to rescue a real atom. If no derangement exists, the scrambled endpoint is undefined and readiness is inconclusive.

* Supportive: all inherited primary/H/holistic gates pass; readiness has positive support and finite simultaneous intervals; target non-readiness and scrambled-readiness gates pass; and `Delta_R` lower bound is at least 0.10. This supports only that the exact target packet is source-serializable in a fixed forwardable DS scope more often than the matched non-target control under the frozen protocol. It permits consideration of a separately approved silent validation, with no alert, order, copy, referral, or patient-facing action.
* Adverse: with adequate support, target non-readiness exceeds its bound, `Delta_R` is below zero, its lower bound is below zero, or scrambled readiness exceeds its ceiling. This blocks the target-cell silent-bridge nomination for this instrumentability construct but does not imply unsafe care, absent follow-up, or clinical error.
* Inconclusive/`DEFER`: `NO_SELECTION`, no paired support, sparse strata, zero/undefined weights, undefined or excessively wide intervals, `R_U` provenance failure, parser/serializer fixture failure, missing section support, broken seals, or any inherited gate/workload/ledger failure. A positive point estimate below the 0.10 lower-bound margin is inconclusive rather than promoted. Unknown outside care, actual workflow, or clinical adjudication cannot be resolved by MIMIC.

The inherited H/B results remain separately reported. A passing `R` cannot rescue failing H, holistic challenge, exact handoff, route, or paired-control gates; a failing `R` cannot be rescued by H agreement, pooled atoms, neighboring services, favorable consensus, or a post-label reparse.

## Prospective silent bridge after retrospective nomination

Only if the inherited protocol and this endpoint pass may governance consider a target-cell-specific prospective silent study. The shadow system must suppress alerting, copied text, orders, referrals, scheduling, and patient communication. It must use actual calendar timestamps and independently collect report availability/delivery/view logs, accountable user role, order/referral/scheduling/completion/result-review events, edits/copies/overrides, refusal and patient preference, outside-care ascertainment, and independent adjudication of finding reality, recommendation appropriateness, timing safety, adverse events, and outcomes. Those are not in MIMIC and cannot be inferred from `R`, H+, DS placement, service, transfer, ICU, death, or discharge location.

The prospective primary feasibility estimand must be frozen before live exposure and must concern availability of the shadow atom to a documented responsible workflow within the prescribed interval, with delivery/view, action, completion, appropriateness, safety, and outcomes as distinct measures. Missing responsibility, calendar evidence, outside care, or clinical adjudication yields `DEFER`; it is not non-delivery or harm. Only a later governed comparative intervention study could evaluate clinical utility, safety, equity, or benefit.

## Falsification and verification contract

Fail closed if any endpoint membership is selected or altered after labels; if controls are replaced; if a generic or clinically similar phrase is accepted as exact; if a match crosses a section/field boundary; if a conditional, uncertain, negated, historical, screening, surveillance, staging, or no-follow-up phrase is positive; if a missing span, duplicate identity, null text, or unresolved heading becomes `R=1`; if a parser or dictionary is tuned to H results; if the target/control denominator is conditioned on R or H; if the endpoint adds reader time or admissions; if scrambled atoms are chosen from DS appearance; if `R_U` is complete-case deleted; if zero weights are divided; if transfers/ICU/services/death/location are interpreted as delivery or completion; or if any conclusion claims viewing, responsibility, action, appropriateness, safety, benefit, or causality.

The verifier independently reconstructs source/member and schema hashes, all joins, one-admission ordering, strict `D` chronology, reciprocal chain, canonical DS, frozen target/control identities, serializer dictionary hash, section scope, exact `(E,M,W)` matching, packet schema/type checks, double-serialization byte identity, unknown reason codes, derangement independence, support/positivity, HT/Hájek weights, simultaneous margins, unchanged workload ledger, and all nested variance replicates. Fixtures must show that phase-1 label permutations do not change R; a one-token action/interval or heading-boundary perturbation changes only the prescribed readiness status; missing/high-weight provenance widens adverse bounds; generic and conditional text never becomes positive; and scrambled atoms cannot silently pass as real target evidence.

Automatic verification can establish only computational reproducibility of this source-derived endpoint. It cannot establish that a reader's judgment is clinically true, that the DS was delivered/viewed, that a person was responsible, that an order or imaging occurred, or that a prospective bridge is safe or beneficial. Those claims require the unavailable prospective logs, actual-calendar workflow data, outside-care linkage, images/completion evidence, patient preference, and independent clinical adjudication described above.

## What changed and what remains uncertain

Compared with the parents, this child adds a fully source-only, pre-label `R` endpoint and an immutable serializer/provenance contract. It makes prospective-silent instrumentability testable from exact MIMIC paths, columns, keys, timestamps, canonical DS/detail fields, atom IDs, section scopes, and byte-stable packet rules. It adds no sampled admissions, readers, route, label, workload, or inherited estimand. It also makes adverse, unknown, structural absence, positivity, scrambled specificity, and `DEFER` handling explicit.

The unresolved uncertainty is fundamental: MIMIC stores deidentified text and subject-shifted ordering, not actual delivery/view, responsibility, patient preference, order execution, completion, outside care, images, appropriateness, safety, or benefit. `R=1` means only that the registered serializer can construct a shadow packet from stored text. Even a supportive result can nominate only a separately governed prospective silent validation for the exact atom-route; it cannot justify a live alert or any causal or clinical claim.
