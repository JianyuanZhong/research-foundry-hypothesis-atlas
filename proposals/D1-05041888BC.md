# Deterministic documentation-to-actionability bridge with closed field states and an additive workload ledger

## Status, inheritance, and the one permitted change

This is a targeted successor of `[prior hypothesis]`. It repairs only the remaining executable bridge details: deterministic H1/H2 unit matching and ordering, independent H3 rerun reproducibility, explicit NA versus unknown/actionability coding, and additive reconciliation of every bridge charge with the inherited workload contract. It does not restart or reinterpret the scientific design.

The following are inherited and frozen verbatim. The population is the first-eligible adult, one-admission-per-subject, all-opportunity pulmonary-opportunity population. The denominator is not a convenience sample. The reciprocal pre-departure radiology report/addendum chronology, one canonical discharge artifact `DS`, recommendation-unit inventory, unit-specific storage clocks `G_u = DS_store - R_store,u`, exhaustive departure/availability/lag/eventual states `Y,V,H,Z`, exact atom `g=(possible-calendar class, terminal curr_service, workflow class)`, route vocabulary and precedence `AUTO > RECON > TIMING > DEFER > NOACTION`, all-unit adverse admission routing, safety-sentinel census, master/audit probability sampling, inclusion probabilities, hash-rank challenge selection, no-rescue/no-switching/no-post-label reallocation rules, finite-population compatible-set estimands, and the ceilings `A <= 900` distinct admissions and `C <= 300` challenge admissions are unchanged. The conclusion ceiling is unchanged: a successful retrospective result can nominate only a prospective silent validation of stored-text behavior. It cannot establish delivery, viewing, responsibility acceptance, appropriateness, completion, safety, benefit, or causality.

The bridge remains a pre-label, route-blinded secondary layer within the already budgeted sampled-admission review. It asks two separate, falsifiable questions. **H1** is whether the frozen radiology recommendation-unit inventory can be reproduced from its sealed source-unit packet and canonical serialization. **H2** is whether the corresponding explicit text-defined handoff/actionability fields can be reproduced from the sealed discharge packet, conditional on a *label-eligible* target unit. **H3** is whether the source-unit/assertion representation and its deterministic serialization are independently rerunnable. H1/H2 are documentation constructs, not clinical truth. H3 is a software-and-specification reproducibility check, not external validation.

## Frozen packet and canonical serialization

Before any labels are seen, the compiler creates immutable packets and writes a manifest containing the catalog hash, source IDs, schema hashes, archive-member names, code version, timezone (`UTC`), Unicode normalization (NFC), newline normalization (`LF`), and parser version. Source files remain read-only. Every packet has a unique `packet_id` and an admission key `(subject_id,hadm_id)`.

For each radiology source note, the source-unit packet contains `subject_id`, `hadm_id`, `note_id`, `note_type`, `note_seq`, parsed `charttime`, parsed `storetime`, the normalized text bytes, and all matching `radiology_detail` rows sorted by `(field_name,field_ordinal,field_value)`. Report/addendum chronology is frozen by the inherited reciprocal rule. A recommendation unit has an immutable `source_note_id` and a `unit_ordinal`; it is never identified by text position alone. For each unit, the packet retains the exact source-note identifiers and the raw and normalized spans/assertions used by the blinded adjudication.

The canonical row serializer is length-prefixed UTF-8 with fields in this exact order:
`subject_id,hadm_id,note_id,note_type,note_seq,charttime,storetime,field_name,field_ordinal,field_value,unit_ordinal,assertion_code`.
Null is serialized as the literal token `\N`; an empty string is serialized as a zero-length field; integers are base-10 without padding; timestamps are ISO-8601 UTC to microseconds. Each row is sorted by the tuple `(subject_id,hadm_id,note_id,note_seq,charttime,storetime,field_name,field_ordinal,field_value,unit_ordinal,assertion_code)` using bytewise UTF-8 order, with null preceding non-null. Duplicate rows are retained with multiplicity. A packet manifest records row count, SHA-256 of the serialized bytes, and the ordered list of source IDs. This is the only ordering used by H1, H2, or H3; filesystem order, database query order, reviewer order, and Python hash order are prohibited.

The canonical discharge packet is similarly serialized from the selected `DS` note and its detail rows, with its admission key, `note_id`, `charttime`, `storetime`, text, and detail fields. If no qualifying `DS` exists, the packet is present with an explicit `DS_ABSENT` state and an empty payload hash; it is not dropped.

## Deterministic H1/H2 matching and order contract

### Frozen output vocabulary

Every recommendation unit and every candidate discharge assertion receives exactly one of these mutually exclusive states, with the raw condition flags retained: `MATCH_EXACT`, `MATCH_NORMALIZED`, `MISMATCH`, `SOURCE_UNIT_AMBIGUOUS`, `SOURCE_UNIT_MISSING`, `TARGET_AMBIGUOUS`, `TARGET_MISSING`, `TEXT_UNREADABLE`, `NONRESPONSE`, or `NOT_ELIGIBLE`. `NOT_ELIGIBLE` is not a failure and is used only for the explicit NA states below. No reader may invent a new category.

H1 and H2 use the same canonical unit identity, matching vocabulary, and ordering. This prevents one panel from manufacturing a favorable denominator by splitting, merging, or reordering units.

### Canonical unit identity and matching

The source unit key is `U=(subject_id,hadm_id,source_note_id,unit_ordinal)`. `unit_ordinal` is the ordinal in the sealed, pre-label source-unit inventory; it is assigned by the frozen parser and never by a target reviewer. The target assertion key is `T=(subject_id,hadm_id,DS_note_id,target_ordinal)`, where `target_ordinal` is assigned by a separate frozen target parser over the canonical `DS` bytes. Target ordinals are therefore stable even when two assertions have identical text.

For each admission, source units and target assertions are matched by the following deterministic one-to-one algorithm, run before route labels are revealed.

1. Normalize each assertion into a tuple of prespecified fields: modality, anatomic target, interval/calendar class, action verb, and assertion polarity. Normalization uses only the frozen lexical/codebook map; it does not use route, service, outcome, or reviewer edits. Preserve both raw and normalized values.
2. Construct candidate edges only when the admission key agrees and the normalized modality, target, and polarity agree. An interval is an exact field, not a free-text similarity. `UNKNOWN` or `NOT_PRESENT_IN_AVAILABLE_SOURCES` in any required identity field does not wildcard-match; it makes the edge ineligible and is retained as unresolved.
3. Assign edge class `EXACT` when all required normalized fields and the source-to-target interval/calendar class agree; assign `NORMALIZED` only when the raw lexical forms differ but the frozen normalization maps them to the same tuple. Any disagreement is `MISMATCH`, not a near match.
4. Solve the one-to-one assignment by maximum cardinality, then maximum total edge class (`EXACT` before `NORMALIZED`), then minimum absolute interval-distance in integer days, then lexicographically smallest sorted list of pairs `(source_note_id,unit_ordinal,DS_note_id,target_ordinal)`. This is a total order. If the best assignment is not unique after all tie-breakers, every involved unit is `SOURCE_UNIT_AMBIGUOUS` or `TARGET_AMBIGUOUS`; do not choose the first database row.
5. A duplicate restatement in the same source note remains one source unit if and only if the parser's frozen unit boundary says it is one assertion; identical text in distinct `unit_ordinal` values remains distinct. Cross-admission candidates, malformed IDs, duplicate primary identities, and impossible timestamps fail closed as `SOURCE_UNIT_AMBIGUOUS`/`TARGET_AMBIGUOUS` and are counted.
6. Emit matched pairs in the canonical order `(subject_id,hadm_id,source_note_id,unit_ordinal,DS_note_id,target_ordinal)`. Emit unmatched source units next in source-key order and unmatched target assertions next in target-key order. The manifest contains all three lists and their hashes. H1 and H2 must consume exactly this manifest, not independently rediscover units.

The H1 inventory-reproducibility label is computed from the sealed source packet and an independently produced source-unit inventory. `H1=1` only if the two inventories have identical canonical row hashes, identical ordered unit keys, identical normalized identity tuples, and identical assertion states. Any missing, extra, reordered, ambiguous, unreadable, or unknown unit yields `H1=0` or an unresolved compatible state according to the inherited adverse rule; it is never silently excluded.

H2 is computed only for a target unit whose eligibility state is `ELIGIBLE_TARGET`. H2 asks whether the canonical DS explicitly carries the unit's prespecified handoff fields: identity tuple, timing/interval, action, and named follow-up destination or responsible service when that field is part of the inherited actionability definition. H2 uses the exact H1/H2 pair manifest above. It has no access to route labels, atom labels, adjudicator decisions from another component, post-discharge records, or workflow claims.

## Explicit eligibility, NA, unknown, and actionability table

The eligibility/actionability field state is frozen before labeling and is applied per source unit, then aggregated adversely to the admission. Each field retains `raw_present`, `parsed_value`, `source_note_id`, `field_path`, and `reason_code`.

| state | deterministic condition | included in H2 denominator? | interpretation |
|---|---|---:|---|
| `ELIGIBLE_ACTIONABLE` | source unit is eligible; required target fields are present and explicit in DS | yes | positive text-defined actionability state |
| `ELIGIBLE_PARTIAL` | source unit eligible; at least one required field present but at least one required field absent/ambiguous | yes | adverse unresolved actionability, never success |
| `ELIGIBLE_REPLACED` | DS contains an explicit competing/superseding plan under the frozen parser | yes | actionability of the original unit is not asserted; preserve replacement state |
| `ELIGIBLE_CONTRADICTED` | DS explicitly contradicts a required source field | yes | adverse mismatch |
| `ELIGIBLE_TIMING_INVALID` | explicit target text exists but timing is malformed, stale, or outside the inherited boundary | yes | adverse timing state |
| `ELIGIBLE_UNREADABLE` | source or DS text exists but required field cannot be parsed under the locked codebook | yes | adverse unknown |
| `ELIGIBLE_NONRESPONSE` | DS packet exists and is readable but no target assertion can be linked | yes | adverse nonresponse |
| `NA_NOT_ELIGIBLE` | unit fails the frozen pulmonary/opportunity eligibility predicate before H1/H2 labels | no | structural NA, retain reason |
| `NA_NO_TARGET` | eligible source inventory has zero target units because the inherited target-universe rule gives no target opportunity | no | structural NA, not a missed handoff |
| `NA_NO_ACTION` | eligible unit is explicitly classified by the frozen action vocabulary as `NOACTION`, with no requested follow-up/action field | no | structural NA, not a documentation failure |
| `NA_ROUTE_DEFER` | inherited route is `DEFER` and the unit is outside the H2 actionability target by the preregistered target rule | no | structural NA, not evidence of readiness |
| `UNKNOWN_SOURCE_AVAILABILITY` | required modality/field availability cannot be determined from the packet or schema audit | yes where unit is otherwise eligible | unresolved, adverse for gates |
| `NOT_PRESENT_IN_AVAILABLE_SOURCES` | the source-audit manifest establishes that the workflow/outcome fact is not collected by any permitted MIMIC table | not applicable | availability limitation, never an observed patient state |

Precedence is exact and fail-closed: `NA_NOT_ELIGIBLE` first; then `NA_NO_TARGET`; then `NA_NO_ACTION`; then `NA_ROUTE_DEFER`; then source/target ambiguity, unreadable, contradiction, replacement, partial, nonresponse, and finally positive actionability. A record cannot receive an NA label merely because the text is missing or inconvenient to review. Conversely, an unavailable workflow fact cannot be converted to `UNKNOWN` at the patient level or to a negative actionability result. The raw flags and the final state are both reported. For an admission with multiple eligible units, any adverse or unresolved unit determines the admission-level bridge state; `NA` units do not mask an adverse eligible unit.

The denominator for the primary H2 descriptive estimand is the finite population of eligible target units after applying only the preregistered NA rules. Its numerator is `ELIGIBLE_ACTIONABLE`; all other eligible states remain in the denominator. The inherited admission-level estimand, routes, and all-unit adverse rule are unchanged. If a stratum has no eligible target units, its H2 estimand is structurally undefined and reported as NA with its census count, not as zero.

## Independent H3 reproducibility contract

H3 is produced by an independent implementation or independently rostered rerun that receives only the immutable packet manifest, raw permitted rows, and a sealed codebook version. It receives no H1/H2 labels, route, atom, sample assignment, reviewer comments, or prior output hash. The primary implementation writes an append-only `H3_source_unit_manifest` containing one row per `(subject_id,hadm_id,source_note_id,unit_ordinal)` and one row per assertion with normalized tuple, state, source references, and canonical serialization hash.

The independent rerun must reproduce, byte for byte, the canonical ordered unit keys, normalized tuples, state codes, row counts, and SHA-256 hashes. It is run three times: original input order, reverse input order, and a deterministic pseudorandom permutation generated from seed `H3-2026-09-12` using PCG64. Inputs are also split into fixed chunks and concatenated in reverse chunk order. All four reruns must yield identical manifests and hashes. The verifier checks that no unordered container, wall-clock time, locale, filesystem traversal, or unstable floating-point operation enters identity or order. A failure is `H3_FAIL_REPRODUCIBILITY`, not a rerun selected for convenience; the compatible set is widened/adverse and no route nomination can pass the H3 gate.

H3 includes the matcher manifest because a reproducible unit inventory with nondeterministic H1/H2 matching is insufficient. H1/H2 and H3 are distinct: H1/H2 compare independently sealed documentation artifacts, whereas H3 tests whether the source-unit/assertion construction itself is a deterministic executable object. The H3 pass criterion is exact identity, not approximate agreement or a favorable percentage.

Positive controls are seeded synthetic packets with known exact, normalized, unmatched, duplicate, ambiguous, missing, and NA cases. Negative controls permute target assertions across admissions, reverse timestamps, and alter one required identity field. Before labels, the verifier freezes the expected outcomes and hashes. Any positive-control failure, negative-control match, or leakage of route/reviewer fields fails the bridge and is recorded rather than repaired after inspection.

## Additive workload ledger and reconciliation

No bridge task is free. The inherited ledger is copied verbatim as ledger version `PARENT_LEDGER_V`; this amendment adds named bridge rows rather than replacing, netting, or redefining parent charges. The hard ceilings remain `A<=900`, `C<=300`, physician review time `H<=1,400` hours, and packet-review time `M<=84,000` minutes, with any stricter inherited sub-cap also binding.

For every admission `i`, record a single immutable ledger row with the admission key, phase, stratum, challenge flag, number of source units `nU_i`, number of target assertions `nT_i`, and these nonnegative charges in minutes:

* `m_census,i`: census/eligibility packet assembly;
* `m_H1,i`: source-unit inventory and H1 review;
* `m_H2,i`: target/actionability review;
* `m_H3,i`: independent rerun and manifest verification;
* `m_audit,i`: any inherited duplicate or audit review;
* `m_admin,i`: masking, seal, transport, and quality-control time.

The bridge charge is the sum of the actual recorded components, `m_bridge,i = m_census,i+m_H1,i+m_H2,i+m_H3,i+m_audit,i+m_admin,i`, with zero charge recorded explicitly for a task not performed. Physician minutes are a separately recorded subset of the same task rows, not another additive copy of packet minutes. If a reviewer performs two roles, time is split by the contemporaneous task timer; overlapping minutes cannot be counted twice. If a packet is infeasible, its attempted time through the fail-closed decision is charged and the admission remains in the denominator/census as inherited.

The final reconciliation is:

`M_total = M_parent_actual + sum_i(m_bridge,i) + M_duplicate_corrections`,

`H_total = H_parent_actual + sum_i(h_bridge,i) + H_duplicate_corrections`,

`A_total = A_parent_distinct ∪ A_bridge_distinct`, and

`C_total = C_parent_challenge ∪ C_bridge_challenge`,

where the admission unions are keyed by `(subject_id,hadm_id)`, so a bridge review of an already reviewed admission adds workload but not a second admission. `M_duplicate_corrections` and `H_duplicate_corrections` are nonnegative only; double-count detection never creates negative credit. The ledger also reports parent, bridge, overlap, and total rows separately and includes hashes of the row-level ledger and its aggregation.

Allocation is fixed before labels. Let `r_i` be the registered worst-case packet minutes and `q_i` the registered worst-case physician minutes for each planned task. The selected master plus audit plus bridge allocation must satisfy, before any review begins, `sum_i r_i <= 84,000` packet minutes and `sum_i q_i <= 84,000` physician minutes (equivalently `H<=1,400` physician hours). These checks include the inherited parent worst-case charges and every bridge task; packet minutes and physician minutes are distinct ledgers, even when both arise from the same task. A planned bridge allocation that would exceed either cap is rejected before labels; there is no post-label downsampling or silent truncation. If actual charges exceed a cap because of an implementation fault, the entire bridge is `LEDGER_OVERFLOW`, the relevant estimate is inconclusive, and no route is nominated.

The distinct-admission ceiling is checked independently: the union of all parent and bridge admissions must be at most 900, and the challenge subset at most 300. The source-wide safety-sentinel census and unsampled accounting remain as inherited, non-review admission counts and are not incorrectly added to the distinct sampled-admission total. The ledger reports planned worst case, actual charge, unspent reserve, and every fail-closed exclusion.

## Analysis, falsification, and interpretation

All H1/H2 bridge estimates use the inherited known inclusion probabilities and finite-population Horvitz-Thompson/Hájek-compatible-set procedure. The implementation reports unit-level and admission-level counts, weighted proportions, effective sample size, and uncertainty with the inherited replication method. It does not pool route cells, borrow across strata, learn thresholds, or treat agreement as truth. Unknown, ambiguous, partial, contradicted, unreadable, nonresponse, H3 failure, control failure, packet infeasibility, and ledger overflow are adverse or inconclusive exactly as specified; they are never removed to improve a gate.

The prespecified supportive pattern is simultaneous H1 exact/normalized reproducibility and H3 byte identity, no negative-control matches, adequate weighted support and effective sample size, and an H2 actionability estimate reported with its adverse states and uncertainty while all ledger and leakage checks pass. Even then, the only supported claim is that, in this MIMIC stored-text sample, the frozen source-unit construction and explicit DS fields are reproducible enough to justify a prospective silent validation. It does not support clinical appropriateness, actual action, or benefit.

An adverse pattern is any H1/H3 mismatch, ambiguity or missingness beyond the registered gate, negative-control match, route leakage, nonresponse/partial/contradiction burden that fails the registered gate, or any ledger/ceiling violation. It argues against nominating the relevant atom-route cell for silent validation and identifies which documentation component failed. An inconclusive pattern is zero or sparse eligible support, unavailable source modality, failed feasibility, wide compatible bounds crossing the gate, or a H3/control/ledger failure that prevents interpretable estimation. Inconclusive is not evidence of success or failure and requires a new independently registered study or prospective collection.

The verifier may check exact source paths and schema bindings, key/time joins, deterministic hashes, state precedence, matching/order fixtures, weights, denominators, caps, ledger sums, and that each conclusion is linked to a saved output. It cannot determine whether a text field was clinically appropriate, whether someone saw or acted on it, whether a patient received follow-up, or whether any route changes safety or outcomes. Those claims require expert adjudication, workflow telemetry, prospective silent deployment, and a later governed comparative study. No conclusion may exceed this evidence boundary.
