# Does the laboratory testing process in the first 24 h add prognostic information for in-hospital mortality beyond APACHE II and measured values? A bounded eICU study with leave-one-hospital-out transport analysis

## 1. Unresolved clinical question

In ICU stays, does **testing intensity** in the first 24 h — the number of distinct laboratory tests ordered and the number of results returned — carry **independent prognostic information for in-hospital mortality** beyond (a) the standard APACHE II severity score and (b) the measured values of core laboratories, and is the association **consistent across hospitals**?

Two competing explanations, with different observable predictions:

1. **Acuity-proximate signal.** Clinicians order more tests for sicker patients; testing intensity captures unmeasured severity not represented in APACHE II (which is built from 12 fixed physiologic variables, age and chronic health [K2]). Prediction: testing intensity remains significantly associated with mortality after conditioning on APACHE II and core lab values, and the association is similar in direction and magnitude across hospitals.
2. **Practice/selection artifact.** Testing volume reflects hospital ordering culture, lab menu availability, or case mix rather than patient state. Prediction: the association is driven by between-hospital differences (hospital random intercept absorbs it) and/or models using testing intensity lose more performance when transported to a held-out hospital than models without it.

The study is designed to separate these: within-hospital (random-intercept) models test the acuity account conditional on severity; leave-one-hospital-out (LOHO) retraining tests the transport account directly.

### Why it matters

- eICU-CRD contains 39.1M laboratory rows across 195,730 stays [K1]; testing volume is routinely treated only as a missingness nuisance and ignored as a variable.
- If testing intensity adds independent, transportable signal, it is a free real-time feature for early risk stratification (the order stream is available before results return).
- If it does not, that bounds the value of "process" features and argues against deploying order-stream features in transportable risk models — a direct design decision for clinical prediction systems.
- The LOHO contrast answers a known failure mode of EHR prediction: models that learn hospital practice rather than patient state [K3].

## 2. Evidence base and closest inspected work

- [K2] Knaus et al., 1985 (PMID 3928249, abstract inspected): APACHE II is a point score from 12 routine physiologic measurements, age, and previous health status, validated on 5,815 admissions from 13 hospitals. It establishes that a *fixed, small* set of first-24 h measurements stratifies mortality risk — and by construction it does **not** include how many tests were ordered or the values of tests outside the 12. This is the baseline our study must beat.
- [K3] Meyer et al., 2024 (PMID 35045573, abstract inspected): external validation of EHR prediction models showed discrimination collapse (C-statistic 0.93 → 0.57) when models were transported to a different measurement context, and refitting locally recovered performance. This bounds the interpretation of any in-sample gain: without a transport test, an added feature may capture local practice.
- [K1] eICU-CRD documentation (PhysioNet, frozen page inspected): field semantics, offsets in minutes relative to ICU admission, and the laboratory table structure.

None of these has tested whether the *testing process itself* (volume of distinct tests in the first 24 h) adds signal beyond APACHE II in a large multicenter cohort with an explicit transport analysis. A PubMed search for "laboratory test frequency ICU acuity proxy" returned no directly matching study (empty result sets on 2026-09-30); this is an absence-of-evidence in a bounded search, not a proof of novelty.

- `lactate_measured`: binary; `lactate_max`: max `labresult` among lactate rows in window (when present).

**Covariates:** `apachescore` (continuous), `age`, `gender`, `hospitaladmitsource` (categorical; top values measured: Emergency Department 58,469; empty 38,082; Operating Room 14,155; Floor 12,753; Direct Admit 9,132; …), `unittype`.

**Outcome:** `actualhospitalmortality` (EXPIRED=1, ALIVE=0).

## 4. Analysis plan

**Model A (baseline):** logistic GLMM, hospital random intercept; outcome ~ apachescore + age + gender + admitsource + unittype.

**Model B (process):** Model A + log1p(n_results) + log1p(n_types).

**Model C (value-adjusted):** Model B + last-24 h value summaries for the core set {creatinine max, WBC max, platelets min, lactate_max, lactate_measured}, each with a missing indicator. This tests whether the process signal survives measured values.

**Transport (LOHO):** for each of the 171 hospitals: fit Model A and Model B on all other hospitals, evaluate AUROC and calibration (calibration slope/intercept, Brier) on the held-out hospital. Report the distribution of per-hospital ΔAUROC (B − A) and the fraction of hospitals with ΔAUROC > 0.

**Sensitivity (learned alternative):** gradient-boosted classifier (sklearn HistGradientBoosting, CPU) with the same features under the same LOHO split. Rationale: could reveal a non-linear dose–response of testing volume or APACHE × volume interaction that the GLMM cannot; costs interpretability. Retained as sensitivity, not primary, because the estimand is an association and its transport, which the GLMM answers with a clear within-hospital coefficient.

**Falsification criteria (pre-specified):**
- **Supportive:** log1p(n_results) coefficient significant (p < 0.01) in Model C *within-hospital* (random intercept), AND ΔAUROC > 0 in ≥ 60% of LOHO held-out hospitals.
- **Adverse:** association vanishes in Model C (p ≥ 0.10) or is absorbed by the hospital random effect (fixed effect non-significant with random intercept), OR median LOHO ΔAUROC ≤ 0 — testing intensity is a practice artifact or redundant with APACHE II.
- **Inconclusive:** significant in B but attenuated > 50% in C with wide LOHO ΔAUROC CI spanning 0 — requires an external cohort or order-level data before any clinical claim.

## 5. Method alternatives and deferrals (recorded before selection)

- **Baseline GLMM** (primary): interpretable within-hospital estimand; directly answers "does the process add signal conditional on severity, and does it transport?".
- **GBM sensitivity** (retained in solver experiment): non-linear capacity; same split.
- **Ordered-vs-returned tests** (deferred, missing dependency): eICU `lab` is result-level only; there is no order-level timestamp table in this snapshot, so "tests ordered but not returned" cannot be computed. Recorded as an unavailable dependency, not silently dropped.
- **Canonical-panel missingness features** (deferred): defining a canonical panel of expected tests requires a clinical adjudication of what each hospital *should* have ordered; not attempted here. `n_results` is a practice-free count of what was actually returned.

## 6. What a supportive / adverse / inconclusive result would and would not establish

- Supportive: testing intensity is an independent, transportable prognostic feature in this cohort. Would not establish that ordering more tests *causes* better outcomes (association only; clinician behavior is confounded by unmeasured severity). Would justify a prospective study or a trial of order-stream-informed risk alerts.
- Adverse: testing volume is redundant with APACHE II or a hospital-practice artifact. Would not establish that testing is uninformative in general — only that *volume* in this window carries no independent transportable signal.
- Inconclusive: the 24 h window or the result-level proxy may be too coarse; order-level data (unavailable here) or a longer window would be needed.

## 7. Solver deliverables (for compilation)

The solver must:
1. Build the 144,626-stay cohort table with the exposures, covariates and outcome above (deterministic filters; record exact row counts at each filter step).
2. Fit Models A, B, C (GLMM, hospital random intercept) and report coefficients, CIs, within-hospital significance.
3. Run the 171-fold LOHO for A vs B (and A vs C as sensitivity), reporting per-hospital AUROC, ΔAUROC distribution, calibration.
4. Run the GBM sensitivity under the same LOHO split.
5. Write a results JSON linking every reported number to its computed output, plus a short interpretation stating which of supportive/adverse/inconclusive the data support and what would require further study (clinical adjudication of ordering intent is out of scope).

**Resource estimate (planning envelope: 16 CPU, 256 GB, 28,800 s):** cohort build ≈ 5–10 min per full lab pass (measured: 272 s for the 24 h pass on 4 CPU); GLMM fits on ~145k rows are seconds each; 171 LOHO fits × 2 models ≈ 342 GLMM fits (seconds each) + 342 GBM fits (tens of seconds each) — total well within 28,800 s on 16 CPU. No GPU required. Estimates marked *measured* are from the discovery probes above; LOHO runtime is *unverified* but bounded by the measured single-fit times.

## 8. Limitations

- `labtypeid` is coarse (6 categories in a 2M-row sample); `n_results` is the primary exposure for this reason.
- eICU `apachescore` field range (0–211) exceeds the classic 0–71 scale; used as a continuous covariate without reinterpretation.
- In-hospital mortality is the outcome; ICU mortality (`actualicumortality`) is a pre-specified sensitivity.
- No order-level data: cannot distinguish "ordered but not returned" from "not ordered".
- 5.5% of stays have no core lab in 24 h; retained with missing indicators (documented, not dropped).
- Association, not causation; clinician ordering is confounded by unmeasured severity.
