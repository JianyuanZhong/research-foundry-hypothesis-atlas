# Executable compatible-set and finite-workload repair

## Status, parent, and scope

This is a targeted child of `[prior hypothesis]`. It preserves the parent's scientific schema and precedence. The repair is limited to two implementation gaps: (1) making the admission-level compatible set under arbitrary correlated/shared reviewer error an enumerable, nonempty, jointly optimized object; and (2) reconciling every admission, physician-hour, challenge, packet-minute, and atom-level workload bound in one fail-closed ledger.

The frozen decision remains whether an exact MIMIC pulmonary-opportunity signature can be nominated for a prospective **silent**, within-site validation of text-defined `AUTO`, `RECON`, `TIMING`, or `DEFER` routing. This is a stored-text reproducibility and contamination audit. It is not a test of guideline appropriateness, clinician performance, actual workflow delivery, patient safety, follow-up, benefit, causality, or transport. A retrospective pass cannot authorize an alert, order, referral, or patient-facing action. No claim may exceed the prospective-silent-only ceiling.

No population, chronology, canonical artifact, recommendation atom, route estimand, sampling stratum, inclusion probability, all-unit adverse rule, no-rescue rule, or conclusion boundary is changed. Where an inherited paragraph uses “selected challenge” ambiguously, this amendment uses **phase-1 selected** for every sampled admission and **phase-2 challenged** only for the pre-label subset `C`; this is a terminology repair, not a change to the two-phase design.

## Frozen vocabulary and route truth table

The protocol hash freezes the following ordered categories. They cannot be merged or renamed after labels.

* Atomic status: `SUPPORT`, `CONTRADICT`, `INDETERMINATE`, `NOT_PRESENT`, `UNREADABLE`, `NONRESPONSE`.
* Unit status: `U_RESOLVED`, `U_OPEN`, `U_TIMING`, `U_CLOSED`, `U_DEFER`, `U_BOUNDARY`.
* Departure: `F`, `C_O`, `C_I`, `R`, `A`, `U_D`; availability `V_D`, `V_24`, `V_72`, `V_168`, `V_late`, `V_U`; lag `H_stale`, `H_0_6`, `H_6_24`, `H_24_72`, `H_72plus`, `H_U`; eventual text `F_text`, `C_O_text`, `C_I_text`, `R_text`, `U_text`.
* A route assertion is exactly `(unit_id,target_cluster,action_modality,due_interval,polarity,recipient,responsibility,replacement,conflict)`. Every field is an applicable coded value, `ABSENT`, or `UNKNOWN`.
* Admission output is `ROUTE_AUTO`, `ROUTE_RECON`, `ROUTE_TIMING`, `ROUTE_DEFER`, `ROUTE_NOACTION`, or `UNKNOWN`. Missing, unreadable, nonresponse, unresolved reciprocal link, boundary, or conflict remains adverse-compatible.

The implementation must materialize the inherited route-table predicates, rather than a reviewer vote. Let `P_A(u)`, `P_R(u)`, `P_T(u)`, and `P_D(u)` be the already-frozen parent unit predicates, including its exact opportunity, action, recipient/responsibility, replacement, conflict, and clock rules. For an admission with unit inventory `U`, the locked reducer is:

```text
if U is empty: ROUTE_NOACTION
else if any unit is UNKNOWN, U_BOUNDARY, unresolved, nonresponsive, unreadable,
        or has a route-table DEFER condition: ROUTE_DEFER
else if any unit satisfies the parent TIMING predicate: ROUTE_TIMING
else if any unit satisfies the parent RECON predicate: ROUTE_RECON
else if every unit satisfies the parent AUTO predicate: ROUTE_AUTO
else: ROUTE_DEFER
```

The listed route order remains the parent's `AUTO, RECON, TIMING, DEFER`; the all-unit reducer takes the worst admissible unit, so the mixed states are deterministic and no favorable unit can mask an adverse unit. If a compiler implementation evaluates predicates in a different order, it is invalid unless its output is byte-for-byte identical to this reducer and the sealed parent route table. `ROUTE_NOACTION` is descriptive and is never silently converted to `AUTO`.

The following truth-table fixtures are required before any real label. `S` means all required fields are `SUPPORT`/known, `?` means `UNKNOWN` or unresolved, and the due/clock symbols are the exact parent-coded values.

|---|---|---|

## Deterministic two-phase allocation and one additive ledger

Before labels, compute the parent's complete `N_A`, five outcome-blind strata, support atlas, exact atom `g=(possible-calendar class, terminal curr_service, workflow class)`, residual cells, and unchanged phase-1 `n_h`. The allocation is deterministic:

```text
for every noncensus cell c=(h,g or RESIDUAL_h):
    reserve k_c=min(2,N_c) by hash-rank(protocol_hash || c || admission_key)
solve the predeclared integer allocation for unchanged n_h:
    k_c <= n_c <= N_c; sum_c n_c=n_h
    lexicographically maximize minimum n_c/N_c over certifiable atoms,
    then minimum n_c over certifiable atoms,
    then negative projected maximum normalized weight;
    minimize absolute deviation from n_h*N_c/N_h;
    tie-break (h,E,terminal_service,W), then admission hash.
```

The solver is a pinned exact integer solver or deterministic exhaustive branch-and-bound. It writes constraints, objective, version, unique optimum, tie-break, cell counts, ordered IDs, `pi_i`, and `pi_ij` before labels. If no unique optimum remains after all tie-breaks, selection is invalid. Any occupied certifiable cell unable to receive its reservation is moved once to `RESIDUAL` before labels; no post-label movement, top-up, replacement, adaptive reallocation, atom merging, or route-triggered verification is allowed.

Draw without replacement by the same hash rank. For each phase-1 admission, `pi_i=n_c/N_c` (or 1 for census) and `w_i=1/pi_i`. The hard distinct-admission ceiling is:

```text
N_total = N_sentinel + sum_h(formula sample n_h) <= 900.
```

A duplicate reading, duplicate unit, control packet, or H1/H2/H3 packet never adds an admission. If the unchanged inherited formula samples exceed 900, the run is `NO_SELECTION` rather than downsampling a stratum.

Set `Q=floor(N_total/3)`. Before any label, rank phase-1 admissions by `hash(protocol_hash || "challenge" || admission_key)`. Let `R` contain the first two ranked phase-1 admissions in each occupied final-atlas atom whenever those records exist. If `|R|>Q`, `R` is not feasible and the run is `NO_SELECTION`; there is no hidden atom borrowing. Otherwise set `C=R` plus the first `Q-|R|` non-reserved phase-1 admissions in the same hash order. Thus `|C|=Q<=300`, and challenge inclusion is conditional on the already drawn sample. `C` is never enriched by route, disagreement, outcome, missingness, or workload. Challenge summaries use the inherited conditional design weights and are never complete-case or unweighted substitutions.

### Physician ledger

Every phase-1 admission receives exactly the inherited base activities. Every phase-2 challenged admission receives every challenge activity, regardless of apparent route.

| Activity | maximum hours per phase-1 admission | maximum hours per challenged admission |
|---|---:|---:|
| eligibility and retrieval-negative review | 0.30 | 0 |
| index recommendation and context lanes | 0.45 | 0 |
| independent audit lanes | 0.50 | 0 |
| redaction/access QA and minority-unit safety audit | 0.45 | 0 |
| inherited base total | 2.00 | 0 |
| H1 holistic challenge | 0 | 0.50 |
| H2 independently coded holistic challenge | 0 | 0.50 |
| H3 assertion-support challenge | 0 | 0.35 |
| locked controls and packet-integrity check | 0 | 0.15 |
| challenge increment | 0 | 1.50 |

The complete physician ledger is additive and is computed from actual activity minutes, with no double counting:

```text
H_phys = H_setup + H_base + H_challenge
H_setup <= 120 hours
H_base <= 2.00*N_total hours
H_challenge <= 1.50*|C| hours
H_phys <= 120 + 2*900 + 1.5*300 = 5,070 hours <= 5,100 hours.
```

`H_setup` covers codebook writing, hashing, training on synthetic fixtures only, packet-generation QA, seal verification, and prespecified statistical computation. It cannot be converted into extra reviews. Each activity has an append-only start/stop record, reviewer pseudonym, admission key or setup identifier, and capped minutes. Any activity cap, `N_total<=900`, `|C|<=300`, or 5,100-hour absolute cap breach invalidates selection or the affected run; unused setup time cannot rescue real-admission overflow.

### Packet-minute ledger

Packet minutes are a separate operational clock for extraction, redaction, assembly, hash verification, and access QA; they are not physician adjudication hours and are not converted into hours. The fixed packet contract is:

| Packet activity | maximum minutes |
|---|---:|
| phase-1 packet extraction/redaction/hash QA per phase-1 admission | 60 |
| additional phase-2 holistic/control packet work per challenged admission | 90 |
| fixed packet setup/closeout (templates, manifest, seal and roster verification) | 3,000 |

The single packet ledger is:

```text
M_packet = M_setup + M_base + M_challenge
M_setup <= 3,000 minutes
M_base <= 60*N_total minutes
M_challenge <= 90*|C| minutes
M_packet <= 3,000 + 60*900 + 90*300 = 84,000 minutes.
```

Packet time is recorded per packet and per control. A packet is not counted twice because a duplicate reading shares a packet identifier but has its own physician activity record. A packet-minute breach, missing packet hash, roster leak, or phase-order violation is adverse/inconclusive and cannot be hidden by physician-hour compliance. The inherited atom gate remains binding: the simultaneous upper median packet-time bound must be at most 45 minutes where that gate is specified, and atom-specific upper physician hours per 100 atom admissions must be at most 400; a pooled pass cannot rescue an atom. If an atom's reservations or packet controls are infeasible, that atom is unsupported/inconclusive and is not allow-listed.

## Enumerable compatible sets with unrestricted shared error

For admission `i`, let `O_i` be the sealed outputs from the two parent lanes, minority-unit auditor, H1/H2/H3, including all atomic fields, route outputs, missingness, packet integrity, and safety findings. Let `r_i^P` be the locked parent route and let `r_i^H` be the route computed from the holistic cross-product. `A_i(r)=1` is the operational adverse indicator when route `r` is not defensible under at least one admissible reading; it is not clinical harm.

No latent clinical truth is introduced. The compatible set describes possible observable audit states consistent with recorded outputs and the frozen error model.

### Finite state construction

For every panel `p` and every atomic field `f`, define observed value `o_{pif}` and a finite corrected value domain `D_f` equal to the frozen vocabulary for that field. Define an error bit `e_{pif}` and corrected value `t_{pif}`. Enumerate, in lexicographic order, all tuples satisfying:

```text
if o[p,i,f] is missing, unreadable, nonresponsive, or UNKNOWN:
    t[p,i,f] = o[p,i,f]       # no favorable imputation
    e[p,i,f] = MISSING
else if e[p,i,f] = 0:
    t[p,i,f] = o[p,i,f]
else:
    t[p,i,f] in D_f, including the observed value
```

For nonmissing fields, an error flag means that the observed assertion may be wrong; it does not edit the stored observation. The corrected tuple is only a compatible explanation used to evaluate the locked route table. Error flags are unconstrained across panels: every subset of panels may share every error bit, including all panels. Thus the construction permits correlated/shared reviewer error, identical codebook error, and shared-text error; it never assumes conditional independence. A reason code records `IDENTITY`, `PANEL_ERROR`, `SHARED_ERROR`, `MISSING_ADVERSE`, `BOUNDARY_ADVERSE`, or `CONTROL_INFEASIBLE`.

For each candidate tuple `z`:

1. retain all observed nonmissing fields exactly;
2. enumerate reciprocal restatement deduplication only for the same locked `unit_id`; retain distinct units;
3. apply the inherited unit matcher, admitting `MATCH` and `NONMATCH` whenever an observed field is `UNKNOWN`, never selecting a favorable match by hand;
4. calculate the parent unit predicates and all-unit route using the truth-table reducer;
5. require the route, unit precedence, packet-integrity, missingness, and no-rescue rules;
6. append `z` with its full reason code if and only if these conditions hold.

If a panel is missing/nonresponsive, the only compatible certification states are adverse-compatible states and `missingness=1`; its observed missing field is never replaced by support. If all holistic panels report support on every route-defining field, the identity member remains in `Omega_i` for the lower endpoint, but a shared-error member is also retained whenever a finite corrected tuple can produce an adverse route. Unanimous agreement therefore never proves truth. If no adverse corrected tuple is compatible with a particular fully resolved state, the set still contains the identity state and the reason is recorded; the implementation must not fabricate an adverse member solely to widen a bound.

The final set is

```text
Omega_i = sorted(unique({z: z satisfies all six rules above}))
```

The fixture runner asserts `|Omega_i|>=1` for every admissible observed record. It writes `|Omega_i|`, every member's route, corrected fields, shared-error mask, reason, and whether lower and upper contributions differ. A malformed observed tuple is mapped to `UNKNOWN` before enumeration, so malformed input cannot make the set empty.

### Joint sharp bounds

For each admission, each `z in Omega_i` supplies a finite contribution vector for confirmation, disagreement, `C_AUTO`, `D_MIX`, leakage, capture, workload, and route-specific atom quantities. Do not replace it by a midpoint. Solve each cell and each Rao-Wu replicate with binary variables `x_{iz}`:

```text
sum_z x[i,z] = 1 for every i
x[i,z] in {0,1}
```

The weighted total of any contribution is the exact design-weighted sum over selected states. For a ratio `T_y/T_d`, retain numerator and denominator jointly and solve min/max by rational Dinkelbach iterations (or exhaustive enumeration for small fixtures); if every feasible denominator is zero, report `NO_RATIO`, never a zero or complete-case substitute. This admission-wise program prevents incompatible independently minimized numerator and denominator states from being combined. Nested route/event quantities are optimized jointly under the same `x` variables.

Use the widest of: sharp compatible-set endpoints; exact stratified finite-population inversion; and the inherited common 20,000 Rao-Wu max-statistic family. Preserve design weights, census fixed units, missingness, packet corruption, and control infeasibility adversely. No consensus, latent-class estimate, shrinkage, pooled atom, neighboring atom, or model-based narrowing may alter certification. A diagnostic latent-class fit may be reported only if separately justified and identifiable before labels; it cannot narrow the primary interval.

A narrow interval means only that the declared observable audit functional is constrained by recorded panel outputs and design. A wide interval, an upper endpoint crossing a gate, or a denominator with no feasible positive state blocks nomination. If shared-error compatibility makes a gate unidentifiable, report `NO_SELECTION` or atom-level inconclusive rather than inventing independence.

## Required nonempty-state and falsification fixtures

The verifier must execute these fixtures without clinical records before labels:

1. **Identity state.** One fully resolved T1 admission observed identically in parent and all holistic panels. `Omega_i` contains the identity T1 state and has a nonzero lower contribution.
2. **Shared-wrong state.** The same three panels unanimously observe a nonmissing T1 atomic tuple, while a corrected tuple with one route-defining field changed to the predeclared adverse category is enumerated with a shared error mask. `Omega_i` contains both identity and adverse members; AUTO certification is blocked if its upper bound crosses the frozen gate. Agreement is not truth.
3. **Missingness.** One panel has `UNKNOWN` recipient or nonresponse. The only certification-compatible route is adverse-compatible `DEFER`/`UNKNOWN`; `Omega_i` is nonempty and its width is no smaller than the corresponding complete observation. No favorable imputation is accepted.
4. **Correlated disagreement.** H1/H2 disagree on one field and H3 repeats H1. Both `MATCH` and `NONMATCH` branches are present when allowed by the inherited matcher, and the shared H1/H3 error mask is retained. Independent-panel multiplication is prohibited.
5. **Joint ratio.** Two admissions have state pairs where the state minimizing the numerator also forces a zero denominator, while another state gives a positive denominator. The jointly optimized ratio differs from independently combining admission-level endpoint ratios; the fixture must choose the joint result or `NO_RATIO`.
6. **Mixed-unit route.** T5–T7 above verify that an AUTO unit cannot mask RECON, TIMING, or DEFER.
7. **Allocation tie.** Two allocations with identical first objective are resolved by the declared lexicographic tie-break; if the tie-break is removed, the runner reports invalid rather than analyst choice.
8. **Challenge overflow.** More than `Q=floor(N_total/3)` occupied-atom reservations produces `NO_SELECTION`, even if the physician ledger would fit.
9. **Ledger arithmetic.** The runner asserts `120+2*900+1.5*300=5,070<=5,100` and `3,000+60*900+90*300=84,000`. Any hidden activity or unrecorded packet is a failure.
10. **Atom workload failure.** One atom exceeds its upper 400 physician-hours per 100 or 45-minute packet-time gate while pooled workload passes. Only that atom is excluded; pooled rescue is rejected.
11. **Control invariance.** Route-irrelevant formatting/author-like perturbations cannot change route; a one-field timing/replacement perturbation changes only as the locked truth table permits. Controls are falsification checks, not evidence of clinical correctness.

The verifier must also reject a result that (a) treats unanimous H1/H2/H3 agreement as truth, (b) fits a latent-class model and narrows the primary interval without a pre-label identifying restriction, (c) deletes unknowns or corrupted packets, (d) performs outcome- or route-adaptive challenge selection, (e) counts duplicate readings as admissions, (f) exceeds either time ledger, or (g) concludes workflow delivery, safety, benefit, causality, appropriateness, or transport.

## Outcomes and evidence ceiling

A supportive result requires every inherited gate plus the compatible-set, control, atom-specific, admission, physician, packet, and seal gates for every allow-listed atom. It supports only a separately approved prospective, within-site, silent bridge for those exact observable MIMIC signatures; all other signatures remain `DEFER`.

An adverse result includes an adverse-compatible upper endpoint crossing a route gate, route-invariant control flip, decisive-control failure, atom-specific workload failure, packet/physician/admission overflow, or a supported atom whose AUTO state remains compatible with RECON, TIMING, DEFER, or UNKNOWN. The affected atom is excluded despite favorable agreement.

An inconclusive result includes sparse events, fewer than required challenge cases, impossible reservations, nonresponse, corruption, broken seal order, nonempty-set failure, wide bounds, zero ratio denominator, or absent identifiability. Inconclusive is not evidence of safety, benefit, workflow delivery, or transport.

MIMIC stored text cannot establish physical departure visibility, finalization/signature, communication, responsibility, order/referral execution, patient preference, outside care, appropriateness, follow-up, harm, utility, causal effects, or calendar transport. The source profile's shifted dates, service codes, ICU exposure, and storage clocks remain proxies. Only prospective silent data with actual viewing/edit/sign/transmission, responsibility, orders/referrals, scheduling, outside-plan, and outcome evidence could support stronger claims, followed by expert-governed work for live safety or benefit.
