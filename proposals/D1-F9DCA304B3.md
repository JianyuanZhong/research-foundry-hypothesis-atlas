## Frozen eight workflow-fact availability codes

These are availability codes, not truth labels. For every admission/unit bridge record, each fact receives exactly one code from the following two-state availability vocabulary before any reader label:

- `NOT_PRESENT_IN_AVAILABLE_SOURCES`: the local catalog and permitted source tables contain no field, row, modality, or event representation that can observe the fact under this protocol. This is a **source-level non-observability** result, not a patient-level negative.
- `UNKNOWN`: the permitted source family could in principle carry a related representation, but the relevant row/value/time/link is missing, null, contradictory, ambiguous, outside the locked time window, or otherwise insufficient to determine the fact for this record. `UNKNOWN` is adverse-compatible and never favorable-imputed.

`OBSERVED_PROXY` is not an availability code. Where a proxy is retained for the inherited atom, it is recorded separately with its table, key, and timestamp; it cannot upgrade any workflow fact to observed. The complete eight-fact table is fixed as follows.

## Deterministic unit identity and source-to-panel unit matching

### Canonical source unit

The only source unit key is

```text
U = (subject_id, hadm_id, source_note_id, reciprocal_chain_id, unit_ordinal)
source_note_id = (subject_id, note_id)
```

`unit_ordinal` is zero-based and emitted by the locked extractor over the canonical reciprocal chain. Chain order is sorted by `(storetime, charttime, note_seq, note_id)`, with null times after non-null times and literal serialized note key as final tie-break. Source rows are never merged because text is equal. If the extractor cannot emit a unique ordinal or reciprocal chain, emit `U_BOUNDARY` with a deterministic boundary reason; do not drop the unit.

The extractor emits a structural envelope, not clinical truth:

```text
E(U) = (target_span_id, action_span_id, due_span_id,
        target_cluster, action_modality, due_interval, polarity,
        recipient, responsibility, replacement, conflict)
```

Each coded field is a frozen code, `ABSENT`, or `UNKNOWN`. Span IDs are byte offsets in the NFC-normalized copy of the source text; source text itself is preserved byte-for-byte. No reviewer, panel route, author, service, or outcome can alter `U`.

### H1/H2 packet and output contract

H1 and H2 receive the same permitted source artifacts but independent pseudonyms, packet order, rosters, and sealed codebooks. Each must return append-only JSONL records keyed by the packet pseudonym and source `unit_ref`, not by free text:

```text
{
  "packet_id": string,
  "unit_ref": U or "NO_UNIT_CLAIM",
  "assertion": {
    "target_cluster": code|"ABSENT"|"UNKNOWN",
    "action_modality": code|"ABSENT"|"UNKNOWN",
    "due_interval": code|"ABSENT"|"UNKNOWN",
    "polarity": code|"ABSENT"|"UNKNOWN",
    "recipient": code|"ABSENT"|"UNKNOWN",
    "responsibility": code|"ABSENT"|"UNKNOWN",
    "replacement": code|"ABSENT"|"UNKNOWN",
    "conflict": code|"ABSENT"|"UNKNOWN"
  },
  "reader_state": "SUPPORT"|"CONTRADICT"|"INDETERMINATE"|"UNREADABLE"|"NONRESPONSE",
  "workflow_fact_codes": {"WF01":...,"WF02":...,"WF03":...,"WF04":...,"WF05":...,"WF06":...,"WF07":...,"WF08":...},
  "packet_hash": sha256
}
```

A panel may not invent a new source unit. `NO_UNIT_CLAIM` is retained as an explicit unmatched output and maps to `UNKNOWN`/adverse-compatible; it is never discarded. Malformed JSON, duplicate `(packet_id,unit_ref)` records, out-of-domain values, or missing required keys are `NONRESPONSE` with the raw record hash retained.

### Pure matching function

For each panel assertion, matching proceeds without fuzzy similarity or semantic analyst judgment.

1. Validate admission equality `(subject_id,hadm_id)` and exact `unit_ref` syntax. A different admission is `CROSS_ADMISSION_NONMATCH`.
2. If the panel supplies the exact canonical `U`, match only that source unit. If it supplies `NO_UNIT_CLAIM`, compare against every source unit in that packet and retain all candidate states; an unresolved one-to-many mapping is `AMBIGUOUS_MATCH`, not a best match.
3. Compare `(target_cluster, action_modality, due_interval, polarity, recipient, responsibility)` field-by-field. Identical coded values yield `MATCH`; `ABSENT` versus any non-`ABSENT` yields `NONMATCH`; distinct known codes yield `NONMATCH`; `UNKNOWN` against any admissible value yields both branches (`MATCH` and `NONMATCH`) tagged `UNKNOWN_WILDCARD`.
4. `replacement` and `conflict` are not erased by a match. Differing values retain separate compatible states; any unresolved conflict/replacement remains adverse-compatible.
5. `DUPLICATE_RESTATEMENT` is emitted only when canonical `U` and the complete assertion tuple, including replacement and conflict, are byte-identical. Equal text with a different note ID, chain ID, or ordinal is `DISTINCT_UNIT`.
6. The result is an ordered set of `(match_state, candidate_U, field_trace, reason_code)`, sorted by canonical `U` and field order. It is never collapsed to a vote.

The complete match-state vocabulary is `EXACT_MATCH`, `DUPLICATE_RESTATEMENT`, `DISTINCT_UNIT`, `FIELD_NONMATCH`, `AMBIGUOUS_MATCH`, `CROSS_ADMISSION_NONMATCH`, `UNKNOWN_WILDCARD`, `MALFORMED_MATCH`. `MALFORMED_MATCH` is adverse-compatible and distinct from a structural `NA`.

### H3 reproducibility contract

H3 is not a consensus resolver or truth oracle. H3 receives the same sealed packet artifacts and the **canonical source-unit manifest** plus H1/H2-independent pseudonymization, but not H1/H2 outputs, routes, atom, weights, challenge status, or bridge results. H3 must reproduce the source-unit inventory and assertion tuple under the same extractor/codebook, then independently record `reader_state` for each source `U`. H3 may mark `NO_UNIT_CLAIM`, but may not create a unit identity.

H3 output has the same schema as H1/H2, with `reader_id=H3`; its reproducibility fields are mandatory:

```text
{"source_manifest_hash": sha256,
 "packet_hash": sha256,
 "unit_ref": U|"NO_UNIT_CLAIM",
 "extraction_version": string,
 "assertion": {...},
 "reader_state": ..., 
 "workflow_fact_codes": {...},
 "output_hash": sha256}
```

The verifier runs H3 twice from the same sealed packet with fresh process state and reordered physical input rows. It requires byte-identical canonical output after sorting by `U`; different `source_manifest_hash`, packet hash, unit inventory, or assertion tuple is `H3_REPRODUCIBILITY_FAILURE`. A failure widens the compatible set and is adverse/inconclusive; it cannot be repaired by choosing the more favorable run. H3 agreement with H1/H2 is recorded as agreement only, never as a truth certificate.

All source-derived and panel-derived records use UTF-8, Unicode NFC, ASCII LF, sorted object keys, declared array keys, explicit JSON `null`, no NaN/infinity, and identifiers serialized as strings without floating-point conversion. Timestamps are UTC-naive ISO-8601 with six fractional digits when present. Canonical records are ordered by

```text
(subject_id, hadm_id, source_note_id, reciprocal_chain_id, unit_ordinal,

```

The run writes `unit_manifest.jsonl`, `panel_match_manifest.jsonl`, `h3_repro_manifest.jsonl`, `bridge_eligibility.jsonl`, and `serialization_manifest.json`. Each includes protocol hash, schema hashes, source hashes, code version, input/output counts, sorted-key assertion, and per-record SHA-256. Reordered source rows, repeated execution, and repeated H3 extraction must yield identical manifest bytes and hashes. Any duplicate key, missing null/unknown distinction, source-to-derived count discrepancy, or hash mismatch fails closed.

## Complete mutually exclusive actionability coding table

Every record has both `eligibility_code` and `actionability_code`; neither is nullable. Exactly one actionability code is selected by the following ordered decision table after eligibility is sealed. `NA` codes are structural or explicit absence only; all reader failures, contradictions, ambiguity, and timing problems are adverse or inconclusive.

| priority | eligibility code | actionability code | deterministic precondition | treatment |
|---:|---|---|---|---|
| 1 | `NOT_ELIGIBLE` | `NA_NOT_ELIGIBLE` | any structural predicate 1–7 false, including absent/nonunique DS, invalid chain, missing required clock, malformed envelope, wrong join, or source unit boundary | excluded from eligible-pair numerator/denominator; counted and weighted separately; never success/failure |
| 2 | `ELIGIBLE` | `NA_NO_TARGET` | structural envelope is explicitly `ABSENT` for target under locked parser, with no target-bearing assertion | reported as NA subtype; excluded only from target-bearing exact-preservation denominator; never a successful no-action |
| 3 | `ELIGIBLE` | `NA_NO_ACTION` | target envelope exists but locked codebook declares no action modality and the unit is outside the actionability construct | reported separately; not route `NOACTION`; no reader missingness hiding here |
| 4 | `ELIGIBLE` | `ACTIVE_EXACT` | target/action/due are exact-linked to DS, compatible polarity/recipient/responsibility, no replacement/conflict, no unresolved required clock, and all required reader outputs are valid | favorable contribution only to exact-preservation functional |
| 5 | `ELIGIBLE` | `ACTIVE_PARTIAL` | target links but at least one required action/due/recipient field is absent or unknown in DS, while no explicit contradiction is established | adverse-compatible for exact preservation; descriptive partial state |
| 6 | `ELIGIBLE` | `SUPERSEDED_EXPLICIT` | DS explicitly documents replacement or superseding plan | adverse; never exact |
| 7 | `ELIGIBLE` | `TARGET_CONTRADICTED` | DS explicitly negates/conflicts with source target/action | adverse |
| 8 | `ELIGIBLE` | `TIMING_UNRESOLVED` | target/action may be present but due interval or required chronology cannot be resolved under locked clocks | adverse-compatible; timing endpoint undefined/adverse per predeclared denominator |
| 9 | `ELIGIBLE` | `DS_UNREADABLE` | DS text/detail exists in source but packet integrity, decoding, or reader access fails | adverse-compatible; no complete-case deletion |
| 10 | `ELIGIBLE` | `NONRESPONSE` | required H1/H2/H3/bridge-reader record absent, malformed, duplicated, or outside domain | adverse-compatible and reported as missingness |
| 11 | `ELIGIBLE` | `DETAIL_AMBIGUOUS` | duplicate/conflicting DS-detail rows prevent unique interpretation after retaining every ordinal | adverse-compatible; no favorable tie-break |
| 12 | `ELIGIBLE` | `BRIDGE_INCONCLUSIVE` | eligible pair exists but locked evidence cannot distinguish rows 4–11, including unresolved panel-unit mapping or H3 reproducibility failure | inconclusive/adverse-compatible; not favorable |

The state machine is:

```text
structural failure                         -> (NOT_ELIGIBLE, NA_NOT_ELIGIBLE)
explicit absent target                     -> (ELIGIBLE, NA_NO_TARGET)
explicit outside-construct no action       -> (ELIGIBLE, NA_NO_ACTION)
exact target/action/due and no conflict    -> (ELIGIBLE, ACTIVE_EXACT)
linked target with missing action/due       -> (ELIGIBLE, ACTIVE_PARTIAL)
explicit replacement                      -> (ELIGIBLE, SUPERSEDED_EXPLICIT)
explicit contradiction                    -> (ELIGIBLE, TARGET_CONTRADICTED)
unresolved required chronology             -> (ELIGIBLE, TIMING_UNRESOLVED)
unreadable/corrupt DS                     -> (ELIGIBLE, DS_UNREADABLE)
missing/malformed reader                   -> (ELIGIBLE, NONRESPONSE)
ambiguous detail                           -> (ELIGIBLE, DETAIL_AMBIGUOUS)
otherwise unresolved                       -> (ELIGIBLE, BRIDGE_INCONCLUSIVE)
```

If multiple adverse conditions coexist, retain all condition flags but select the first applicable code by this fixed precedence; the raw condition vector remains in the manifest. `NA_NO_ACTION` must never be generated from a missing reader, unknown action, disagreement, contradiction, or route `NOACTION`. A workflow fact code of `NOT_PRESENT_IN_AVAILABLE_SOURCES` does not itself create `NA_NO_TARGET` or `NA_NO_ACTION`; it is carried as an unavailable-evidence limitation and any dependent claim remains untestable/adverse-compatible.

Admission clustering, inherited weights, compatible-set joint ratio optimization, zero-denominator `UNDEFINED`, and widest compatible/design/simultaneous interval remain unchanged.
