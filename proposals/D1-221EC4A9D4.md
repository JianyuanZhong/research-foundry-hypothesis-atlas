# Executable deterministic bridge amendment: H1/H2 unit matching, H3 reproducibility, source-availability vector, and actionability coding

## Status, parentage, and strict scope

This is a targeted successor of `[prior hypothesis]`, with the compatible route-predicate and ledger fixtures inherited from `[prior hypothesis]`. It repairs only executable definitions that remained underspecified:

1. H1 and H2 recommendation-unit inventories now have a deterministic, total matcher and a fixed byte-level ordering;
2. H3 is defined as a reproducibility functional over the sealed H1/H2/H3 artifacts, rather than being an informal or optional third label;
3. all eight workflow-fact availability fields use a predeclared distinction between `NOT_PRESENT_IN_AVAILABLE_SOURCES` and `UNKNOWN`; and
4. actionability eligibility, `NA`, adverse, and inconclusive codes are frozen for zero-unit, `NOACTION`, `DEFER`, missing-target, and missing-plan cases.

Nothing below changes the frozen scientific schema, population, chronology, atom, routes, sampling, estimands, workload, or conclusion ceiling. The first-eligible adult, one-admission-per-subject, all-opportunity pulmonary denominator; reciprocal pre-departure radiology chronology; one canonical discharge artifact; unit-specific `G_u = DS_store - R_store,u`; exhaustive `Y,V,H,Z`; exact atom `g=(possible-calendar class, terminal curr_service, workflow class)`; route precedence `AUTO > RECON > TIMING > DEFER > NOACTION`; all-unit adverse routing; positive-probability two-phase whole-admission sampling; finite-population compatible-set inference; no rescue, switching, pooling, borrowing, or post-label reallocation; `A<=900`, `C<=300`; the reconciled 2,370 physician-hour and 84,000 packet-minute ceilings; and the prospective-silent-only, noncausal conclusion ceiling remain binding.

The bridge is still secondary and route-blinded. It tests reproducibility and storage-to-storage documentation actionability only. It does not test clinical appropriateness, truth, contemporaneous awareness, viewing, responsibility, communication, ordering, completion, follow-up, safety, benefit, or causality.

## Frozen H1/H2/H3 objects

### H1: radiology-side unit inventory

For each eligible admission, H1 is the sealed inventory of recommendation units extracted from the eligible reciprocal radiology report/addendum chain, using the inherited pulmonary lexical/semantic codebook and chronology. H1 is not a route label. Each unit has a deterministic record:

`{unit_id, subject_id, hadm_id, source_note_ids, report_charttime, report_storetime, modality_code, target_code, interval_code, possible_calendar_code, target_span, recommendation_span, extraction_status}`.

`unit_id` is not a reviewer-assigned ordinal. It is the lowercase hexadecimal SHA-256 of canonical UTF-8 JSON for the tuple `(subject_id, hadm_id, sorted source_note_ids, report_storetime, target_code, modality_code, interval_code, possible_calendar_code, normalized target span, normalized recommendation span)`, with null represented only by JSON `null`, no omitted keys, and no whitespace. If two otherwise identical units occur, their complete source-note set and span offsets are retained; a duplicate unit is not silently collapsed. The inherited atom and route rules, including all-unit adverse handling, remain unchanged.

### H2: canonical-DS unit inventory

For the sole canonical discharge summary selected by the inherited canonical-DS rule, H2 is the sealed inventory of explicit discharge-plan units using the same unit schema and codebook. H2 extraction is performed without access to H1 unit identifiers, H1 labels, derived routes, atom cells, or challenge assignment. H2 `source_note_ids` contains the canonical discharge note identifier, and `report_*` fields are replaced by the corresponding canonical-DS chart/store times under a fixed field name `ds_*`; this is a representation difference, not a chronology change.

H2 unit identity uses the same canonicalization function and the same normalized target, modality, interval, and calendar vocabularies. H2 may contain zero units. A missing or unreadable canonical DS is represented by the inherited departure state and does not create a synthetic H2 unit.

### H3: deterministic matched bridge and reproducibility functional

H3 is a deterministic, route-blinded bridge object generated only after H1 and H2 artifacts have been independently sealed. H3 contains one row for every H1 unit and every H2 unit, including unmatched rows. It is not an adjudicator consensus and it is not a third opportunity denominator. Each row has:

`{admission_key, h1_unit_id, h2_unit_id, match_state, component_match_vector, exact_match, interval_match, target_match, modality_match, calendar_match, h1_rank, h2_rank}`.

The component match vector is computed from frozen exact equality after canonical normalization: target, modality, interval, and possible-calendar components are each `1`, `0`, or `UNKNOWN` when a component is structurally unresolvable. `exact_match=1` only when all required components are equal and neither unit has an unknown required component. It is `0` when at least one required component is observed and unequal. It is `UNKNOWN` only when no deterministic decision can be made because a required component is unknown or a source artifact is unreadable. No fuzzy similarity, reviewer preference, route, atom, or post-label rule can alter a match.

## Deterministic H1/H2 matching algorithm

The following algorithm is normative and must be implemented identically by compiler and verifier.

1. Normalize all text with Unicode NFC, replace CRLF/CR by LF, trim only leading/trailing ASCII whitespace, collapse internal runs of ASCII whitespace to one space, lowercase only for codebook lookup, and preserve the normalized span offsets used in the sealed artifact. Do not apply locale-specific case folding, stemming, fuzzy matching, or punctuation deletion except where the inherited codebook explicitly declares it.
2. Parse every unit into the fixed schema. Encode missing values as JSON `null`; encode a known unavailable component separately as `UNKNOWN`; never encode either as an empty string.
3. Sort H1 and H2 independently by the tuple `(subject_id numeric, hadm_id numeric, source_storetime UTC, source_note_id bytewise UTF-8, target_span_start integer, target_span_end integer, modality_code bytewise, interval_code bytewise, possible_calendar_code bytewise, canonical_unit_json UTF-8)`. The sorting tuple is total; the final canonical JSON is the tie breaker.
4. Assign `h1_rank` and `h2_rank` as zero-based positions within the admission after that sort. Ranks are reproducibility metadata, never identity.
5. Construct candidate edges only between H1 and H2 units in the same `(subject_id,hadm_id)` with equal required target, modality, interval, and calendar components. Exact edges have lexicographic cost `(0, absolute store-time difference in integer microseconds, absolute chart-time difference, h1_rank, h2_rank)`. Edges with any unknown component are not exact edges; they are retained as unresolved candidate pairs for the compatible-set state.
6. Select a one-to-one exact matching by repeatedly taking the globally smallest cost edge, breaking all ties by `(h1_unit_id bytes, h2_unit_id bytes)`, and removing both endpoints. This greedy rule is the declared matcher; no maximum-cardinality or reviewer-selected alternative may be substituted. Unmatched H1 and H2 units receive explicit `UNMATCHED_H1` and `UNMATCHED_H2` rows. Unknown candidate pairs receive `UNRESOLVED_COMPONENT` rows only when no exact match was selected for either endpoint.
7. Serialize H3 rows sorted by `(admission_key, h1_rank with unmatched sentinel 2^31-1, h2_rank with unmatched sentinel 2^31-1, h1_unit_id bytes, h2_unit_id bytes, match_state)`. Serialize all integers as decimal, timestamps as UTC ISO-8601 with six fractional digits and `Z`, and booleans as JSON booleans.
8. Write canonical JSON with sorted object keys, UTF-8 encoding, no insignificant whitespace, and a terminal newline. Record SHA-256 for H1, H2, H3, and the combined manifest. Any duplicate key, non-total sort, invalid UTF-8, or hash mismatch is a hard computational failure, not an adverse scientific result.

The fixtures must include: empty H1/empty H2; one exact pair; two identical-looking units distinguished by source span; one H1 versus two H2 units; two H1 versus one H2 unit; unequal interval; unknown interval; missing canonical DS; duplicate note IDs; timestamp ties; and bytewise ordering ties. Expected H1 ranks, H2 ranks, H3 rows, and hashes are sealed before real labels.

## H3 reproducibility functional

For admission `i`, let `M_i` be the ordered H3 rows, and let `I_i` indicate that both H1 and H2 artifacts are present and readable. Define the unit-level reproducibility vector from H3, not from an informal comparison of counts:

- `N1_i = number of H1 units`;
- `N2_i = number of H2 units`;
- `Nmatch_i = number of H3 rows with exact_match=1`;
- `Nunmatched1_i = number of H3 rows with match_state=UNMATCHED_H1`;
- `Nunmatched2_i = number of H3 rows with match_state=UNMATCHED_H2`;
- `Nunknown_i = number of H3 rows with match_state=UNRESOLVED_COMPONENT`;
- `coverage1_i = Nmatch_i/N1_i` when `N1_i>0`, otherwise structurally undefined; and
- `coverage2_i = Nmatch_i/N2_i` when `N2_i>0`, otherwise structurally undefined.

The primary bridge functional is the admission-level exact-inventory indicator

`H3_REPRO_i = 1` iff `I_i=1`, `N1_i=N2_i`, every H1 unit has exactly one exact H3 match, every H2 unit has exactly one exact H3 match, `Nunknown_i=0`, and the canonical H3 serialization/hash verifies; otherwise `H3_REPRO_i=0` for an observed, contradictory inventory and `H3_REPRO_i=UNKNOWN` when the artifact is unreadable or an essential component is unresolved. The zero-unit case is not silently treated as reproducible: `N1=N2=0` is `H3_REPRO_i=NA_NO_TARGET_UNITS`, carried separately from the binary functional.

The bridge-level `D_REPRO` is the finite-population, admission-clustered, design-weighted proportion of eligible admissions with `H3_REPRO_i=1`, with the inherited compatible-set interval used when reviewer/reference states are uncertain. H3 is included by definition; it is not an optional descriptive appendix. The primary reported object is `(lower, point, upper, denominator-state vector)`, with no complete-case deletion. An admission with no H1 target units is outside this bridge functional by the explicit eligibility rule below, while remaining in the frozen all-opportunity route denominator.

Supportive results mean only that the stored H1 inventory is reproducibly represented in the canonical DS under the declared codebook and chronology. Adverse results include unmatched units, contradictions, timing/interval changes, and unresolved components. Inconclusive results arise only from predeclared unreadability, unresolved source artifacts, or a confidence interval/compatible set that cannot identify the prespecified gate. None supports a claim about clinical correctness or actual care.

## Eight workflow-fact availability codes

The vector is frozen before labels and is reported for every admission independently of route, atom, H1/H2 result, and actionability label. `PRESENT_IN_AVAILABLE_SOURCES` means that the catalog contains an explicit field or event capable of encoding the fact; it does not mean the fact occurred. `NOT_PRESENT_IN_AVAILABLE_SOURCES` means the complete frozen source audit found no available table/column/event that can encode the fact. `UNKNOWN` means a source capable of encoding it exists but this admission's value cannot be determined because of missing, conflicting, malformed, censored, or structurally unreadable data. `PRESENT` and `UNKNOWN` are never converted to a favorable actionability label.

| Fact code | Workflow fact | Frozen source audit / available proxy | Availability and value coding |
|---|---|---|---|
| `WF1_VIEW` | clinician actually viewed the radiology recommendation | No view/audit-log field in the bound tables; `note/radiology` and `note/discharge` show stored text only | Catalog code `NOT_PRESENT_IN_AVAILABLE_SOURCES`; never infer viewing from `storetime` |
| `WF2_EDIT` | a clinician edited or accepted the recommendation in a workflow interface | No UI edit/version/audit field; note text and `*_detail` are stored artifacts | `NOT_PRESENT_IN_AVAILABLE_SOURCES`; text presence is not an edit |
| `WF3_RESPONSIBILITY` | accountable clinician/team received or owned the task | `hosp/services` and `hosp/transfers` provide service/location context only, not responsibility | Fact code `NOT_PRESENT_IN_AVAILABLE_SOURCES`; service context, if present, is a separate observed covariate and cannot fill responsibility |
| `WF4_COMMUNICATION` | recommendation was communicated to patient, clinician, or downstream team | No communication/read-back field in bound sources | `NOT_PRESENT_IN_AVAILABLE_SOURCES` |
| `WF5_ORDER` | a target-linked follow-up order/referral was placed | POE/order fields are prohibited for this protocol and no validated target-linked action field is in the allowed evidence view | `NOT_PRESENT_IN_AVAILABLE_SOURCES`; no order claim from discharge text |
| `WF6_COMPLETION` | recommended test/procedure was completed | No validated completion/result linkage is available in the frozen bridge sources; later notes cannot prove outside completion | `NOT_PRESENT_IN_AVAILABLE_SOURCES`; absence of a later note is not noncompletion |
| `WF7_FOLLOWUP` | follow-up occurred on time with responsible service | No reliable follow-up attendance/completion/accountability field | `NOT_PRESENT_IN_AVAILABLE_SOURCES` |
| `WF8_OUTCOME` | clinical outcome, safety event, or benefit attributable to the workflow | Bound tables contain neither a causal workflow exposure nor a validated target outcome endpoint | `NOT_PRESENT_IN_AVAILABLE_SOURCES` |

If a future source audit finds an allowed source that can encode one of these facts, its catalog code must be changed only by a new preregistered protocol version. For the current frozen catalog, all eight are `NOT_PRESENT_IN_AVAILABLE_SOURCES` at the catalog level. A row-level extraction failure for an otherwise available fact would instead be `UNKNOWN`; it must not be relabeled as `NOT_PRESENT`. MIMIC death fields (`deathtime`, `hospital_expire_flag`) remain available descriptive admission variables but do not establish any of WF1--WF8 and do not lower the evidence ceiling.

## Actionability eligibility and complete coding table

The actionability/documentation bridge is label- and route-blinded. Eligibility is determined from sealed structural artifacts before any panel sees a route, atom, challenge assignment, or H3 result. It does not remove the admission from the inherited all-opportunity denominator.

A **target unit exists** exactly when the sealed H1 inventory contains at least one valid pulmonary recommendation unit. A **canonical DS exists** exactly when the inherited canonical-DS selector returns one readable note with a valid `(subject_id,hadm_id,note_id)` key and usable text; no substitute note is chosen. A target-linked bridge field is **eligible** only if both conditions hold. The panel may then label each eligible H1 unit and its deterministic H3 match/unmatched state. Eligibility is not conditional on route: a `DEFER` admission with a target unit and canonical DS is eligible; a `NOACTION` route with a target unit and canonical DS is also eligible. This prevents route-dependent missingness.

| Structural situation, evaluated pre-label | Bridge eligibility | Required code | Interpretation |
|---|---:|---|---|
| H1 has zero units and route is `NOACTION` | No | `NA_NO_TARGET_UNITS` | Structural no-target case; not a favorable actionability result and not adverse nonresponse |
| H1 has zero units and route is any other route due to a failed/contradictory inventory | No | `NA_NO_TARGET_UNITS` plus inherited route/data-error flag | Preserve the adverse route/data-quality state; do not manufacture a unit |
| H1 has one or more units but canonical DS is absent, unreadable, or nonunique under the frozen selector | No | `NA_NO_CANONICAL_DS` | Bridge cannot compare storage artifacts; route remains analyzed under the primary protocol |
| H1 has units and canonical DS exists; route is `NOACTION` | Yes | `ELIGIBLE_ROUTE_NOACTION` | Label units; `NOACTION` does not suppress target-linked review |
| H1 has units and canonical DS exists; route is `DEFER` | Yes | `ELIGIBLE_ROUTE_DEFER` | Label units; `DEFER` is not treated as missing and may yield adverse/inconclusive unit states |
| H1 has units and canonical DS exists; route is `AUTO`, `RECON`, or `TIMING` | Yes | `ELIGIBLE_ROUTE_OTHER` | Label units using the same blinded rules |
| H1/H2 artifact exists but a required component is unknown | Yes for structural review | `ELIGIBLE_UNRESOLVED_COMPONENT` | Label as `INCONCLUSIVE_UNRESOLVED`, not NA and not supportive |
| Eligible unit has an explicit matching plan with exact required target/interval/modality | Yes | `SUPPORTIVE_EXACT_PROPAGATION` | Stored-text agreement only |
| Eligible unit is explicitly present but target, interval, modality, or timing is contradictory/replaced | Yes | `ADVERSE_CONTRADICTION` or `ADVERSE_REPLACEMENT` | Adverse documentation mismatch under the frozen codebook |
| Eligible H1 unit has no corresponding H2 unit after deterministic matching | Yes | `ADVERSE_NONRESPONSE` | Missing canonical-DS representation is adverse only because a target and readable DS made the comparison eligible |
| Eligible H1/H2 pair has an interval/calendar or modality mismatch | Yes | `ADVERSE_TIMING` or `ADVERSE_ATTRIBUTE_MISMATCH` | Do not collapse into exact match |
| Eligible unit text is unreadable/ambiguous after the frozen parser, or source spans cannot be resolved | Yes | `INCONCLUSIVE_UNREADABLE` or `INCONCLUSIVE_AMBIGUOUS` | Not adverse and not supportive; retained in compatible set |
| H3 has unresolved required components or bridge readers cannot determine the frozen state | Yes | `INCONCLUSIVE_UNRESOLVED` | Retain compatible states; no complete-case deletion |
| Panel packet is not delivered because of a ledger/technical failure | No valid label | `INCONCLUSIVE_PACKET_FAILURE` | Hard protocol execution failure for that packet; never recode as NA or supportive |

The codes are mutually exclusive in the following precedence: structural `NA` (`NA_NO_TARGET_UNITS`, then `NA_NO_CANONICAL_DS`) > technical packet failure > inconclusive > adverse subtype > supportive subtype. This precedence applies only within the bridge coding field and cannot rewrite the inherited route precedence. `NA_NO_ACTION` is not used as a bridge label when H1 contains a target unit; the route value `NOACTION` is retained separately and the bridge uses `ELIGIBLE_ROUTE_NOACTION`. Thus zero-unit and true no-action cases are never conflated.

For an eligible admission, the admission-level actionability indicator is all-unit adverse: it is adverse if any eligible unit is adverse or unresolved under the inherited conservative rule; it is supportive only if every eligible unit is supportive exact propagation and no unit is unknown/inconclusive; it is inconclusive if no adverse unit is established but at least one unit is inconclusive. For an ineligible admission, the actionability indicator is `NA` and is excluded from the bridge numerator but retained in the predeclared eligibility denominator and ledger. These rules do not alter the primary route estimand or the <=900-admission allocation.

## Analysis, falsification, and verification obligations

The compiler must verify the H1/H2/H3 fixtures, source-availability manifest, byte-level hashes, route-blind eligibility, and actionability truth table before releasing any real label. The verifier must independently recompute H3 from sealed H1/H2 artifacts and compare serialized bytes and hashes. It must test that: (a) permutation of input row order leaves hashes unchanged; (b) changing one target, interval, modality, source span, or timestamp changes the expected match state; (c) adding an H2 unit creates an unmatched adverse row rather than changing an existing match; (d) H3 is included in `D_REPRO`; (e) zero-unit and `NOACTION` cases remain distinct; (f) `DEFER` with a target and DS remains eligible; (g) source absence yields `NOT_PRESENT_IN_AVAILABLE_SOURCES`, while row-level missingness in an available source yields `UNKNOWN`; and (h) no unavailable workflow fact is silently inferred from a stored note.

The primary estimands, sampling weights, compatible-set bounds, confidence procedures, ledger, and all inherited route and atom gates are unchanged. No post-label choice of matcher, eligibility, threshold, source, route, challenge, or conclusion is allowed. Supportive, adverse, and inconclusive results must be reported separately with the exact computed files that support them. A passing retrospective bridge can nominate only a prospective **silent** validation. Stronger conclusions about action, appropriateness, safety, clinical benefit, workflow responsibility, completion, follow-up, or causality require new prospective workflow/audit-log, expert clinical adjudication, target-linked order/result, and outcome data.
