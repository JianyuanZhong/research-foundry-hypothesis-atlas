# Reconstructable eICU test of persistent respiratory chart state after exact care-plan labels

## Status, parentage, and substantive repair

This is a targeted, compiler-ready child of assessed-valid `[prior hypothesis]` and `[prior hypothesis]`. It preserves the Lead-frozen scientific object: the 540 person-landmark / 443-stay / 74-hospital eICU cohort; the first qualifying stay and inherited exclusions; the exact two literal labels; decision time D; the five inherited landmarks; the descriptive, noncausal estimand; and the requirement that the respiratory endpoint be independently charted rather than copied from the care-plan label.

The substantive change is not a new cohort or estimand. It removes the reconstruction/artifact bottleneck by making the source-wide, outcome-blinded parser, cohort construction, row-level digest, endpoint computation, and feasibility gates executable from the current read-only files. No parent CSV, cached label list, or prior generated artifact is presumed to exist. Every intermediate is regenerated, content-addressed, and checked against the frozen cohort counts before any outcome comparison is permitted. The endpoint is deliberately conservative: it is a structured-chart respiratory patient-state trajectory, not extubation, SBT completion, delivered ventilator settings, clinical benefit, harm, quality, or causal treatment effect.

## Question and claim boundaries

The unresolved hypothesis is: among the frozen labelled person-landmarks, after accounting for pre-D respiratory state and documentation opportunity, the exact label received at D contains reproducible incremental information about a subsequent persistent respiratory patient-state trajectory, and this information is observable in hospitals held out from fitting.

The strongest parent-supported claims are limited to the literal labels' sparsity and hospital concentration, instability of previously examined setting/sedation correlates, and inability to ascertain durable liberation with the available independent markers. Those findings do **not** establish what bedside teams intended, what was delivered, whether an extubation evaluation occurred, or whether either label benefits patients. The experiment tests only a descriptive association/predictive increment for a newly reconstructed structured endpoint. A positive result cannot be translated into clinical intent, efficacy, safety, quality, or transportability outside this snapshot.

## Endpoint and estimand

For each person-landmark, define a post-D landmark state from the frozen parser in a prespecified observation window and require persistence across two separated observation blocks. The exact windows, component thresholds, and missingness rules are serialized in `spec/frozen_spec.json` and are inherited from the parent endpoint definition; they cannot be tuned after label membership is known. The compiler emits, for every landmark and every component, the raw rows used, first/last offsets, observation counts, parsed values, and a reason code for `observed`, `not_observed`, `invalid`, `competing_exit`, or `out_of_stay`.

The primary endpoint is the parent-defined multi-domain persistent respiratory patient-state outcome (improved / not improved, or the parent-defined ordinal state if that is what the frozen spec contains), requiring the same direction of change from the pre-D baseline to the post-D state in the prespecified domains and persistence in both post-D blocks. A single setting, a copied care-plan value, or a missing observation cannot satisfy persistence. The endpoint is computed only when the required baseline and follow-up observations meet the frozen observation rule; otherwise the primary analysis records an explicit missing endpoint rather than coding it as failure or success.

Report three distinct denominators: (a) all 540 person-landmarks; (b) endpoint-observed landmarks; and (c) landmarks with each component observed in each block. Missingness is itself tabulated by label, hospital, landmark, and exit status. The primary estimand is the descriptive difference in endpoint prevalence (and its uncertainty) between the two exact labels among endpoint-observed frozen landmarks, adjusted for the pre-D state/documentation covariates specified by the parent, with a complete-case/observed-endpoint interpretation. A secondary, clearly labelled observation-process analysis describes endpoint observability and competing exits; it must not be presented as an outcome effect.

Competing exits are not silently censored. For each window, stop follow-up at the earliest valid unit discharge offset, death/discharge status as available in `patient.csv.gz`, transfer/other discharge, or another parent-specified exit. Emit exit type and exit offset. The primary analysis reports cause-specific observed endpoint summaries and a competing-exit sensitivity that treats each exit as its own mutually exclusive state; inverse-probability-of-observation weighting is optional only if positivity and model diagnostics pass, and it cannot recover unrecorded bedside events.

## Reconstruction algorithm and fail-closed gates

A single script must run in this order: verify snapshot/source SHA-256 and headers; load and validate `frozen_spec.json`; source-wide-freeze parser inventories; stream-build labels; apply inherited cohort predicates; write canonical cohort rows; compute digest; only then parse endpoint observations and predictors; run analysis; write a manifest. Canonical serialization is UTF-8 JSON Lines with fixed column order, normalized missing token, numeric formatting, and sorted key `(uniquepid, patientunitstayid, D, landmark_offset, label_order)`.

The row-level cohort digest is SHA-256 over one canonical line per person-landmark containing at least `uniquepid`, `patienthealthsystemstayid`, `patientunitstayid`, `hospitalid`, exact `label`, `D`, landmark identifier/offset, eligibility/exclusion bit vector, and source row identifiers. The manifest records row count, unique stay/person/hospital counts, per-label counts, per-landmark counts, parser/spec hashes, source hashes, software/runtime versions, and all rejection counts. The expected counts are hard gates: any mismatch from 540/443/74, any missing D/landmark, duplicate canonical key, unexpected label, nonmonotone time, invalid offset, or failed source/header/hash check aborts before endpoint analysis.

Additional feasibility gates are mandatory and report actual counts: every endpoint component must have at least one parsed source row in the complete snapshot; every labelled row must receive a reason code; each label must have endpoint-observed and not-observed counts; each hospital must have its label/endpoint cell counts exposed; every held-out test fold must contain both labels unless the held-out claim is explicitly marked infeasible. If a required component is absent, if all endpoints are missing, if a component has no observations in either post-D block, or if a competing-exit rule cannot be evaluated from available fields, the run returns `INCONCLUSIVE_INSTRUMENTATION` and does not manufacture an endpoint. If the parent expected count cannot be reproduced, it returns `REJECTED_RECONSTRUCTION` and no scientific comparison is released.

## Falsification and interpretation

The hypothesis is adverse if the label-plus-pre-D-state model has no reproducible incremental association in held-out hospitals, if the sign reverses materially across held-out folds, if the endpoint is largely unobserved or hospital-specific, or if label-only signal disappears after documentation opportunity/state adjustment. It is also adverse if parser perturbations that were fixed *before* label comparison (for example, alternate valid numeric parsing specified in the manifest) show that the result is an artifact of one fragile representation.

A supportive result requires all gates to pass, endpoint observation to be adequate and not concentrated in one hospital, a directionally concordant held-out estimate under the prespecified uncertainty criterion, and no material degradation under the competing-exit/missingness sensitivity. It supports only reproducible incremental information in the structured chart construct.

An inconclusive result includes failure to reconstruct the exact 540/443/74 cohort, absent/insufficient endpoint observations, failed positivity for grouped validation, or wide/unstable estimates. It is a useful feasibility finding, not evidence for or against bedside practice. Neither supportive nor adverse computation establishes that a label denotes intent, an extubation evaluation, SBT, liberation, delivered ventilator settings, patient benefit/harm, care quality, or causality. Those claims require expert adjudication against bedside records and, for benefit or harm, a separate design (ideally prospective or carefully causal with treatment and confounding data).
