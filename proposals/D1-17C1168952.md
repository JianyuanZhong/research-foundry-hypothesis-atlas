# Route-blinded documentation reproducibility versus explicit actionability bridge

## Status, inheritance, and the targeted repair

This is a targeted child of `[prior hypothesis]`. It repairs one remaining documentation-to-actionability specification gap; it is not a new population, route model, endpoint, or causal study.

The following parent schema is frozen verbatim and takes precedence over this amendment: the first-eligible adult, one-admission-per-subject, all-opportunity pulmonary population; the reciprocal pre-departure radiology report/addendum chronology; the single inherited canonical discharge (`DS`) artifact; recommendation-unit construction; unit-specific opportunity clocks `G_u = DS_store - R_store,u`; exhaustive `Y,V,H,Z` states; atom `g=(possible-calendar class, terminal curr_service, workflow class)`; `AUTO > RECON > TIMING > DEFER > NOACTION` route precedence; all-unit adverse admission routing; safety-sentinel census; positive-probability two-phase whole-admission sampling; split-view and sealed-panel design; held-out probability audit; compatible-set/finite-population inference; no switching, pooling, rescue, borrowing, consensus rescue, or post-label allocation; the inherited challenge and physician/packet workload ceilings; and the prospective-silent-only conclusion ceiling. No rule below may alter any of those objects.

The unresolved claim is narrower. Reproducible stored text does not, by itself, establish that an explicit recommendation is ready to be acted on by a receiving workflow. The added bridge asks whether an already eligible recommendation unit has (a) reproducible, target-linked text in the canonical DS and (b) a separately adjudicated set of explicit actionability fields. It also reports which workflow/outcome facts cannot be observed in the available MIMIC snapshot. It does not infer that anyone saw, accepted, communicated, ordered, completed, or benefited from the recommendation.

The strongest supported retrospective claim remains only a source-to-source documentation claim: under the frozen route-blinded protocol, a unit's stored radiology proposition can be reproduced in the stored DS. The new untested claim is that the reproduced proposition contains enough explicit, unambiguous information for a specified prospective recipient to act without a clinician reconciliation step. MIMIC cannot establish that stronger claim; it can only measure a pre-registered text readiness proxy and expose missing evidence.

## Fixed units, clocks, and pre-label order

All inherited population and unit labels are computed before any H-panel sees a downstream text. The inherited radiology unit `u` retains its source `note_id`, `(subject_id,hadm_id)`, report/addendum identity, `R_store,u`, and frozen target fields. The canonical `DS` retains its source `note_id`, `DS_store`, and inherited selection provenance. A detail row is not a unit and cannot alter `R_store,u` or `DS_store`.

For each eligible unit, define a canonical source tuple `K_u` using the inherited unit fields exactly as sealed by the parent. The bridge does not add a new clinical atom. The only bridge keys are:

`A_u = (subject_id, hadm_id, unit_id, target_class, modality_class, interval_class)` from the sealed H1 unit inventory;

`B_j = (subject_id, hadm_id, ds_note_id, assertion_id, target_class, modality_class, interval_class)` from an independent H2 discharge assertion inventory.

`unit_id` and `assertion_id` are local manifest identifiers, not clinical variables. They are assigned after source extraction by deterministic row ordering and are never chosen by route or by an H reader.

All timestamps are parsed as UTC-naive MIMIC timestamps after a fixed parser; unparsable timestamps are `MALFORMED_TIME` and fail closed. Equality uses exact parsed timestamp equality. Every interval uses half-open boundaries `[start,end)`. The inherited reciprocal chronology and `G_u` remain authoritative. The bridge's label order is fixed: source audit -> H1 unit inventory -> H2 assertion inventory -> canonical matching -> H3 documentation label -> H4 actionability label -> route join and inference. No label, threshold, or workload count can feed backward into any earlier stage.

## Deterministic text normalization and matcher

Raw text is retained byte-for-byte in a sealed payload, but matching uses a separately recorded canonical serialization. Normalize Unicode to NFC; convert CRLF/CR to LF; strip only trailing spaces on each line; preserve all internal characters and line order; represent missing text as `NA_TEXT`, not an empty string. Detail rows are serialized as `field_name`, `field_ordinal`, `field_value` sorted by integer `field_ordinal`, then `field_name`, then the raw field value. Duplicate ordinals or duplicate `(field_name,field_ordinal)` pairs are retained and flagged, never deduplicated.

H1 and H2 use separate roster-disjoint panels. H1 sees the eligible radiology payload and context permitted by the inherited radiology panel but never DS text. It writes zero or more source units with a fixed codebook. H2 sees DS text and permitted admission/departure context but never the source radiology payload or H1 output. It writes zero or more explicit discharge assertions. H3 receives only sealed serialized H1 and H2 inventories and performs no clinical relabeling.

A candidate pair `(u,j)` is eligible for matching only if `(subject_id,hadm_id)` agree, the target class agrees exactly, modality class agrees exactly, and interval class agrees exactly. H3 computes a Cartesian product in lexicographic order `(subject_id,hadm_id,unit_id,assertion_id)` and applies this deterministic one-to-one matcher: sort eligible pairs by `(unit_id, assertion_id)`; take the first pair whose two IDs are both unused; continue until no pair remains. This greedy matcher is a reproducibility device, not an optimal semantic matcher. If any unit or assertion has more than one eligible partner before assignment, the affected unit is `MATCH_AMBIGUOUS`; it is not silently assigned. If an inventory has duplicate IDs, cross-admission IDs, malformed tuples, or a noncanonical serialization/hash, the affected admission is `BRIDGE_INTEGRITY_FAILURE` and all its bridge fields are adverse/inconclusive as specified below. The manifest records all candidate pairs, selected pairs, unmatched IDs, ambiguity, ordering, and SHA-256 of each serialized inventory.

H3 then compares the selected pair field by field. Exact target and modality agreement are required by matching; exact interval agreement is required by matching. A field is `PRESENT` only when H1 and H2 both provide a non-NA value and the canonical values are equal. A field is `ABSENT_IN_DS` when H1 provides it but H2 has no corresponding explicit value. `CONTRADICTORY` means both are present but unequal. `SOURCE_UNKNOWN` means H1 could not establish the field; `DS_UNKNOWN` means H2 could not establish it. Thus `D_REPRO=1` requires a unique match and equality for all inherited required recommendation fields, not merely shared target words. H3's fixed output includes `D_REPRO`, per-field status, and unmatched/ambiguous indicators. `D_REPRO` is not a clinical correctness label.

## Explicit actionability contract

H4 is a fresh, route-blinded, recommendation-blinded-to-route panel. It sees only the canonical DS assertion payload and a minimal departure context manifest (`hadm_id`, `DS_store`, inherited terminal service and permitted departure state), not the source radiology text, H1/H3 labels, route, atom, sampling stratum, or eventual outcomes. It codes explicit text properties, not appropriateness. H4 must not infer a modality, interval, recipient, or responsibility from clinical plausibility. An absent explicit field is absent, not implied.

For every matched or unmatched H2 assertion, H4 emits the following fixed fields: `TARGET_EXPLICIT`, `MODALITY_EXPLICIT`, `INTERVAL_EXPLICIT`, `RECIPIENT_OR_SERVICE_EXPLICIT`, `ACTION_VERB_EXPLICIT`, and `DESTINATION_OR_HANDOFF_EXPLICIT`. Each is `YES`, `NO`, `UNCLEAR`, or `NA_NOT_APPLICABLE`, with a verbatim evidence span offset in the normalized DS serialization when `YES` or `UNCLEAR`. A field is `YES` only when the text explicitly states it; `NO` means the assertion is present but the field is not stated; `UNCLEAR` means text is present but its referent or value cannot be uniquely determined. `NA_NOT_APPLICABLE` is allowed only for `RECIPIENT_OR_SERVICE_EXPLICIT` or `DESTINATION_OR_HANDOFF_EXPLICIT` when the codebook's predeclared assertion type genuinely requires no such field; it is never allowed for target, modality, interval, or action verb in an actionable recommendation.

The bridge's text-only readiness label is deterministic after H4 seals:

| State | Required condition | Interpretation |
|---|---|---|
| `ACTIONABLE_TEXT_READY` | assertion exists; target, modality, interval, and action verb are all `YES`; recipient/service and destination/handoff are `YES` or a predeclared applicable `NA`; no field is `UNCLEAR`; no contradiction or superseding ambiguity | Explicit text appears sufficiently specified for a predefined handoff contract |
| `ACTIONABLE_TEXT_RECONCILIATION` | assertion exists and target is `YES`, but any required field is `NO` or `UNCLEAR`, or a superseding/competing plan is unresolved | Text exists but requires human reconciliation |
| `ACTIONABLE_TEXT_CONTRADICTORY` | two explicit DS assertions for the same matched key disagree, or the same assertion contains unresolved mutually exclusive instructions | Adverse; never eligible for AUTO |
| `ACTIONABLE_TEXT_UNREADABLE` | DS text exists but normalization, section extraction, or evidence span validation fails | Adverse/inconclusive; fail closed |
| `ACTIONABLE_TEXT_NO_ASSERTION` | no explicit H2 assertion can be generated for a source unit | Documentation omission; adverse for documentation, not proof of absent care |
| `ACTIONABLE_TEXT_UNKNOWN` | H4 nonresponse, panel seal failure, or record-level ambiguity prevents coding | Adverse in primary bounds and separately reported |
| `ACTIONABLE_TEXT_NA_NO_TARGET` | no frozen H1 target unit exists in that admission | Structural NA only in a control denominator, never a failure of an eligible unit |
| `ACTIONABLE_TEXT_NA_NO_ACTION` | the inherited unit is explicitly `NOACTION` under the parent route vocabulary | Structural NA for actionability, retained separately from adverse states |

A zero-unit admission, a route `DEFER`, missing DS, death at discharge, post-discharge-only text, or unavailable workflow record does not become `ACTIONABLE_TEXT_READY`. For the inherited eligible unit, missing DS or no H2 assertion is `NO_ASSERTION`/`UNKNOWN` according to the fixed table, not NA. `DEFER` remains the inherited route and is not evidence that the text is actionable or inactionable. All-unit admission routing remains exactly the parent rule: any adverse or unresolved decision-relevant unit controls the admission.

The bridge reports two distinct summaries. `D_REPRO` is the stored-text reproducibility functional. `A_READY` is the proportion of eligible units with `ACTIONABLE_TEXT_READY` among units with an observable DS assertion, with a second all-eligible denominator that includes `NO_ASSERTION` and `UNKNOWN` adversely. No ratio with a zero denominator is set to zero: it is `UNDEFINED_ZERO_DENOMINATOR` and the corresponding route cell cannot pass. The joint four-state table (`D_REPRO` by actionability state) is primary for the bridge; marginal agreement must not conceal a reproducible-but-under-specified or nonreproducible-but-explicit case.

## Evidence availability and missing workflow/outcome facts

Before labels, the source audit declares eight facts and their allowed evidence sources: `DS_STORED`, `RADIOLOGY_STORED`, `TARGET_LINK_STORED`, `RECIPIENT_STORED`, `ORDER_OR_REFERRAL_STORED`, `ACKNOWLEDGMENT_OR_VIEW_STORED`, `COMPLETION_RESULT_STORED`, and `CLINICAL_OUTCOME_STORED`. The first three may be observed from the bound radiology/discharge note tables and exact key/time joins. `RECIPIENT_STORED` is text-only when explicit in DS. `ORDER_OR_REFERRAL_STORED`, acknowledgment/view, completion/result, and clinical outcome are `NOT_PRESENT_IN_AVAILABLE_SOURCES` because the protocol admits no corresponding usable source artifact. The source-audit manifest freezes this declaration before labels.

For each admission, each fact receives exactly one of `OBSERVED`, `OBSERVED_ABSENT_IN_ADMITTED_ARTIFACT`, `RECORD_UNKNOWN`, `NOT_PRESENT_IN_AVAILABLE_SOURCES`, or `NOT_APPLICABLE`. `NOT_PRESENT_IN_AVAILABLE_SOURCES` is a dataset-level ceiling, not evidence that the event did not happen. `RECORD_UNKNOWN` is used when an admissible source exists but the row/text is missing, malformed, contradictory, or inaccessible for that record. `OBSERVED_ABSENT_IN_ADMITTED_ARTIFACT` means the admissible artifact is present and contains no explicit assertion of that fact; it is not equivalent to absence of care. `NOT_APPLICABLE` is reserved for a predeclared structural case such as no eligible unit. Death, discharge location, and `deathtime`/`dod` are reported as context or censoring flags only and never upgraded to an outcome or completion state.

The unavailable-fact vector is reported separately from every bridge numerator and denominator. No imputation, proxy upgrade, narrative assumption, or post hoc chart search is permitted. Consequently, a supportive bridge result can nominate only a prospective silent implementation check; it cannot support delivery, acknowledgment, follow-up, safety, benefit, or causality. An adverse result blocks that nomination for the affected atom/route cell. An inconclusive result, including a positive but sparse or unavailable-evidence cell, remains inconclusive.

## Controls and falsification

Controls are fixed before any H labels. (1) **Route-reveal control:** a duplicate payload is shown with route/atom metadata to a separate control roster; materially different rates from the masked panel indicate route leakage. (2) **Route-swap control:** route labels are permuted within admission after all payload seals; actionability labels must not change, and any change invalidates the bridge. (3) **Target-permutation control:** H1 source-unit target tuples are permuted across admissions with the same observable text-length and service strata; matching/actionability must fall to the predeclared null level, otherwise lexical or admission leakage is present. (4) **Negative semantic control:** a fixed non-recommendation DS span, selected by a pre-label hash rule from the same note, is processed by H4; it must not be classified `ACTIONABLE_TEXT_READY`. (5) **Serialization control:** reorder source rows and detail rows, rerun extraction, and require byte-identical manifests and state tables. (6) **Duplicate control:** duplicate a note row in a fixture; the result must be `BRIDGE_INTEGRITY_FAILURE`, never a favorable extra match. (7) **Unavailable-evidence control:** inject synthetic order/view/completion/outcome rows in a private fixture; the production result must remain `NOT_PRESENT_IN_AVAILABLE_SOURCES` and must not accidentally interpret proxies as those facts.

The verifier checks these computational properties, exact key/time joins, no leakage across panel rosters, state-table mutual exclusivity/exhaustiveness, deterministic matching, and that every reported bridge conclusion is linked to the sealed output files. It cannot verify semantic correctness of clinical text, appropriateness, or whether the proposed fields would actually permit a clinician to act; those require independent clinical adjudication and prospective workflow testing.

## Sampling, finite workload, and analysis

The bridge is nested inside the parent's already frozen whole-admission challenge and uses exactly the inherited positive-probability sample, inclusion probabilities, stratification, held-out audit allocation, distinct-admission ceiling `A <= 900`, challenge ceiling `C <= 300`, and inherited physician-hour/packet-minute ledger. It may not add admissions, oversample after seeing bridge labels, or use a separate convenience sample. Every sampled admission contributes all eligible units to the relevant panel views as required by the parent. Bridge H4 rows are appended to the inherited packet ledger before labels; the pre-label ledger must prove that worst-case inherited charge plus bridge charge remains within every inherited hard limit. If it does not, the bridge is not run and the cell is `INCONCLUSIVE_WORKLOAD_OVERFLOW`, never selectively reduced.

The primary bridge estimands are finite-population, design-weighted proportions and joint state totals over all frozen eligible units, with admission-level adverse routing unchanged. Report Horvitz-Thompson totals and Hájek proportions with the parent's prescribed replicate variance and compatible-set bounds. For each atom-route cell report: number of eligible admissions/units; weighted `D_REPRO`; weighted `ACTIONABLE_TEXT_READY`; weighted `ACTIONABLE_TEXT_RECONCILIATION`; weighted `CONTRADICTORY`, `NO_ASSERTION`, and `UNKNOWN`; the full `D_REPRO × actionability` table; and the unavailable-evidence vector. Use no pooled cells, shrinkage, imputation, or favorable selection. Exact zero-event or zero-denominator cases follow the parent's finite-population rules and are reported as structural or undefined rather than hidden.

The bridge gate is jointly fail-closed: no cell may be nominated for prospective silent validation unless the inherited route-purity, capture, workload, chronology, seal, sampling, and uncertainty gates pass; the bridge has positive eligible and observable denominators; no integrity/leakage control fails; all required actionability fields have a predeclared codebook and validated spans; and the lower compatible-set bound for the all-eligible `ACTIONABLE_TEXT_READY` proportion exceeds the pre-registered operational floor while the adverse all-unit route bound remains within the inherited route gate. The floor is a workflow-governance criterion, not a safety threshold and must be frozen before labels; if governance does not supply it, the result is `INCONCLUSIVE_THRESHOLD_NOT_REGISTERED` and no nomination is made.

## Interpretation and evidence ceiling

Supportive results mean only that the stored radiology-to-DS documentation relationship is reproducible and that, among the specified MIMIC-observable text assertions, explicit fields often meet the frozen text contract. They justify at most a prospective silent, route-blinded workflow feasibility and usability study with actual recipients and event capture.

Adverse results mean the bridge is not reliable for that atom/route: missing or contradictory text, low compatible-set readiness, control failure, or unavailable evidence prevents a silent nomination. A reproducible but under-specified result is specifically adverse to automatic propagation and may support only clinician reconciliation in a future governed study. A nonreproducible but explicit DS assertion does not rescue documentation reproducibility. Inconclusive results include sparse cells, zero denominators, nonresponse, workload overflow, seal/chronology failure, threshold nonregistration, and evidence modalities absent from MIMIC.

Neither result establishes clinical appropriateness, actual handoff, recipient awareness, responsibility, order placement, imaging completion, follow-up, patient safety, utility, benefit, or causal effects. Those claims require clinical expert review of the full record and images plus a prospective silent/live workflow study with timestamps for exposure, acknowledgment, action, completion, and outcomes. The experiment therefore remains strictly prospective-silent-only and noncausal.

## What changed and what remains uncertain

Compared with the parent, this child adds an executable bridge rather than another route or adjudication vote: exact H1/H2 unit and assertion identities; fixed lexicographic Cartesian matching and serialization; a mutually exclusive actionability state table with explicit NA, adverse, and inconclusive precedence; an eight-fact source-availability dictionary distinguishing dataset-level unavailability from record-level unknown; route-blinded H4 field extraction; fixed controls; and a finite workload/zero-denominator contract. The population, times, keys, atom, routes, sampling, estimands, all-unit worst-case rule, and conclusion ceiling are unchanged. Remaining uncertainty is substantive and cannot be repaired retrospectively: the stored MIMIC snapshot lacks workflow exposure and clinical outcomes, text adjudication is not clinical truth, and explicit text readiness may not translate into safe action in a real service.
