# Episode 31 — Does first-diagnosis ORDER of a co-present cardiometabolic pair (E11/I10) predict downstream diagnosis accrual beyond co-presence, and is any such signal distinguishable from care-intensity/ascertainment?

## Unresolved question and clinical importance
Multimorbidity tools (comorbidity counts, CKM stage, multimorbidity indices) render disease burden as a **set/count**. Clinicians reason about **sequence** — diabetes-then-hypertension vs hypertension-then-diabetes. [K1] reports that the direction of a cardiometabolic↔internalising multimorbidity trajectory predicts 10-year cardiovascular/renal risk, so order is not obviously inert. But [K1] does not test whether pairwise order beats a co-presence/count baseline and does not adjudicate the obvious artifact: inpatient ICD-10 codes are co-recorded when a patient is jointly investigated/coded, so apparent "order" may reflect *which condition was coded first in a shared encounter* [K3 bounds a nonspecific shared-burden alternative; K2 documents hub/co-occurrence structure as a competing explanation]. Resolving this decides whether sequence belongs in multimorbidity stratification or whether the set/count view is adequate — a useful negative either way.

## Leading claim vs strongest rivals; discriminating observation
- **Leading claim (A):** among people with a fixed co-present pair, first-diagnosis ORDER adds out-of-sample information about downstream ICD-10 accrual (Δ_order ≠ 0) beyond co-presence/count, age, interval and co-coding.
- **Rival B1 (strongest; care-coupling/ascertainment):** "order" reflects joint coding/testing intensity and overall care/documentation volume, not biology. **This is the rival this episode newly operationalises.**
- **Rival B2 (shared continuum):** order is a projection of one graded burden process; the useful signal is stage/count [K3].
- **Rival B3 (network/hub):** apparent pairwise structure is hub centrality, not ordering [K2].

**Discriminating observations.**
1. **Documentation-breadth / care-intensity discriminator (NEW this episode).** Define per participant a records-only *care-intensity proxy* = number of distinct 3-character ICD-10 blocks present ("documentation breadth"); separately, number of dated blocks. Pre-register: B1 predicts the ORDER feature's held-out gain is largely explained by / concentrated in high-breadth participants; A predicts Δ_order persists after conditioning on documentation breadth and in low/mid-breadth strata. **NEGATIVE-CONTROL outcome:** if Δ_order predicts a generic breadth/records-volume outcome (total dated blocks accrued after index) as strongly as it predicts the disease-specific comorbidity-accrual outcome, that is *adverse* evidence for B1.
2. **Long-interval subgroup (≥365 days apart),** where same-encounter co-coding is weakest; B1 predicts Δ_order→≈0, A predicts persistence.
3. **Co-coding-intensity gradient:** B1 predicts Δ_order concentrated in the top co-coding bin.
4. **Retained from parent:** E11/E78 screening-coupling control pair (mechanically co-tested lipid disorder) vs the biological E11/I10 pair; same-day tie-exclusion category; within-stratum permutation null.

- **Exposure:** binary ORDER = (E11 first-occurrence date < I10 date) among discordant pairs.
- **Covariates:** `n_31_0_0` (sex), `n_21003_0_0` (age/ethnic field id as recorded), inter-diagnosis interval (days), pre-index coded count (distinct ICD-10 blocks dated on/before the earlier date), same-encounter co-coding intensity (distinct blocks sharing the earlier date), **and the NEW documentation-breadth proxy.**
- **Outcome:** downstream ICD-10 accrual = number of distinct 3-char blocks with first-occurrence date strictly AFTER the later pair member. Secondary: binary "≥1 new cardiometabolic block (I00–I99 or E00–E90) after index." **Negative-control outcome:** total accrued dated blocks (generic records volume).
- **Primary estimand Δ_order:** out-of-sample improvement (ΔAUC + Δ on a proper scoring rule) of [set/count + age + sex + interval + co-coding (+ documentation breadth)] vs the same model **plus** the ORDER feature, by participant-level cross-validation (split fixed by seed). Secondary: within-stratum permutation null (strata = age-decile × sex × pre-index coded count).

## Baseline vs substantive alternative (method exploration, same question)
- **Baseline (simple, interpretable):** the set/count + covariates model with ORDER as a single term — the transparent comparison the set/count literature already uses.
- **Learned alternative (substantive):** a **diagnosis-event sequence model** consuming the ordered list of dated ICD-10 blocks before the later pair member. Revelatory content the baseline loses: whether information sits in the *position of the pair within a longer within-person coding sequence*, not merely which of the two came first. If the learned model's held-out gain ≤ the single ORDER term's, the simple term suffices and complexity is unwarranted.
- **Device/resource estimate (unverified until solver):** small tabular fit on ≈2×10^4 discordant participants → CPU adequate; bounded GPU optional for the sequence model. Solver envelope per inputs: 16 CPU / up to 8 GPU / 28800 s. The documentation-breadth discriminator adds no GPU need.
- **Selection reason:** the two alternatives test a real uncertainty (is order information in the pair relation or in sequence position?), not a small metric gain. See `diag_breadth.py`/`diag_order.py`.

## Falsification criteria (pre-registered)
- **Supportive (A):** Δ_order > 0 with 95% CI excluding 0 on held-out data, AND persists in the ≥365-day subgroup and mid/low co-coding bins, AND **survives conditioning on documentation breadth (does not collapse)** and is larger for the disease-specific accrual outcome than for the generic records-volume negative control.
- **Adverse (B1):** Δ_order ≈ 0 in the long-interval subgroup, OR concentrated in the top co-coding bin, OR **collapses after adjustment for documentation breadth / predicts the generic records-volume outcome as strongly as the disease-specific outcome**, OR the E11/E78 control shows equal-or-larger "order" effect → set/count representation adequate; do not promote sequence.
- **Inconclusive:** point estimate > 0 but CI spans 0, or tie fraction/structure makes the estimator unstable → report inconclusive, not positive.

## Honest limits
All three key works are **abstract-only** (see key-references.json).
