# Scientific Proposal: Discordant Recovery Phenotype in Decompensated Cirrhosis

## Unresolved Question

**Clinical Problem:** In patients with decompensated cirrhosis undergoing liver transplantation evaluation, current risk stratification relies heavily on single-time-point MELD scores and static laboratory values. However, patients with the same baseline MELD score exhibit vastly different trajectories of clinical deterioration and transplant waiting list progression.

**Key Uncertainty:** Does the *rate of change* in organ function (particularly coagulation and synthetic function) over the first 30 days post-diagnosis predict which patients will require urgent transplant versus those who can wait longer? Existing models treat "abnormal labs" as a binary state rather than capturing the dynamic trajectory of recovery or deterioration.

## Clinical Importance

1. **Transplant Allocation:** More accurate risk stratification could optimize liver transplant allocation, reducing waitlist mortality while ensuring appropriate urgency.

2. **Prognostic Guidance:** Clinicians could better counsel patients about their likely course, improving shared decision-making about transplant timing.

3. **Resource Utilization:** Identifying patients at imminent risk of decompensation could trigger earlier interventions before catastrophic events occur.

4. **Beyond MELD:** MELD score has known limitations, particularly in patients with coagulopathy, hepatorenal syndrome, or severe encephalopathy where synthetic function is already severely impaired.

## Substantive Advance Over Existing Knowledge

Current research on cirrhosis prognosis typically:
- Uses single-time-point or averaged laboratory values
- Relies on established scores (MELD, Child-Pugh) without modification
- Treats laboratory abnormalities as static rather than dynamic

**This proposal advances by:**
1. Modeling the *trajectory* of synthetic function (INR, albumin, bilirubin) rather than just absolute values
2. Capturing discordance between different organ function parameters (e.g., improving bilirubin but deteriorating INR)
3. Integrating medication patterns (diuretics, lactulose, vasoactive drugs) as proxies for clinical management intensity
4. Accounting for hospital-level variation in care patterns

## Hypothesis

**Primary Hypothesis:** The rate of change in synthetic function parameters (INR, albumin, bilirubin) over the first 30 days post-diagnosis of cirrhosis, when modeled as a dynamic trajectory rather than static values, independently predicts time to decompensation and mortality above and beyond baseline MELD score.

**Secondary Hypothesis:** Patients exhibiting discordant trajectories (e.g., improving one parameter while deteriorating another) have different risk profiles than those with concordant trajectories, suggesting that multi-parameter trajectory analysis captures heterogeneity that single-parameter models miss.

## Population and Temporal Boundaries

- **Population:** Adults with diagnosis of cirrhosis in the HCC cohort
- **Temporal Window:** Index date (cirrhosis diagnosis) to 90 days follow-up
- **Inclusion:** Patients with ≥3 laboratory measurements within 30 days of index date
- **Exclusion:** Patients with missing key labs (INR, albumin, bilirubin), active malignancy (except HCC), or transplant already performed

## Methodology

### 1. Trajectory Extraction Algorithms

#### 1.1 Lab Value Normalization and Interpolation
- **Normalization:** Convert all lab values to clinically meaningful scales:
  - INR: Keep as is (already standardized)
  - Albumin: Convert to g/L if needed (current values appear to be g/L)
  - Total Bilirubin: Convert to μmol/L if needed (current values appear to be μmol/L)
  - Creatinine: Keep as mg/dL for MELD calculation
- **Interpolation:** For patients with lab measurements spaced irregularly, use linear interpolation to create daily trajectories:
  ```python
  def create_daily_trajectory(patient_labs, index_date, window_days=30):
      """Create daily lab values from sparse measurements using linear interpolation."""
      daily_values = {}
      for date in pd.date_range(index_date, index_date + pd.Timedelta(days=window_days), freq='D'):
          if date in patient_labs.index:
              daily_values[date] = patient_labs[date]
          else:
              # Linear interpolation between surrounding dates
              prev_date, prev_val = patient_labs.loc[patient_labs.index < date].tail(1)
              next_date, next_val = patient_labs.loc[patient_labs.index > date].head(1)
              if prev_date and next_date:
                  daily_values[date] = prev_val + (next_val - prev_val) * (date - prev_date) / (next_date - prev_date)
              else:
                  daily_values[date] = np.nan
      return daily_values
  ```

#### 1.2 Slope Estimation Methods

**Method A: Piecewise Linear Regression (Recommended)**
- Fit piecewise linear regression with breakpoints at day 14 and day 30
- Captures different recovery/deterioration phases
- Coefficients:
  - `slope_day0_14`: Rate of change from day 0-14
  - `slope_day14_30`: Rate of change from day 14-30
  - `discordance_score`: |slope_day0_14 - slope_day14_30| / mean(|slope_day0_14|, |slope_day14_30|)

**Method B: Simple Linear Regression**
- Single slope across entire 30-day window
- `overall_slope`: Average rate of change per day
- Simpler but less informative about trajectory changes

**Method C: Hidden Markov Model (HMM)**
- Models latent states (stable, deteriorating, improving)
- State transition probabilities capture dynamics
- Computationally intensive but captures complex patterns

#### 1.3 Discordance Metrics

**Metric 1: Parameter Discordance Index (PDI)**
```
PDI = 1 - corr(slope_INR, slope_albumin, slope_bilirubin)
```
- Measures how differently parameters change over time
- PDI = 0: All parameters change at same rate (concordant)
- PDI = 1: Parameters change independently (max discordance)

**Metric 2: Directional Discordance**
```
directional_discordance = sum(|slope_i - mean(slope)|) / n_params
```
- Captures if parameters move in opposite directions
- Positive values indicate discordant trajectories

**Metric 3: Variance-Based Discordance**
```
variance_discordance = std([slope_INR, slope_albumin, slope_bilirubin]) / mean(|[slope_INR, slope_albumin, slope_bilirubin]|)
```
- Normalized standard deviation of slopes
- Accounts for magnitude differences between parameters

### 3. MELD Score Calculation Formula and Data Requirements

**MELD Score Formula:**
```
MELD = 3.78 × ln(INR) + 11.2 × ln(bilirubin) + 9.57 × ln(creatinine) + 6.43
```

**Constraints:**
- INR: If INR < 1.0, use 1.0
- Bilirubin: If bilirubin < 1.0, use 1.0
- Creatinine: If creatinine < 1.0, use 1.0
- If any value is missing, MELD cannot be calculated
- Maximum MELD = 40 (capped)

**Data Requirements:**
- **INR:** `exam` = "国际标准化比值" (International Normalized Ratio)
- **Total Bilirubin:** `exam` = "总胆红素" (Total Bilirubin)
- **Creatinine:** `exam` = "肌酐" (Creatinine)

**Baseline MELD Calculation:**
```python
def calculate_meld(inr, bilirubin, creatinine):
    """Calculate MELD score with constraints."""
    # Apply constraints
    inr = max(1.0, inr)
    bilirubin = max(1.0, bilirubin)
    creatinine = max(1.0, creatinine)

    # Calculate MELD
    meld = 3.78 * np.log(inr) + 11.2 * np.log(bilirubin) + 9.57 * np.log(creatinine) + 6.43

    # Cap at 40
    return min(40.0, meld)
```

**Temporal MELD Calculation:**
- Calculate MELD at each time point where all three values are available
- Use most recent MELD before decompensation event or end of study
- Track MELD trajectory similarly to other parameters

### 4. Concordance vs Discordance Metrics for Multi-Parameter Trajectories

#### 4.1 Concordance Metrics

**Metric A: Slope Concordance Coefficient**
```
slope_concordance = 1 - (abs(slope_INR - slope_albumin) + abs(slope_INR - slope_bilirubin) + abs(slope_albumin - slope_bilirubin)) / 3
```
- Range: 0 (max discordance) to 1 (perfect concordance)
- Higher values indicate more synchronized parameter changes

**Metric B: Directional Concordance**
```
directional_concordance = 1 - (sum(sign(slope_i) != sign(mean_slope)) / n_params)
```
- Range: 0 (all opposite directions) to 1 (all same direction)
- Captures if parameters move in same or opposite directions

**Metric C: Variance of Slopes**
```
slope_variance = std([slope_INR, slope_albumin, slope_bilirubin]) / mean(|[slope_INR, slope_albumin, slope_bilirubin]|)
```
- Range: 0 (all slopes equal) to ∞ (infinite variance)
- Lower values indicate more concordant trajectories

#### 4.2 Discordance Metrics

**Metric A: Discordance Index (DI)**
```
DI = 1 - slope_concordance
```
- Range: 0 (perfect concordance) to 1 (max discordance)
- Primary discordance metric for analysis

**Metric B: Parameter-Specific Discordance**
- Calculate discordance between each pair of parameters
- INR-albumin discordance, INR-bilirubin discordance, albumin-bilirubin discordance
- Can identify which parameters are driving discordance

**Metric C: Trajectory Phase Discordance**
- Compare concordance in different time windows
- Early discordance (days 0-14) vs late discordance (days 14-30)
- May reveal temporal patterns in discordance

### 5. Baseline Cox Model Specification

**Model 1: Standard Cox Proportional Hazards (Baseline)**
```
h(t|X) = h0(t) × exp(β0×MELD + β1×Age + β2×Sex + β3×Comorbidity_Count)
```

**Variables:**
- **Outcome:** Time to first decompensation event or death (censored at 90 days if no event)
- **Predictors:**
  - `MELD`: Baseline MELD score (at index date)
  - `Age`: Patient age at index date
  - `Sex`: Male (1) / Female (0)
  - `Comorbidity_Count`: Number of comorbidities from diagnoses table
- **Covariates:**
  - `Hospital_ID`: To account for hospital-level variation
  - `Index_Date`: Calendar date (for time-varying covariates if needed)

**Model 2: Extended Cox with Trajectory Features**
```
h(t|X) = h0(t) × exp(β0 + β1×MELD + β2×Slope_INR + β3×Slope_albumin + β4×Slope_bilirubin + β5×DI + β6×Age + β7×Sex + β8×Comorbidity_Count)
```

**Variables:**
- All baseline predictors plus trajectory features
- `Slope_INR`: Rate of change in INR over 30 days
- `Slope_albumin`: Rate of change in albumin over 30 days
- `Slope_bilirubin`: Rate of change in bilirubin over 30 days
- `DI`: Discordance Index
- `MELD`: Baseline MELD score

**Model 3: Time-Varying Cox Model**
```
h(t|X(t)) = h0(t) × exp(β0×MELD(t) + β1×Slope_INR(t) + β2×Slope_albumin(t) + β3×Slope_bilirubin(t) + β4×DI(t) + β5×Age(t) + β6×Sex(t))
```

**Features:**
- All predictors can vary over time
- MELD(t): MELD score at time t
- Slope(t): Slope estimates at time t (using rolling windows)
- DI(t): Discordance index at time t

### 6. Trajectory Model Specifications

#### 6.1 Piecewise Linear Regression Model

**Specification:**
```
Y(t) = β0 + β1×t + β2×I(t≥14)×(t-14) + β3×I(t≥30)×(t-30) + ε
```

**Where:**
- `Y(t)`: Lab value (INR, albumin, or bilirubin) at time t
- `t`: Time in days from index date
- `I(t≥k)`: Indicator function (1 if t≥k, 0 otherwise)
- `β1`: Slope from day 0-14
- `β2`: Additional slope from day 14-30
- `β3`: Additional slope from day 30 onwards

**Derived Features:**
- `slope_0_14 = β1`
- `slope_14_30 = β1 + β2`
- `discordance = |slope_0_14 - slope_14_30| / mean(|slope_0_14|, |slope_14_30|)`

#### 6.2 Simple Sequence Model (LSTM)

**Architecture:**
```
Input: Sequence of lab values [Y0, Y1, Y2, ..., Y30]
Hidden: LSTM layers with 64 units
Output: Probability of decompensation in next 30 days
```

**Implementation:**
```python
from tensorflow.keras import layers, models

def build_lstm_model(input_shape=(31,), num_classes=2):
    """Build LSTM model for trajectory prediction."""
    model = models.Sequential([
        layers.Input(shape=input_shape),
        layers.LSTM(64, return_sequences=True),
        layers.Dropout(0.2),
        layers.LSTM(32),
        layers.Dropout(0.2),
        layers.Dense(16, activation='relu'),
        layers.Dense(num_classes, activation='sigmoid')
    ])
    model.compile(optimizer='adam', loss='binary_crossentropy', metrics=['accuracy'])
    return model
```

## Falsification Criteria

The hypothesis would be **falsified** if:

1. Rate of change in labs does not add predictive value beyond baseline MELD (ΔC-index < 0.02)
2. Discordant trajectories show no independent association with outcome after adjustment
3. The trajectory model performs worse than or equal to the baseline model on validation set
4. Hospital-level variation accounts for all apparent trajectory-outcome relationships (suggesting confounding by care intensity)

## Supportive Results

Supportive evidence would show:

1. Trajectory slopes significantly improve prediction beyond baseline MELD (ΔC-index ≥ 0.05)
2. Discordant trajectories have distinct risk profiles
3. Rapid deterioration in any parameter predicts worse outcomes
4. The model generalizes to validation cohort with similar performance
5. Discordance index is independently associated with outcomes after adjusting for individual slopes

## Adverse/Inconclusive Results

**Adverse:**
- Trajectory features introduce bias (e.g., patients with frequent labs have different outcomes)
- Discordance metric captures care-seeking behavior rather than true pathophysiology
- No clear clinical actionability identified
- Sample size insufficient for precise trajectory estimation

**Inconclusive:**
- Trajectory patterns differ by hospital but no unified model emerges
- Discordance captures both biological and behavioral factors
- Need for external validation in different populations
