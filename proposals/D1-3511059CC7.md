# Target-linked longitudinal and structured-event falsification of departure status

## Decision question and targeted advance

The frozen decision is unchanged from parent `[prior hypothesis]`: whether any exact MIMIC pulmonary-opportunity atom can be nominated only for a prospective within-site **silent** validation of the inherited `AUTO`, `RECON`, `TIMING`, and `DEFER` routes. This is not a test of guideline correctness, clinician performance, clinical safety, follow-up completion, benefit, or a causal intervention effect.

The parent repairs reference validity with two roster-disjoint, assertion-centered and trajectory-centered departure-status readings, compatible states, presealed text-copy/target-grounding facts, and textual completion/replacement/tentative anchors. A remaining validity concern is that both reference readings still primarily inspect narrative artifacts. Two readers may correctly characterize text while the text-defined status is contradicted or corroborated by an independently constructed target-linked longitudinal event trajectory. The substantive repair here is a **post-seal, outcome-blind structured-event challenge**: use radiology-linked structured procedure/HCPCS events and target-linked radiology trajectories to look for positive evidence of a matching action already documented before departure, or for a later target-linked action that clarifies persistence. This layer is deliberately one-sided where observation is incomplete.

The falsifiable hypothesis is narrow: among inherited support-qualified candidate `AUTO` or `RECON` units, the parent’s favorable departure-status ledger remains compatible with an independently constructed event trajectory, and no atom has an adverse-compatible excess of positive pre-departure target-linked completion evidence or explicit target-linked event contradiction. A pre-departure target-linked structured event that is temporally and semantically matched to the recommendation can falsify a `FIRM_ACTIVE`/`FIRM_INCOMPLETE` label when the discharge text contains no remaining future action. A post-departure target-linked event may corroborate that an action occurred later, but cannot by itself falsify an active departure plan. **No absence of an event, no absence of a later admission, no missing code, no death, and no lack of same-system follow-up is evidence of noncompletion, inactivity, clinical failure, or harm.**

The strongest available claim remains textual and observational: a supplied MIMIC artifact may contain a target-grounded, firm future action without an observed target-linked completion or replacement in the permitted artifacts. This child tests whether positive, independently linked structured/longitudinal events contradict that claim; it does not convert event absence into a negative result or establish that an action was live, assigned, visible, ordered, scheduled, executed, appropriate, safe, or beneficial.

## Source-derived feasibility check and actual filters

The parent’s frozen bounded profile is retained, not relabeled: it read the first 100,000 physical discharge rows and first 300,000 physical radiology rows in gzip order, with no population or clinical-label filter, and found target/follow-up, tentative, completion, replacement, recurrence, and cross-source overlap patterns. The stored profile is `[internal dataset path]`; its method is explicitly nonrandom feasibility only.

Before labels and before route revelation, construct an event-code feasibility profile over the full dictionary files and all event rows. Record physical row counts, nonmissing descriptor counts, dictionary-match counts, modality/anatomy token counts, date-boundary counts, and target-linked report/event pair counts. This is a computability check, not prevalence. The deterministic code filter is frozen before any reference labels:

* Normalize dictionary descriptions by Unicode normalization, case folding, whitespace collapse, and punctuation spacing only. Preserve modality, anatomy, laterality, measurements, negation, and dates in report text.
* Map each recommendation unit to a source-chain target signature (anatomy/laterality, measurement when present, modality, comparison, and interval) already used by the parent. Do not infer a target from a generic event alone.
* A structured event is `MODALITY_MATCH` only if its dictionary descriptor contains a modality token compatible with the unit’s source-chain modality and, when an anatomy token is present, a compatible chest/lung/pulmonary target. If the descriptor is generic but a same-date radiology report independently contains an exact/compatible target and matching modality, the pair may be `REPORT_LINKED_EVENT`; if neither condition holds it is `EVENT_GENERIC`.
* Use fixed modality groups: CT/computed tomography; MRI/magnetic resonance; PET/positron emission tomography; radiograph/x-ray; ultrasound/sonography; and other/unknown. A modality not represented in a dictionary descriptor is `UNKNOWN`, never coerced to a match.
* A report-event pair is target-linked only when the report is linked to the subject and (where applicable) the same admission, its target identity is `EXACT` or `COMPATIBLE` to the source unit under the parent’s target matcher, its report text documents the matching study/action rather than merely repeating a recommendation, and the structured event’s date is within the frozen temporal rule below. Textual mention alone without a structured event is not independent event corroboration.
* Generic events, unmatched dictionary codes, missing dates, conflicting target links, and ambiguous modality are retained as `UNKNOWN_EVENT`/`EVENT_GENERIC`; they are not counted as noncompletion.

## Longitudinal event trajectory and time windows

For each of the parent’s 300 challenge admissions and every recommendation unit, build the trajectory using all subject-linked event rows and radiology rows, while retaining the admission as the only review unit. Define `D=dischtime` and the source report’s `R_store,u` as inherited. Use the following predeclared windows:

* `PRE_D`: a structured event with `chartdate` on or before the calendar date of `D`, paired to a target-linked radiology report with `charttime<D` and `storetime<D`; if the event date equals `D` but the report time is missing or cannot be ordered relative to `D`, classify as `BOUNDARY_UNKNOWN`, not completion.
* `POST_D_365`: a target-linked report/event pair with report `charttime>D` and `storetime>D`, event `chartdate` after the calendar date of `D` and no later than 365 deidentified calendar days after `D`. This is a positive later-documentation state only. Follow-up outside this window, events without dates, and later records not target-linked are `UNOBSERVED/UNKNOWN`, never negative.
* `INDEX_ADMISSION`: event and report share `(subject_id,hadm_id)` with the opportunity admission. `LATER_ADMISSION`: the same subject has a different admission key, and the report/event pair is target-linked by its own explicit report content. A later admission key alone is never evidence of target completion.
* If date-only `chartdate` and timestamped `D` cannot establish ordering, use the adverse-compatible boundary state. Do not use raw shifted years to define external calendar eras.

For a `PRE_D` pair, classify `PRE_D_STRUCTURED_COMPLETION` only if the target-linked report documents the matching performed study/action and the DS contains no explicit remaining future action for that target. If the DS explicitly retains a next future action, classify `PRE_D_COMPLETED_WITH_REMAINING_ACTION`; this does not falsify `FIRM_ACTIVE` for the next action. If the report documents a different modality or target, classify `EVENT_TARGET_CONFLICT`, not completion of the original unit. For `POST_D_365`, classify `LATER_TARGET_LINKED_ACTION` and leave departure status unchanged unless an explicit pre-D artifact also resolves it. A later positive event cannot be used to claim that an initially active plan was non-live or that absent follow-up was failure.

The trajectory state is an ordered, auditable tuple, not a consensus label:

`E_PRE_NONE_OBSERVED`, `E_PRE_TARGET_LINKED_COMPLETION`, `E_PRE_COMPLETION_NEXT_STEP_REMAINS`, `E_PRE_TARGET_CONFLICT`, `E_POST_TARGET_LINKED_ACTION`, `E_GENERIC_ONLY`, `E_BOUNDARY_UNKNOWN`, `E_DATA_MISSING`.

`E_PRE_NONE_OBSERVED`, `E_GENERIC_ONLY`, and `E_DATA_MISSING` all mean only that no qualifying positive event was observed in the supplied fields. They never lower the parent’s `R_UNKNOWN`/adverse state and never support `R_FIRM_ACTIVE`.

## Independent seal and falsification workflow

1. Freeze source hashes, code dictionaries, token groups, date windows, target matcher, event-pair rules, codebook, and packet order before reading either parent panel’s labels or revealing atoms/routes.
2. Build the event trajectory mechanically from source rows. Store event IDs, admission keys, dictionary versions, dates, report IDs, target-match class, modality class, and reason codes; do not export clinical source text.
3. Seal the event trajectory independently of R1/R2. The event operator receives only source rows needed for code/date matching and cannot see panel labels, routes, weights, or expected outcomes. R1/R2 do not see event-derived states during their initial readings.
4. After both panel labels are sealed, join the event trajectory to the parent’s compatible departure-status set. The join is a computational comparison, not an adjudicator vote. Any explicit target-linked `E_PRE_TARGET_LINKED_COMPLETION` or `E_PRE_TARGET_CONFLICT` is an adverse-compatible challenge to a favorable parent state; `E_POST_TARGET_LINKED_ACTION` is reported as longitudinal corroboration/trajectory information only.
5. Re-run the comparison with labels, routes, and event rows permuted according to locked negative controls. No event-derived result can rescue a failed text-control or make an unobserved event favorable.

Primary unit-level discordance is `REF_EVENT_CONFLICT`: the parent-compatible set includes only `R_FIRM_ACTIVE` or `R_FIRM_INCOMPLETE`, while a qualifying `E_PRE_TARGET_LINKED_COMPLETION` has no explicit remaining next action, or a qualifying `E_PRE_TARGET_CONFLICT` explicitly identifies a different target/action. `REF_EVENT_CONCORDANT` includes a pre-D event with a remaining future action and post-D positive actions that do not contradict departure status. All other cases remain compatible/unknown.

## Falsification controls

Controls are computational and outcome-blind, and cannot rescue real-case failures:

* **Target-swap control:** swap target identity between a report and structured event while preserving date and modality. The pair must become `EVENT_TARGET_CONFLICT` or `UNKNOWN`, never a completion.
* **Modality-swap control:** replace the event descriptor with a different modality while preserving target text. The pair must lose `MODALITY_MATCH`.
* **Date-shift control:** shift a pre-D event to post-D and vice versa in synthetic fixtures. The state must change only according to the frozen temporal rule, with boundary cases becoming `BOUNDARY_UNKNOWN`.
* **Admission-swap control:** pair a target-linked report/event from another admission of the same subject. It must not be an index-admission completion; it can qualify as `LATER_ADMISSION` only if the later report independently identifies the target.
* **Generic-code control:** pair a generic chest/imaging code with a target-irrelevant report. It must remain `EVENT_GENERIC`/`UNKNOWN`.
* **Addendum/provenance control:** duplicate or reorder reciprocal radiology detail rows and addenda without changing target/action content. The event state must not change; note identity remains `(subject_id,note_id)`.
* **Absence control:** delete a positive event from a fixture. The result may move to `E_PRE_NONE_OBSERVED` but must never be labeled noncompletion or clinical failure.
* **Post-D persistence control:** add a target-linked post-D event to a `FIRM_ACTIVE` fixture. It must be reported as `E_POST_TARGET_LINKED_ACTION` and must not be treated as a departure contradiction.

A broken target matcher, date ordering, admission key, absence rule, source seal, or POE prohibition invalidates the affected run and defaults the affected atom to `DEFER`.

## Supportive, adverse, and inconclusive outcomes

**Supportive.** All inherited and new gates pass; at least one exact atom has every candidate unit adverse-compatible with an active/incomplete status; there is no qualifying pre-D target-linked structured completion without a remaining next action and no target conflict; controls pass; and finite-population upper conflict bounds are below the prespecified route-specific margins. The result supports only that the parent’s text-defined departure status is not contradicted by positive target-linked structured/trajectory evidence in the available MIMIC artifacts. It supports nomination for a prospective within-site silent workflow study, not a live action.

**Adverse.** A supported atom has a pre-D target-linked structured completion without remaining action, target/action conflict, or a simultaneous upper conflict bound crossing its gate; a target/admission/modality/date control fails; or an event seal/join violation reveals circularity. The atom is excluded from nomination. This does not prove that the plan was clinically wrong, that care failed, or that a patient lacked follow-up. A later positive event alone is not adverse.

**Inconclusive.** Exact target linkage is sparse, structured dictionaries are too generic, date-only events cannot be ordered relative to `D`, source rows or addenda are missing, event positive classes are not calibratable, the 300-admission challenge or <=600 reference readings cannot be completed, effective sample size is inadequate, or adverse-compatible bounds remain wide. Inconclusive is not a pass and defaults to `DEFER`. Absence of a structured event, absence of a later admission, or absence of same-system follow-up is explicitly inconclusive rather than adverse.

## Computable versus clinical-adjudication claims

Computationally checkable claims include source/schema/hash reproduction; exact `(subject_id,hadm_id)` joins; canonical DS and reciprocal radiology linkage; date ordering; code-dictionary mapping; target/modality/admission matching; event-state construction; pre/post-D classification; positive-only absence handling; roster and seal separation; workload and distinct-admission counts; inherited sampling probabilities; finite-population bounds; simultaneous uncertainty; and the locked-control outcomes.

Human or prospective evidence is required for whether the target was clinically the same lesion, whether the structured event represents an actually completed study rather than billing/coding artifact, whether an action was still medically indicated, whether anyone viewed or owned the recommendation, whether it was communicated, ordered, scheduled, executed outside MIMIC, safe, useful, or beneficial. Even a perfect event trajectory cannot establish a clinically live departure obligation. MIMIC lacks reliable viewing/edit/finalization semantics, responsibility assignment, conversations, patient preference, outside records, target-linked referral/order completion, scheduling, clinical appropriateness, malignancy, harm, and forward/external transport. The next study remains an expert-governed prospective actual-calendar silent bridge that captures workflow exposure, responsibility, communication, orders, scheduling, execution, and outcomes.
