## Unresolved question and clinical importance
Multimorbidity risk tools and staging constructs (comorbidity counts, CKM stage, multimorbidity indices) represent disease burden as a **set or count**. Clinicians instead reason about **sequence** — diabetes-then-hypertension vs hypertension-then-diabetes. [K1] shows, in a UK South Asian cohort, that the *direction* of a cardiometabolic/internalising multimorbidity trajectory predicts 10-year cardiovascular/renal events — so order is not obviously inert. But [K1] does not test whether pairwise order beats a co-presence/count baseline and does not adjudicate the obvious artifact: inpatient ICD-10 codes are co-recorded when a patient is jointly investigated, so apparent "order" could reflect *which condition was coded first in a shared encounter* rather than a biological sequence [K3 bounds the nonspecific/shared-burden alternative; K2 shows hub/co-occurrence structure as a rival]. Resolving this decides whether sequence belongs in multimorbidity stratification or whether the set/count view is adequate — a useful negative either way.

## Leading claim vs strongest rivals; discriminating observation
- **Leading claim (A):** among people with a fixed co-present pair, first-diagnosis ORDER adds out-of-sample information about downstream ICD-10 accrual (Δ_order ≠ 0) beyond co-presence/count, age, interval and co-coding.
- **Rival B1 (strongest; ascertainment/care-coupling):** "order" reflects joint coding/co-testing intensity, not biology [K3 caution; parent discussion].
- **Rival B2 (shared continuum):** order is a projection of one graded burden process; the useful signal is stage/count, not pairwise order [K3].
- **Rival B3 (network/hub):** apparent pairwise structure is hub centrality, not ordering [K2].

**Discriminating observations (this child):**
1. **Long-interval subgroup (new, pre-registered):** restrict to pairs whose two first-occurrence dates are **≥365 days apart**, where same-encounter co-coding is weakest. B1 predicts Δ_order → ≈0 here; A predicts Δ_order persists.
2. **Co-coding intensity gradient (new, pre-registered):** bin pairs by same-encounter co-coding intensity (number of distinct ICD-10 blocks sharing the earlier date). B1 predicts Δ_order concentrated in the highest co-coding bin; A predicts persistence across bins.
3. Retained from parent: **screening-coupling control pair** E11/E78 (mechanically co-tested lipid disorder) vs biological pair E11/I10, plus a same-day tie-exclusion category and a within-stratum permutation null.

## Population, temporal boundaries, variables, outcome
- **Population:** adults in the frozen clinical table (`n_eid` namespace). Target group = participants with BOTH `E11` (type 2 diabetes) and `I10` (essential hypertension) present as ICD-10 3-character blocks in `s_41270_0_{0..258}`, with both parallel `s_41280_0_{0..258}` first-occurrence dates non-null and **discordant** (day-resolution); control group = both `E11` and `E78` present.
- **Temporal boundary:** this is a **prevalent/records-based** design. The `n_eid` clinical table has NO attendance/draw date (53-0.0), death date (40000) or cancer date (40005) among its non-array columns (only `n_eid`, `n_31_0_0`, `n_21003_0_0`, and 105010/105030 diet timestamps). Therefore no incidence, washout or reverse-causation window is defined; **no causal claim is made**.
- **Exposure:** binary ORDER = (E11 first-occurrence date < I10 date) among discordant pairs.
- **Covariates:** `n_31_0_0` (sex), `n_21003_0_0` (age/ethnic field id used as recorded), inter-diagnosis interval (days), pre-index coded count (distinct ICD-10 blocks dated on/before the earlier date), and same-encounter co-coding intensity (distinct blocks sharing the earlier date).
- **Outcome:** downstream ICD-10 accrual = number of distinct 3-character blocks with first-occurrence date strictly AFTER the later member's date (a records-accrual count). Secondary: a binary "≥1 new cardiometabolic block (I00–I99 or E00–E90) after index".
- **Primary estimand Δ_order:** out-of-sample improvement (ΔAUC and Δ on a proper scoring rule) of [set/count + age + sex + interval + co-coding] vs the same model **plus** the ORDER feature, evaluated by participant-level cross-validation (train/eval split fixed by seed). Secondary: within-stratum permutation null (strata = age-decile × sex × pre-index coded count).

## Baseline vs substantive alternative (method exploration, same question)
- **Baseline (simple, interpretable):** the set/count + covariates model above; ORDER entered as a single binary/parametric term. This is the clinically transparent comparison the set/count literature already uses.
- **Learned alternative (substantive, same question):** a **diagnosis-event sequence model** that consumes the ordered list of dated ICD-10 blocks before the later pair member (order-aware representation) and predicts downstream accrual. What it can reveal that the baseline loses: whether information sits in the *position of the pair within a longer within-person sequence* (e.g. diabetes early vs late in the coding history), not merely in which of the two came first. If the learned model's held-out gain is no better than the single ORDER term, the simple term is sufficient and complexity is not warranted.
- **Device/resource estimate (unverified until solver):** small tabular fit on ≈10^4 participants with a few thousand features → CPU is adequate; a bounded GPU run is optional for the sequence model. Solver envelope per inputs: 16 CPU / up to 8 GPU / 28800 s. No GPU quota is required for the baseline.
- **Selection reason:** the pair of alternatives tests a real uncertainty (is order information in the pair relation or in sequence position?), not a small metric gain.

## Falsification criteria (pre-registered)
- **Supportive (A):** Δ_order > 0 with 95% CI excluding 0 on held-out data, AND persists (interval ≥365-day subgroup and mid/low co-coding bins), AND the biological pair's Δ_order is not smaller than the E11/E78 coupling control.
- **Adverse (B1):** Δ_order ≈ 0 in the long-interval subgroup, or Δ_order is concentrated in the top co-coding bin, or the E11/E78 control shows an equal-or-larger "order" effect → set/count representation adequate; do not promote sequence.
- **Inconclusive:** Δ_order point estimate > 0 but CI spans 0, or tie fraction/structure makes the estimator unstable — report as inconclusive, not positive.
