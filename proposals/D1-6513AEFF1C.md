# Scientific Proposal: Hospital-Level Learning in Clinical Prediction Models

## Unresolved Question

Current critical care machine learning research predominantly focuses on model performance within a single hospital setting, with validation performed via internal holdout or cross-validation. However, a fundamental question remains unresolved: **Do prediction models learn patient-specific physiology or hospital-specific testing practices?**

This question is critical because:
1. Models trained on one hospital's testing frequency and missingness patterns may fail catastrophically when deployed elsewhere
2. The "black box" nature of ML deployment prevents understanding whether poor transportability stems from practice differences or patient heterogeneity
3. Current benchmarking practices (internal validation) may systematically overestimate generalizability by conflating patient signal with hospital artifacts

## Clinical Importance

This question has direct clinical importance because:

1. **Model deployment risk**: Hospitals deploying models trained elsewhere face unpredictable performance degradation
2. **Resource waste**: Failed models lead to unnecessary interventions or missed diagnoses
3. **Quality improvement**: Understanding hospital-level learning patterns can guide standardization efforts
4. **Fairness implications**: Models may inadvertently learn hospital biases rather than patient physiology

## Substantive Advance Over Existing Knowledge

This proposal extends beyond existing work by:

- **Moving from single-hospital to multi-hospital analysis**: Most prior work uses single-center data; this explicitly tests cross-hospital transportability
- **Operationalizing "testing practices"**: Rather than vague "testing frequency," we measure concrete metrics: lab test intervals, missingness patterns, and test selection
- **Comparing model architectures**: We test whether adding hospital-level features improves (or harms) transportability
- **Using whole-hospital holdout**: This provides a realistic test of generalization that internal validation cannot

## Hypothesis

**Hypothesis**: Models that incorporate information about hospital-specific testing practices (test frequency, missingness patterns, test selection) will show significantly worse transportability to unseen hospitals compared to models trained only on patient-level features.

**Alternative Hypothesis**: Models with hospital-level features will show improved transportability because they can account for systematic differences in testing intensity and patterns across hospitals.

## Study Population

- **Dataset**: eICU-CRD v4.0 (100,000+ ICU admissions from 50+ hospitals)
- **Inclusion**: Patients with complete laboratory data (lab table), patient demographics (patient table), and hospital information (hospital table)
- **Exclusion**: Patients with less than 30 days of ICU stay (insufficient for learning testing patterns)
- **Temporal boundaries**: January 2018 - December 2021 (5 years, sufficient for learning stable testing practices)

## Main Variables

### Predictors (Model Features)
1. **Patient-level features** (baseline):
   - Demographics: age, sex, race, comorbidities
   - Admission vitals: MAP, SpO2, respiratory rate
   - Lab values: creatinine, lactate, glucose, WBC
   - Diagnosis: admission diagnosis codes

2. **Testing practice features** (hospital-level):
   - Test frequency: mean interval between consecutive lab tests (by test type)
   - Missingness pattern: proportion of missing values for each test type
   - Test selection: which tests are most frequently ordered
   - Hospital fixed effects: hospital-specific testing intensity

3. **Model features** (for comparison):
   - Same as above + hospital ID as feature

### Outcome
- **Primary**: 28-day mortality (from hospital table)
- **Secondary**: ICU length of stay, ventilator-free days, re-intubation

## Baseline Comparison

We will compare three modeling approaches:

1. **Patient-only model**: Uses only patient-level features (demographics, vitals, labs, diagnoses)
2. **Testing-aware model**: Uses patient features + hospital testing practice features
3. **Hospital-aware model**: Uses patient features + hospital ID as feature

**Key comparison**: Does adding testing practice information improve or worsen transportability?

## Analysis Plan

### Step 1: Data Preparation
- Extract testing patterns from lab table (test timestamps, test types)
- Calculate hospital-level metrics: mean test intervals, missingness rates
- Split data by hospital: 80% training, 20% validation (whole hospital holdout)

### Step 2: Model Training
- Train all three models on training hospitals
- Evaluate on held-out validation hospitals

### Step 3: Transportability Analysis
- Compare model performance across hospitals
- Calculate AUROC, calibration, and net benefit
- Test statistical significance of differences

### Step 4: Mechanism Exploration
- Analyze which testing practices correlate with performance differences
- Test whether patient-level performance correlates with hospital-level testing patterns

## Falsification Criteria

The hypothesis will be **falsified** if:
1. Models with hospital-level features show **better** transportability (p < 0.05)
2. The difference between patient-only and testing-aware models is non-significant
3. Hospital-level features improve calibration without worsening discrimination

The hypothesis will be **supported** if:
1. Models with hospital-level features show **significantly worse** transportability (p < 0.001)
2. Testing-aware models have lower AUROC on unseen hospitals
3. The effect persists after adjusting for patient mix

## Method Comparison: What Testing Practices Reveal That Baselines Cannot

**Baseline approach** (single-hospital validation):
- Measures model performance within familiar context
- Cannot distinguish patient signal from hospital artifacts
- Overestimates generalizability

**Testing practices approach** (multi-hospital holdout):
- Reveals whether models learn stable physiology or unstable practices
- Identifies which testing patterns cause performance degradation
- Provides actionable insights for model deployment

**Information revealed**:
- Whether testing frequency correlates with performance differences
- Which hospital-level features improve vs. harm transportability
- The extent to which hospital effects can be modeled vs. must be learned

## Missing Evidence and Limitations

1. **Test type mapping**: The lab table uses numeric test_id; we need to map these to test names (e.g., "CBC", "CMP", "Lactate")
2. **Testing intensity definition**: Need to define what constitutes "high" vs. "low" testing intensity
3. **Confounding by patient mix**: Hospitals differ in case mix; must adjust for this
4. **Temporal changes**: Testing practices may change over time; need to ensure stable patterns
5. **Unmeasured hospital effects**: Staffing, quality metrics not captured in dataset

## Clinical Decision Impact

If the hypothesis is supported:
1. **Model deployment**: Hospitals must validate models locally before deployment
2. **Feature engineering**: Testing practice features may need to be excluded from models
3. **Standardization**: Hospitals with similar testing practices may share models
4. **Quality improvement**: Understanding testing patterns can improve care consistency

If the hypothesis is falsified:
1. **Model deployment**: Hospital-level features may improve generalizability
2. **Feature engineering**: Testing practice features could be added to models
3. **Standardization**: Cross-hospital model sharing becomes more feasible
