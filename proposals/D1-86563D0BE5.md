# Episode 12 evolution — independent respiratory-care corroboration

Status: proposed substantive child of `[prior hypothesis]`. This is a design only: no cohort count, fitted coefficient, prediction, metric, or study result is claimed.

## Scientific opening and falsifiable hypothesis

The preceding design makes a useful but limited claim possible: an early process increment and two independently constructed labels from the vital tables may predict a later *recorded-vital transition*. The unresolved same-stream problem is that both vital labels can share the same observation schedule, interface, unit, duplicate, and threshold artifacts. A respiratory-care record supplies a different operational stream and different timing fields. It can therefore test convergence, although it is not a physiologic gold standard.

The strongest inspected evidence supports the use of temporally ordered EHR information, transport-aware validation, and explicit missingness/measurement audits for prediction; it does not establish that any eICU row is a bedside measurement, that a vital threshold is clinical deterioration, or that a respiratory-care transition is a treatment or severity state. The parent is a proposed design and has no observed result to inherit.

**Hypothesis.** In the adult first-ICU S6 risk set, the parent process vector (P), after the fixed measured state (T), will have a directionally coherent, hospital-held-out increment for (i) the parent’s paired recorded-vital labels `D_thr_recorded` and `D_traj_recorded`, and (ii) a source-defined respiratory-care transition `R_transition`, with observed vital/respiratory event-time proximity greater than a prespecified schedule-preserving null. This convergence should be present in both a simple additive model and a capacity-matched learned model, and should not disappear in source-observation, state, discharge-time, or hospital-stratum falsification checks.

A positive result supports only a reproducible cross-stream operational association: early recorded state/process information is associated with later recorded vital and respiratory-care transitions. It does not establish deterioration, treatment effect, monitoring causality, airway physiology, or a clinical alert threshold. A vital-only result, a respiratory-only result, or a signal explained by observation timing supports a narrower recording/workflow interpretation. The primary analysis is corroboration and heterogeneity, never a treatment-effect analysis.

This could change the next clinical decision: if cross-stream convergence is robust, fund source-level clinical adjudication of transition episodes and prospective timestamp capture; if it is absent or schedule-sensitive, do not treat the vital endpoint as a validated deterioration proxy and instead prioritize interface/measurement-quality work.

## Respiratory-care endpoint and strata

All raw respiratory values are retained in a source audit. Do not infer support from a missing row, a vital value, or a generic label.

### Primary endpoint: R_transition

Construct a stay-level union endpoint from source-defined components, all strictly in (360,720] and before recorded ICU exit:

1. `R_vent_start`: the earliest finite `ventstartoffset` with `ventstartoffset < ventendoffset` when both are present, or an open interval when `ventendoffset` is missing; require the start offset to be within follow-up. Exact duplicate rows are collapsed by `patientunitstayid,currenthistoryseqnum,ventstartoffset,ventendoffset,airwaytype`. If conflicting rows share the same `ventstartoffset` and sequence, retain the event but flag ambiguity; do not silently resolve it.
2. `R_vent_end`: the earliest finite `ventendoffset` after its finite start, within follow-up, and before ICU exit. A `ventendoffset` without a valid paired start is recorded as an unpaired boundary and is not part of the primary endpoint; report it separately.
3. `R_airway_change`: only if the raw `airwaytype` audit shows a stable, nonempty source vocabulary and no same-offset conflicting values. Sort valid rows by `respcarestatusoffset`, then numeric `currenthistoryseqnum`, then `respcareid`. A change is the first strictly later status offset at which the raw normalized `airwaytype` differs from the preceding valid airwaytype; do not map values to clinical support levels without a source dictionary. Same-offset conflicts are observation ambiguity and cannot create a transition.

`R_transition` is the earliest valid component time; save component, boundary time, `respcarestatusoffset`, current-history sequence, raw airwaytype, and all ambiguity flags. A status row is not itself a transition. The event time is the source-defined boundary for vent events and status offset for an auditable airway change. Report boundary/status lag; a positive lag is not proof of backfill or causal timing.

Primary support requires at least five viable hospitals, source-field stability, no unresolved duplicate conflict that changes endpoint assignment, and adequate counts in every required baseline stratum. If the airway vocabulary fails this audit, `R_transition` remains the vent-boundary union and `R_airway_change` is deferred; this is not a failed study.

### Baseline respiratory strata

Define strata only from [0,360], never from post-landmark events:

- `documented_support_0`: a valid vent interval from `ventstartoffset` to `ventendoffset` (or open end) overlaps [0,360]. This is an operational recorded-support stratum.
- `documented_no_active_vent_0`: at least one valid `respiratoryCare` row with `respcarestatusoffset` in [0,360], no valid vent interval overlaps [0,360], and the audited `airwaytype` vocabulary supplies an explicit non-support/none category. If that vocabulary is not auditable, this stratum is withheld rather than calling absence of a vent interval “no support.”
- `no_respiratory_record_0`: no valid respiratoryCare row in [0,360]. This is an undocumented/non-respiratory-care-recorded stratum, not evidence that the patient had no respiratory support.

Rows not classifiable due to invalid offsets, conflicting same-offset records, or unknown airway semantics are an explicit `R0_unknown` stratum and are not dropped. Report all three requested strata where valid, plus unknown.

### Respiratory charting gate

Do not use `respiratoryCharting` in the primary endpoint or predictors. It may enter a secondary, descriptive corroboration only if a training-fold-blind source audit establishes a reproducible mapping of `respcharttypecat/respchartvaluelabel/respchartvalue` to a time-stamped support state, with stable categories, no same-offset conflicts, and agreement with `respiratoryCare` on a prespecified sample. No mapping may be chosen by looking at mortality or model metrics. Given the catalog’s generic fields and lack of a declared unit/state dictionary, deferral is expected and must be reported honestly if the audit fails.

## Falsification and interpretation

Preserve the parent’s X-state, trajectory-state, within-hospital process-permutation, +180-minute displacement, laboratory/vital block, selection, EOL, and observation-weight nulls. Add:

- **respiratory availability:** model any valid respiratoryCare row, any vent interval, and any auditable airway-change opportunity as outcomes. If P predicts availability but not R_transition, the cross-stream signal is ascertainment.
- **recording-time null:** repeat using `respcarestatusoffset` as the event time for vent boundaries; a large change implicates backfill/recording timing.
- **component null:** require concordance separately for vent starts, vent ends, and airway changes; union-only support is insufficient if driven by one ambiguous component.
- **source independence audit:** verify no respiratoryCare-derived field enters X/T/P, and no post-360 row enters any predictor or weight model.
- **hospital and exit nulls:** repeat within held-out hospitals and exit-time bands, with P permutations that preserve respiratory and vital schedules.
- **same-offset/duplicate null:** exclude flagged conflicting rows and report whether endpoint assignment changes materially.
- **no-support falsification:** if the documented-no-active-vent stratum is valid, test whether apparent concordance is confined to baseline supported stays; if it is absent in no-support or undocumented strata, interpret this as effect heterogeneity/ascertainment, not refutation of the overall operational association.

Supportive results require: endpoint source audit passes; at least five hospitals and adequate events/coverage/positivity in required strata; both model classes show coherent held-out P increments for R and both vital labels; observed cross-stream timing exceeds the schedule-preserving null; and findings are not explained by availability, duplicate/backfill, discharge-time, state, or one-hospital controls. This supports only cross-stream operational reproducibility.

Adverse results mean adequate R support but no coherent R increment, no timing excess, or collapse under source/availability/discharge/state nulls. If vital labels remain positive but R is null, the strongest remaining claim is same-stream recorded-vital association, not corroborated transition. If R is positive while both vital labels are null, the respiratory stream is informative but the parent’s vital endpoint is not corroborated.

Inconclusive/deferral means unresolved airway semantics, too few hospitals/events, sparse no-support or undocumented strata, conflicting duplicate offsets, poor observation-weight positivity/effective sample size, or intervals spanning both meaningful and negligible effects. An imprecise null is not refutation.

No result establishes that a patient deteriorated, that ventilation was clinically indicated, that a treatment caused a transition, or that an alert would improve care. Clinical adjudication requires raw device/order/interface provenance, clinician-reviewed transition episodes, reliable clinical event time, and a prospective or external cohort. This dataset lacks those dependencies, as well as treatment assignment, staffing/workflow logs, and a gold-standard respiratory severity outcome.

## Matched simple and learned alternatives; selection and compute

The actual deliverable is newly fitted, leakage-safe R and D hazard predictions and cross-stream timing/null outputs, not a narrative-only design.

**Simple baseline.** Elastic-net pooled discrete-time cause-specific logistic hazards for each endpoint and competing exits, with X versus X+P and T versus T+P, identical intervals, hospital folds, weights, strata, seeds, and bootstrap. It estimates an interpretable additive process increment and exposes whether the convergence survives without flexible interactions.

**Substantive learned alternative.** Capacity-matched histogram gradient-boosting hazards with exactly the same inputs, targets, fold assignments, preprocessing, weights, null assignments, and uncertainty evaluation. It can reveal nonlinear state-by-process and baseline-respiratory-stratum interactions that the additive baseline averages away. A learner-only small discrimination gain, absent calibration/utility and null robustness, is not substantive convergence.

The primary selection is this matched tabular pair because the uncertainty is cross-stream endpoint coherence, not representation capacity. A raw respiratory/vital sequence model is deferred: current source rows lack reliable device/order/interface semantics and a sequence model could learn recording order rather than physiology. Revisit only after endpoint adjudication and a bounded diagnostic show that fixed 60-minute summaries lose clinically meaningful transition timing; then use the same target, folds, held-out hospitals, uncertainty, and nulls. A causal model is deferred because there is no intervention assignment, treatment start/stop provenance, valid clinical event time, or exchangeability basis. A hierarchical hospital model is descriptive-only and deferred as primary because hospital-held-out transport, not within-hospital shrinkage, is the estimand.

Future solver planning envelope is the inherited estimate: up to 16 CPUs, 262,144 MiB RAM, and 28,800 seconds for selected-column extraction, endpoint construction, two tabular learner families, nulls, strata, and 2,000 cluster-bootstrap replicates. It is unverified for the full study. CPU is selected provisionally for these tabular fits; no GPU is requested because this workload does not require neural sequence computation, and GPU use cannot repair missing respiratory semantics. A readiness job may measure extraction, endpoint audit, one fold of each model, and bootstrap throughput; no readiness result is a study result.
