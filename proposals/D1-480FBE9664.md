# Report-opportunity case-crossover documentation layer

## Scope, strongest supported claim, and unresolved claim

This child of `[prior hypothesis]` and `[prior hypothesis]` preserves the frozen first-eligible, one-admission-per-subject adult pulmonary-opportunity population; reciprocal pre-departure chronology; exactly-one canonical DS rule; recommendation unit and all-unit adverse precedence; sealed exact atom-route target `g=(E, terminal curr_service, W)`; route concealment; phase-1 master sample and outcome-blind bands; frozen target-cell selection; whole-admission phase-2 allocation, inclusion probabilities and HT/Hájek weights; shared-error frontier; 900/300/1,400-hour, 96-reviewer-hour, 6-hour/week and 32-week ceilings; and the conclusion ceiling of a separately approved prospective silent actual-workflow bridge. The layer remains downstream of the sealed phase-2 admissions and target. It cannot change eligibility, target choice, route, allocation, weights, parent endpoints, or an adverse parent decision.

The strongest evidence-supported claim is only that MIMIC-IV 3.1 contains timestamped stored radiology reports and their text for some subject-times after the frozen discharge anchor. It does not support continuous observation between records. A later admission, death entry, report, or store time proves only that the particular later record exists; it does not prove uninterrupted MIMIC capture, continued care in the system, or an opportunity to observe a report in an earlier interval.

The unresolved, falsifiable claim is narrower: **conditional on a radiology report genuinely appearing in both a due window and a within-subject placebo window, is explicit linkage to the sealed pulmonary target enriched in the due-window reports, beyond changes in competing nonpulmonary radiology documentation?** This tests a target-specific stored-text footprint at observed report opportunities. It does not test imaging completion, follow-up completion or noncompletion, delivery, viewing, acknowledgement, scheduling, appropriateness, safety, benefit, responsibility, continuity of care, or causality.

## Frozen anchors and deterministic windows

For selected admission `i`, retain the sealed recommendation interval `m_i in {3,6,12}` and the parent-identical clamped calendar function:

`calendar_add(D,m) = datetime(year(D)+(month(D)-1+m)//12, ((month(D)-1+m)%12)+1, min(day(D), days_in_result_month), D.hour, D.minute, D.second, D.microsecond)`.

Preserve source timezone metadata if present; otherwise use source-naive timestamps. Unit-test leap years, 29/30/31-day month ends, and equality boundaries against the inherited fixture before opening report text; mismatch returns `ANCHOR_NOT_RUN`.

Set `T_i=calendar_add(D_i,m_i)`. Define half-open windows using report `charttime`:

* pre placebo `Wpre=[T-60 days,T-30 days)`;
* due `Wdue=[T,T+30 days)`;
* post placebo `Wpost=[T+180 days,T+210 days)`.

`30`, `60`, `180`, and `210 days` are exact timedeltas. A report enters exactly one window only when its nonmissing `charttime` is within that half-open interval and its `subject_id` equals the index subject. A `charttime` before `D` is excluded from downstream outcomes. `storetime` is not an event-time substitute and is used only to report nonnegative/negative availability-lag anomalies. Equality at a left boundary is included; equality at a right boundary is excluded.

There is deliberately **no full-window observability rule and no subject last-observable time**. In particular, maxima over `dischtime`, `deathtime`, `dod`, `charttime`, or `storetime` are prohibited from converting an empty earlier window to an observed negative or from making a post window eligible. Snapshot-wide or subject-specific latest timestamps may be reported as source diagnostics only and are never analytic variables.

## Report identity, packets, and genuine opportunity states

Deduplicate only duplicate physical rows sharing `(subject_id,note_id)`. Select one deterministically by greatest required-field nonmissingness and then lexicographically smallest serialization; report the number discarded. Never deduplicate by text, `hadm_id`, `note_seq`, or timing. Include every `note_type`. Distinct addendum note IDs remain in the same admission-window packet and can modify linkage judgment, but the primary window endpoint is an admission-window fraction/indicator, so addenda cannot create extra admissions. Explicitly contradictory base/addendum text makes the affected report-family judgment `K_U`; no analyst tie-break is allowed. Null `charttime` cannot enter a window. Empty or unavailable text is retained as an unknown report, not dropped.

For every selected admission and each prescribed window, create exactly one state before examining target linkage:

1. `R_OBS`: at least one unique radiology row has eligible `charttime` and nonblank available `text`; this is a genuinely observed report opportunity.
2. `R_TEXT_UNKNOWN`: one or more timestamp-eligible rows exist, but all have empty/unavailable text; target linkage is unknown.
3. `NO_REPORT_UNKNOWN`: no timestamp-eligible radiology row is present. This is never `L=0`, never “no follow-up,” and never evidence of complete observation.
4. `DEATH_BEFORE_WINDOW`: an exact `admissions.deathtime` for a later admission or other exact available death timestamp precedes the left boundary. It is displayed separately and does not imply why no report exists. Date-only `patients.dod` cannot establish ordering within that day and produces `DEATH_DATE_AMBIGUOUS` when it intersects a boundary.
5. `DEATH_IN_WINDOW`: exact death lies in the window. Reports strictly before death remain genuine opportunities; absence after death is not evaluated. The window is not a complete 30-day negative opportunity.

A report found at a specific charttime is observable even if no later record exists. Conversely, no amount of later documentation upgrades `NO_REPORT_UNKNOWN`. Pre/due or due/post pair eligibility requires `R_OBS` on both sides and adequate adjudication on both sides; it never requires evidence that either entire interval was continuously observed.

## Blinded labels and competing documentation

Construct route- and window-concealed packets for every `R_OBS` window. Mask route, recommendation order, due interval, phase-1/phase-2 labels, parent endpoint, and whether the packet is pre/due/post. Two independent readers apply a frozen codebook before real packets.

For each report identity, label target linkage `L`:

* `L=1`: an explicit evidence span identifies the same pulmonary nodule/indeterminate focal opacity, or an explicit interval comparison/follow-up of that same target;
* `L=0`: text is sufficient to assess linkage and does not link to that target;
* `K_U`: text is insufficient, contradictory, target identity cannot be resolved, or readers disagree.

`L=0` is permissible only because a report is genuinely present and readable. It is never assigned to `NO_REPORT_UNKNOWN` or `R_TEXT_UNKNOWN`. Each `L=1` requires `note_id` and an exact evidence span retained in the governed audit output.

Independently of `L`, readers label the primary examination focus from report title/body/detail, while blinded to the target-link decision:

* `A=P`: primary examination is chest/pulmonary;
* `A=C`: primary examination is clearly nonchest/nonpulmonary, even if an incidental chest statement appears;
* `A=K_U`: focus cannot be resolved.

This separation allows nonpulmonary reports to be genuine competing documentation rather than defining them to have `L=0`. Reader disagreements remain `K_U`; duplicate blinded rereads and agreement are reported. The main analysis requires the whole window packet to have resolved `L` for all readable reports; a sensitivity analysis may use resolved reports while displaying the unresolved fraction, but cannot replace the main result.

## Estimands with common denominators

Let `n_iw` be the number of readable reports with resolved `L` in admission-window `w`, `x_iw` the number with `L=1`, and `f_iw=x_iw/n_iw`. Define `f^P_iw` and `f^C_iw` analogously among reports with resolved focus `P` and `C`; a class-specific fraction is undefined if its class denominator is zero. Let `a_iw=1` if any report has `L=1` and `0` only when the packet is `R_OBS` and every readable report has resolved `L=0`.

The primary estimand is the inherited design-weighted mean paired change among admissions with genuine report opportunities and fully resolved packets in both windows:

* `Delta_pre = mean_w(f_idue - f_ipre | R_OBS due and pre)`;
* `Delta_post = mean_w(f_idue - f_ipost | R_OBS due and post)`.

Use inherited admission path weight `w_i=1/(pi1_i q_i)`, normalize at the admission-pair level so an admission with many reports does not receive more sampling weight, and publish HT totals, Hájek ratios, the exact common pair denominator, report counts, and all excluded opportunity states. The pre contrast is the primary temporal test; the post contrast is co-primary only if at least 30 design-effective complete pairs were fixed as feasible before unmasking `L`, otherwise it is descriptive and explicitly inconclusive. No pair is formed by treating a no-report side as zero.

The admission-level paired sensitivity uses `a_idue-a_icontrol` on the identical complete-pair sets. A deterministic sentinel sensitivity selects, without reading text, the report whose `charttime` is closest to the window midpoint, then smallest `storetime` and `note_id`; this checks whether an “any report” result is driven by report multiplicity.

The prespecified competing-documentation specificity estimand uses only admissions/windows with both `P` and `C` report classes observed and resolved:

`DiD_pre = mean_w[(f^P_idue-f^P_ipre) - (f^C_idue-f^C_ipre)]`.

Its denominator is one common set of admission pairs; no P-versus-C comparison may use hidden different denominators. Also report due/pre total report counts and P/C composition as documentation-intensity diagnostics. A generalized radiology surge without target-specific linkage should raise report volume or both classes but not produce positive `DiD_pre`.

For all selected admissions, publish partial-identification bounds for the unconditional due-window target-linked-documentation proportion. The lower bound counts only adjudicated `L=1` windows. The upper bound additionally treats every `NO_REPORT_UNKNOWN`, `R_TEXT_UNKNOWN`, packet `K_U`, and death-truncated/ambiguous state as potentially positive. These intentionally broad bounds are never narrowed using a later/latest timestamp, a same-subject admission, or inverse modeling of report capture. Thus the unconditional claim may remain unidentified even when the conditional opportunity contrast is estimable.

## Falsification and interpretation

Supportive requires all inherited gates, allocation, role, control, agreement, and workload checks to pass; adequate report-opportunity pair counts; a simultaneous lower bound above zero for `Delta_pre`; concordant direction for an eligible `Delta_post`; and a simultaneous lower bound above zero for `DiD_pre`, without a sentinel sensitivity reversal. This supports only that, among observed MIMIC radiology-report opportunities, target-specific stored documentation is temporally concentrated near the prescribed due interval beyond competing radiology documentation. It can warrant only the already prescribed separately governed silent bridge.

Adverse means adequate paired observed-report opportunity exists but simultaneous bounds are compatible with no due enrichment, the direction is negative, competing-documentation specificity fails, wrong-target/addendum controls explain the signal, or the sentinel analysis reverses it. This weakens the documentary-anchor hypothesis and bridge priority for the exact target cell. It does not establish noncompletion, unsafe care, poor follow-up, or absence of imaging.

Inconclusive includes `ANCHOR_NOT_RUN`; sparse effective complete pairs; absent P/C common denominators; wide simultaneous intervals; many `NO_REPORT_UNKNOWN`, text/focus/linkage unknowns, or death-truncated states; disagreement; control failure; or unconditional partial-identification bounds spanning clinically incompatible values. Parent results remain unchanged. The remedy is actual workflow/capture logs or a dataset with explicit observation opportunities, not reclassification using later events.

The automatic verifier can check source paths/hashes, schemas, joins, identity deduplication, exact windows/boundaries, absence of a latest-timestamp rule, state counts, common pair denominators, weights, resampling, bounds, controls, workload arithmetic, and whether conclusions match supportive/adverse/inconclusive outputs. Human clinical adjudication is required for target identity, report focus, contradiction, and evidence spans. Actual care, imaging completion, delivery/viewing, responsibility, appropriateness, safety, benefit, and causal effects are unavailable and require a prospective actual-calendar study with immutable capture logs and later governed clinical evaluation.
